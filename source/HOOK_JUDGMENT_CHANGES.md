# Hook 修改游戏判断清单（更新至 1.0.22）

## 1.0.22 当前行为

飞机原生路径点的两个补丁只允许单机 Session 0 / 5。联机 Session 3 / 4 保留开关，自动使用现有的外部 Z 路径计划和普通移动事件；不安装飞机虚表或到达分支补丁。按住 Z 设置路径、松开后执行，状态显示“已启用（联机兼容）”。所有事件仍由 GameRuntime 的统一构造与 OutList 入口提交。补丁冲突不会被强行覆盖。

因此，下文 1.0.10 的“原生模式停用外部路径、失败不自动换回”只描述当时实现；1.0.22 的联机路径以本节为准。单机仍使用原生规划系统。界面分类已在 1.0.21 调整为普通设置，不代表联机验收通过。

本轮没有新增可修改地址。任意建造、C4 Beta 和地图绘制例外仍按各自设置及原有管理器校验执行。`nativeHook` / `clickHook` 等旧日志字段是接口就绪状态，实际代码补丁数量以新增的 `installedCodePatches` 为准。详见 [本轮审查和验证界限](REVIEW-1.0.22.md)。

## 历史清单：1.0.10，含 C4 Beta

任意建造、原生飞机路径点及文末 C4 Beta 均为**联机危险**，默认关闭，在战术助手底部独立勾选，修改后自动生效并保存。并未因为统一管理而变成联机安全；其他客户端可能执行不同判断，造成不同步、掉线或指令被拒绝。尚未完成 Windows 游戏实测和真实双机验证。

| 功能 | 修改位置 | 改变的行为 | 关闭与失败处理 |
|---|---|---|---|
| 任意建造 | `DisplayClass::PassesProximityCheck`，`0x4A8EB0`，5 字节入口跳转 | 对当前玩家的建筑放宽基地距离/邻接条件；保留原版 `CanPlaceHere` 的地形、地基占用检查。不改科技前提、造价、生产队列，不直接生成建筑。 | 仅恢复自身补丁；签名不匹配或位置被占用则拒绝安装。 |
| 飞机原生路径点 | `AircraftTypeClass::CanUseWaypoint` 虚表项 `0x7E2908`，4 字节；`AircraftClass::Mission_Move` 到点分支 `0x416AB6`，10 字节 | 放开原生规划资格；原版认定到达目标格后，在原生返航状态之前调用 `TechnoClass::TryNextPlanningTokenNode`（`0x6385C0`）。没有可继续节点时执行原版分支。 | 先安装到点行为、再启用前端；任一步失败回滚整组。关闭时先恢复前端。 |

飞机原生路径点**属于本清单**：原版飞机类型的资格函数直接返回 false，仅构造事件不足以接通原生界面和连续执行。此次没有修改所有单位共用的 false 函数，而是只替换飞机类型的虚表项。

## 使用与边界

- 原生模式使用游戏自身的路径点键（默认 Z）与原生规划界面，节点和后续事件归游戏规划系统管理。原生攻击、取消等操作沿用游戏行为。本次没有另外增加攻击任务拦截，也未验证所有 MOD 下攻击终止规划的表现。
- 原生模式选中后，旧外部 Z 队列停止捕获、清空待执行请求；Runtime 也拒绝过时的外部路径请求。原生补丁不可用时不会偷偷换回外部队列；面板显示失败，取消原生勾选后才恢复已开启的外部模式。
- 到点续行只处理仍存活的己方飞机，跳过 Team、空袭和坠毁飞机。采用原版“已到达目标格”条件，没有移植 Phobos 的平滑转弯、飞水面及其它扩展任务补丁。特殊飞机/地图/MOD 行为需要实机确认。
- `[Experimental] BuildAnywhere=0` 与 `NativeAirWaypoints=0` 为默认值；不继承旧 `[Modes] BuildAnywhere=1`，避免历史设置自动启用危险功能。
- 面板显示关闭、等待就绪、已启用、不支持、冲突/安装或恢复失败；状态变化写入现有自动日志。

## 统一入口与生命周期

1. EXE 仅发布配置。原有消息入口在绑定游戏线程上安装、恢复补丁；不新增 DLL、不新增调度线程或帧调度 Hook。
2. `ManageGameEntry` 是唯一修改代码/虚表的写入者，只允许上述三个判断位置、下文两个绘制测试位置，以及 C4 Beta 的一个执行标志读取位置。旧帧、CS、事件、侧栏和 `0x464AC0` 修改请求仍被拒绝。
3. 管理器验证执行租约、模块身份、原始字节、补丁形状、目标属于本 GameRuntime 的可执行映像、当前字节所有权。冲突不可通过下一轮重试覆盖。
4. 游戏原生回调在同一管理器取得 Capture 租约；保存/恢复整数寄存器、标志与 x87/SSE 状态。异常边界释放租约并停用功能。回调直接读取当前游戏帧，不要求它等于上一次外部采样帧。
5. 关闭、对局结束、宿主退出/失活、异常路径均恢复自身补丁；菜单边界可能等到游戏线程下一次正常处理。DLL 固定驻留，避免残留回调指向已卸载代码。外国补丁冲突时不强行写回。

## 1.0.6 仅绘制测试例外

“地图全开：仅去黑幕 / 迷雾（绘制测试）”默认关闭。两个绘制叶函数 `0x47EFE0`（6 字节）/ `0x47F250`（5 字节）由同一管理器安装和恢复；不改变全局视野查询或模拟状态。原调用者的视野缓存计算仍执行。该项仍是游戏代码 Hook，已计入本清单；仅作用于绘制不等于已经证明联机安全。详见 [实现与测试范围](ESCAPE_AND_RENDER_REVEAL.md)。

## 1.0.7 边界补充

未增加补丁位置。所有原生判断/绘制回调先检查当前菜单、对话框及战术视图；暂停或不适用时执行原版分支，恢复后继续已启用的功能。停止桥接时仅在原游戏线程、相同有效对局中请求一次遮罩重绘。测试覆盖五位置同时开启、独立关闭、两组安装失败回滚，以及四种支持的会话模式。

## 1.0.10 C4 Beta（按用户要求开放联机）

默认关闭。`[Experimental] InfantryC4=1` 显式启用，`C4HoldKey` 默认 Alt+C，`C4Mouse` 默认中键；按键和鼠标键均可配置，空按键只需鼠标。选中己方步兵点击敌方 `CanC4` 建筑，经现有指针邮箱、统一仲裁和原版 MegaMission 构造器追加任务 17，目标与目的地均为该建筑的对象引用。保留原始点击，C4 不参与原生点击屏蔽。

唯一新增补丁为 `0x51A4D8` 的 6 字节 `mov al,[ecx+0xEC2]`。在当前玩家的存活步兵上返回 AL=1，其余走原始读取；后续原版距离、位置、目标及爆破逻辑继续执行。不开启时无补丁，不改 InfantryType.C4 或目标建筑内存，不添加帧调度或独立输入 Hook。管理器的允许位置、原始签名和所有权登记均已扩展；冲突拒绝覆盖，关闭恢复自有字节；整数/flags/x87/SSE 保持，AL 是唯一有意改变的指令结果。自动日志 `c4Beta`：1 安装，0 关闭，-2 冲突/安装/恢复失败。

**这是模拟判断修改，可能造成联机不同步或掉线。统一入口及 Beta 标签不会消除风险；单端启用不会让对方自动采用同一规则。** 原版混合谭雅规划漏洞仍未完整复现。C4 Beta 不声称复用了该漏洞，也不保证所有建筑、兵种、MOD 或平台能够完成爆破。
