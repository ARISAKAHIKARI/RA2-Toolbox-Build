# 1.0.17 Beta：战术决策双路径与范围调整

## 按功能职责划分

按用户最新要求，单位统计、预定列表、覆盖层、放大小地图等与外部 UI 绑定的功能保持外部采样/计算/绘制，不再把“迁入 Runtime”作为待完成事项。原版游戏 API、事件构造、最终合法性、生命周期取消和回执始终留在统一 GameRuntime 游戏线程。

本版新增智能卸载和载员逃生的两种决策位置，连同 1.0.16 的八项，集中配置共十项。新增 `[Compute] SmartUnload=1`、`Ejection=1`，0 为外部，1 为游戏内；默认沿用游戏内。配置自动保存，新对局或完整桥重建时应用，不在有任务时迁移所有权。选兵、原生判断仍为 Runtime 接口，外部飞机 Z 路径仍由宿主维护；没有为这些接口/队列提供无实际作用的位置开关。

| 阶段 | GameRuntime 模式 | 外部模式 |
| --- | --- | --- |
| 原始采集、原版能力/鼠标动作合法性查询 | Runtime | Runtime 发布带对局、帧、源时间的只读观察批次 |
| 部署观察/等待/重试决策，工程师/间谍/C4 后续目标及普通攻击目标排序 | `unloadcompute::decide` | 宿主运行同一个 `unloadcompute::decide` |
| 乘员任务、载具存亡/选中跟踪、手动取消、功能关闭/超时释放 | Runtime | Runtime |
| 身份/手动版本/当前状态/目标合法性复核、预算仲裁、原生事件构造及回执 | Runtime | Runtime |

外部模式是 Runtime 采集必要原生查询结果、宿主进行纯决策、Runtime 复核后下令；不是宿主调用游戏函数。初始卸载请求仍通过统一管理器下原生卸载事件。逃生继续仅跟踪选中的己方载具。没有新增独立 Hook、远程写入或任务拦截。

## 算法与异步约束

`unload_compute.h` 不依赖 Windows、进程读取或游戏函数。共享算法按部署动画和每位乘员位置/任务状态推进观察，先等待已排队的部署，发现中断后单独重试。没有同格全员串行锁。工程师/间谍按原版合法候选的距离排序，同距按 ID；C4 的合法建筑动作优先，普通战斗目标使用原有武器兼容条件。

Runtime 每批最多采集 64 位乘员、8192 个候选目标。批次和结果各有序列锁；计算不修改原始时间戳。外部结果必须在 150 ms 且 6 帧以内，与当前对局、任务编号、对象身份、手动版本、类型及观察状态一致。对象移动、改令、死亡、合法性变化、切局或功能关闭时，旧结果不能发送事件；下一轮按新状态重新采集。两种位置的算法相同，异步往返和过期丢弃会影响实际提交时机，不能保证逐帧相同或笼统保证内部一定更快。

只有事件成功进入统一原生通道才提交与发令相关的阶段推进；队列满时保留观察并允许后续重算。Host 的 `unloadComputed` 只表示计算完成，事件 ACK 仍由 Runtime 单写。

## 版本与验证

文件版本 1.0.17.0，Assist 协议 51、映射 v051，Runtime 传输协议仍为 3。EXE/DLL 必须一起更新。构建校验器兼容已经移除旧版二进制哈希字段的清理后清单，并继续严格校验当前文件版本、导出、协议和依赖。

针对实际 x86 DLL 与原版构造器执行卸载/逃生/内外计算及原生预定回归；覆盖五人中两人完成、三人动画中断散开后独立重试，外部结果过期、手动取消、目标死亡/合法性改变、关闭、切局、半写和队列满。配置和被动捕获协议夹具同步更新，计算掩码覆盖 1024 种组合。详见 `REVIEW_VERIFICATION.json` 与 `verification/review-117/`。

OS、世界和虚函数合法性是模拟夹具；未运行真实 Windows、兰博玩、双机联机、画面或端到端延迟验收。1.0.16 的进程重连、小地图和目录恢复继续保留，本轮未重复声称这些功能完成新的实机验收。
