# 1.0.24：绘制初始化、科技刷新与回调环境

本版基于已交付的 1.0.23。针对用户报告的战网开局断线，修正已证实的实现问题；不把受控测试通过当成断线根因已定位或双机联机已通过。

## 平台证据与结论边界

用户提供的（3）为战网，（4）为兰博玩。静态磁盘文件的 SHA-256：

- 战网：`268a81b7422b3bb855e1b4a162aadba4d807f88fb9f70feb99118211d8fbb8d0`
- 兰博玩：`c287d62a4d6a25b547e9339d071dd6e03adcf545699062e478aaeee38c60e89a`

两份程序在 `0x64C6F0` 比较 CRC；战网的 `0x64C6F2` 是六个 NOP，兰博玩保留跳往 `0x64CC61` 的不等分支。这支持“战网跳过一处不同步处理”的判断，不能推广为所有校验都被关闭，也不能凭文本字符串确定 LBW 的完整弹窗替换流程。工具箱不修改此处。

公开 [ProtocolZero.cpp](https://github.com/CnCNet/yrpp-spawner/blob/2f4918c758810bc204060278b28357a5a5507ff2/src/Spawner/ProtocolZero.cpp) 的 Enable 默认 false；[Spawner.cpp](https://github.com/CnCNet/yrpp-spawner/blob/2f4918c758810bc204060278b28357a5a5507ff2/src/Spawner/Spawner.cpp) 按配置 Protocol==0 启用它。它交换响应时间并协调延迟，不回滚修复已经分歧的游戏世界。

两份输入 EXE 在本轮核对的旧 ProtocolZero 队列、发送间隔和晚到事件位置均保留原始指令，不能证明采用了该静态实现，也不能排除运行时 DLL 或不同实现。因此 **战网、LBW 是否实际启用 ProtocolZero 均未确定**。本版不根据平台名称修改协议、MaxAhead、FrameSendRate、事件帧或 CRC 处理。

[Phobos ShroudFix](https://github.com/Phobos-developers/Phobos/blob/f75bc8f0e866d486d214fe772d7f7bd4a3505e0f/src/Misc/Hooks.BugFixes.cpp) 保留多人模式下三个特殊格子的处理规则。两份输入程序原生 `MapClass::Reveal`（`0x577D90`）已经包含对应跳过逻辑。旧“地图全开”仍调用原生 Reveal，会改变玩家与格子状态；不能称为纯绘制。此次没有重写该功能，也没有把上游的模拟修正单端移植进来。

## 修正内容

### 绘制未揭示区域

旧版在 `0x47EFE0` / `0x47F250` 函数入口提前返回，同时跳过了 SHP 资源的首次初始化。两平台样本在这段前缀中还包含内嵌资源跳转，因此不能把整个函数当成纯绘制操作删除。

现在保留原函数前缀，在初始化之后的 `0x47F038` / `0x47F274` 各替换五字节，仅在允许状态下省略后续遮罩绘制。补丁数仍为两个，旧入口不再属于管理器允许位置。关闭、菜单、失活、换局与冲突回滚继续由同一 GameRuntime 管理。原 Cell 调用者的遮挡查询及缓存更新保持执行，不调用 Reveal，也不改 Cell/House 视野字段。

这是已复现的初始化范围错误；尚不能证明它就是战网断线的原因。

### 科技全开

原文档声称每轮最多补八个图标，实际刷新代码却遍历全部类型。本版使用续扫游标：每个逻辑帧至多检查 32 项、添加八个新图标；同帧重复刷新不追加另一批，后续帧继续，目录改变时重新扫描。关闭时取消未完成扫描。

保持现有两处 UI CanBuild 调用适配及原版生产事件，不修改全局 CanBuild、科技前提、造价或原生生产执行器。分批刷新解决开局集中工作量，不代表生产规则差异已消失，也不承诺所有平台均可生产。

### 回调计算环境与重复查询

统一消息入口、结束消息入口、看门狗和判断/绘制桩，在执行工具箱代码前保存 x87/SSE 状态，清空临时 x87 栈并保留原控制字，使用确定的 SSE 控制设置；退出后完整恢复。调用其他 Windows Hook 前已经恢复调用方环境。它只隔离工具箱自身，不全局更改游戏浮点模式。

模块身份首次解析后缓存，避免每格绘制重复调用模块查询 API；执行租约、线程绑定、所有权和当前补丁校验均保留。

### 任意建造与诊断

本轮未找到新的任意建造判断实现错误，仍只保留原有邻接检查适配；回调环境修正同时覆盖它。没有关闭功能来替代修复，也没有新增私人注入入口。

启动日志增加同步分支、协议相关位置、绘制初始化和功能补丁位置的运行时字节证据。PE 元数据仅作样本提示，不是完整文件鉴定，不授予补丁权限。后续需结合实际加载模块、这些运行时字节和平台实测继续确认根因。

## 验证及限制

当前结果见 `REVIEW_VERIFICATION.json` 与 `verification/review-124/`，均绑定本次 DLL 哈希。

- 以 1.0.23 DLL 作对照，确认开启绘制时遗漏首次资源初始化、科技一次补入 42 项、回调继承外部 SSE 设置、100 次绘制重复查询模块身份。
- 新 DLL 分别结合两份输入 EXE，执行真实初始化前缀、实际回调、科技分批、菜单/换局/冲突回滚、侧栏权限、统一入口和飞机 Z 路径回归。
- 检查实际编译桩的寄存器、栈、标志及浮点保存恢复；执行原 Cell 绘制调用者，比较完整 Cell/House 字节及遮挡查询缓存。
- 无输入开局矩阵检查功能组合、前几帧写入、事件和浮点环境。它不包含完整平台启动器或网络层。

世界对象、Win32 API、原生查询与图形设备为受控夹具；没有真实 Windows 画面、平台扩展 DLL、完整游戏模拟或双机联机。不得把这些测试表述为“已保证战网不掉线”。文件版本 1.0.24.0，Assist 协议 52。
