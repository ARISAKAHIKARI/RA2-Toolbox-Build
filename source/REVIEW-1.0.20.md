# 1.0.20 Beta — 原生科技侧栏与玩家控制测试

基于已发布 1.0.19，文件版本 1.0.20.0，Assist 协议 52；Runtime/入口管理器 API 仍为 3。EXE/DLL 必须成套更新。

## 科技生产的实际阻断位置

本轮找回的是两个 0.3.0 源码包，没有找到可核实的 0.3.2 源码。旧源码同时调用 `SidebarClass::AddCameo` 并包装两处侧栏 `HouseClass::CanBuild`，而 1.0.19 只维护外部允许目录并发送 Produce。

对参考游戏原生指令的追踪发现：

1. Produce 执行路径：`0x4C7130 → 0x4FA350 → FindFactory → FactoryClass::DemandProduction (0x4C9C70)`。
2. `ObjectTypeClass::FindFactory (0x5F7900)` 的 requireCanBuild 分支在 `0x5F79A3` 调用 `CanBuild(type, true, true)`，这里只检查建造上限。其生产设施类别、阵营 OwnerFlags、供电等检查仍可能拒绝生产。
3. 侧栏绘制 `0x6A97D2` 与重检 `0x6AA781` 调用完整科技检查。重检失败进入 `0x6AA7B6`，若图标关联生产工厂，在 `0x6AA7E7` 构造 Abandon。因此，仅补图标或 Produce 仍可能立刻取消。

本版恢复真实 AddCameo，并将这两个 **UI 调用点** 的 buildLimitOnly 参数改为 true；仍调用原生 CanBuild，不伪造返回值。只对当前操控方、已启用清单中的类型生效；所有生产事件继续走原生构造器和统一 DoList/OutList。没有改 prerequisite、OwnerFlags、资金、工厂、生产执行函数或收到的网络事件。

两处补丁作为一组安装；签名冲突时回滚已安装项，功能报不兼容。正常生产设施消失仍由原版处理。每个原生页签最多 75 个图标，无法添加时不谎报成功。现在也支持有匹配建造厂的建筑类型。生产进度显示仍依原生工厂；成功入队不等于实际开工或出厂。

侧栏许可在同局持续保持，不因宿主界面短暂卡顿超过心跳阈值而改变；停止、故障、实际退出和换局清理由统一 Runtime 执行。关闭科技测试会恢复原版规则，因此不再满足条件的未完成生产可能被原版取消。

这不是“无工厂任意生产”。匹配阵营的设施、电力、上限以及模组额外条件仍可限制购买。尚未进行真实单机购买、LBW 或双机联机验收。

## 玩家控制测试

- **跨玩家单位操控**：Alt＋左键选择，Shift 追加；Alt＋右键移动/攻击。可混选不同玩家单位，包含 AI。此入口目前支持移动和攻击，不承诺所有普通快捷键对混选敌方单位有效；需要完整普通操作时使用切换操控方。
- **切换操控方**：显示本局有效玩家名单，明确选择后切换；可恢复原操控方，取消开关或工具正常停止会恢复。更改 Player 指针和 CurrentPlayer 标志，不转移单位所属，不修改 PlayerControl/AI 生产参数。
- **出售其他玩家建筑**：使用“出售被吸取目标”所配置的键盘/鼠标键。构造建筑原所属方的 Sell，不改变建筑归属；退款由原版按原所属方结算。

三项玩家测试开关启动默认关闭，不从旧 INI 自动恢复；切换目标不保存到配置。中立/平民/治安（Neutral/Special/Civilian/CivilianSide/Police）、MultiplayPassive、观战位、已结束玩家均被拒绝；名单与命令执行都检查。AI 可能在后续重新给单位下令。

跨玩家操控仅在选择流程的五个 ControlledByPlayer 调用点放宽判定：`0x6FBFB3`, `0x6FBFEF`, `0x5F45D2`, `0x5F45DF`, `0x5F45EF`。不修改 House::ControlledByPlayer 本身、AI 分支、原生命令构造或事件执行。原版鼠标命令不被删除，测试移动/攻击通过现有输入邮箱追加原所属方命令。

切换玩家前取消工具旧任务并清理本地侧栏，下一次调度使用新代次，旧请求失效。重建只处理本地 Cameo，不 Abandon 或重建 Factory。恢复记录绑定房屋对象 ID/类型/索引、完整房屋列表、Scenario 指针和单调游戏帧；世界更换后丢弃记录，不向新局复用地址回写旧值。关闭跨玩家选择时清除选择，避免残留不可操作对象。切换时同时清除待放建筑和超级武器目标光标。临时未就绪不等于换局，不丢失恢复记录；暂停期间恢复只改经身份验证的本地操控指针/标志，避免调用未就绪的 UI 函数。

原版投降路径 `0x48CA34 / 0x48CAB2 / 0x48CBAE` 从 Player 取编号后构造 Destruct(0x08)。切换会改变这一目标。平台身份和网络连接没有替换，操作系统关闭窗口仍断开本客户端；不能保证所有退出方式均替目标玩家自爆。联机模式未硬禁，但这些功能均标为测试与联机风险。

## 统一入口与隔离

`submitConstructed` 增加默认拒绝外方事件的归属检查。只有明确的 PlayerTest（Move/Attack）和 SellPlayerTest（建筑 Sell）能力允许外方事件，并再次校验开关、目标身份、存活状态和有效所属方。普通自动装车、维修、卸矿等仍保持 own() 校验，不获得跨玩家权限。

单机准备 DoList 的步骤现在保留已经验证的事件 house；此前无条件改写为本地玩家，会使跨玩家指令失效。多人包也保留同一所属方。兼容高层接口依赖全局 Player，因此跨玩家命令固定使用统一构造路径，不临时换全局 Player 来调用接口。

全部补丁仍由 `GameEntryManager` 在绑定线程、有效租约内写入，精确白名单和原字节校验；目标必须是本 Runtime 映像中的代码。回调借用 Capture 租约，保留寄存器/标志/x87/SSE 状态。最多 13 个实验点，注册表容量 16。没有新 DLL、私有线程、私有输入 Hook、接收事件 Hook 或仿真帧 Hook。

## 验证边界

`assist/tests/player_tech_runtime.py` 执行本次真实编译 DLL、原生事件构造器、侧栏重检分支和原生混选函数；其世界对象、FindFactory/CanBuild 部分结果及 Win32 API 有明确桩；混选测试为模拟容器提供 Find 虚函数，选择与取消选择的原生逻辑仍实际执行。检查科技启停、作用范围、冲突回滚、原生重检取消/保留分支、单机/多人 house 字段、跨玩家出售、禁用/中立拒绝、恢复、新局地址复用和原生混选。

另回归统一入口、线程/租约/补丁所有权、自动装车、普通建筑预定、实际 UI 构造布局和设置保存。旧入口测试中尚存的“允许帧/输入 Hook”断言更新为目前实际要求的拒绝；没有为通过测试放宽生产管理器。

测试结果及对应二进制 SHA-256 见 `verification/review-120/` 与 `REVIEW_VERIFICATION.json`。所有历史版本报告保留原版本标识，不能代表本版重新测试。未进行真实 Windows 加载、截图、真实购买/出厂、LBW 兼容或双机联机验收。
