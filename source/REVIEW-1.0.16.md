# 1.0.16 Beta：进程重连、目录恢复、小地图与计算位置

## 范围与证据

用户确认每局会退出旧游戏进程再启动新进程。本版按此条件审查；没有现场新日志，不能把代码缺口称为已复现的唯一根因。发现并修复：旧桥回收重新按 PID 打开进程，无法识别 PID 复用；首次绑定辅助/临时 HWND 后只检查句柄存活，不持续核对正式 YRpp HWND；类型目录仅首次初始化，或非空部分目录不再刷新。三条分别有进程身份、窗口与真实采样器测试。

## 读取与重连

`ProcessReader::connectionIdentity()` 返回不可变只读连接；`RetiredBridge` 持有旧连接至回收，直接查询旧句柄，不把新 PID 所指进程当作旧进程。采样缓存仍各任务独立，不加读取串行锁。

战术与统计每 250 ms 复核 YRpp `Game::hWnd` 0xB73550 的即时读值，并验证 PID/线程。正式窗口替换仍活着的辅助窗口时重绑；旧桥先停止并回收，再建新桥。单位统计清除展示状态。进程退出时清采样器、运行期对象指针与队列；磁盘图标缓存不按进程代次删除。

`catalogue_stamp.h` 复核四个类型向量的地址、数量、指针、ID/cameo 和可用性过滤元数据；稳定后 500 ms 复核，未就绪按有限频率重试。类型更新通过 Runtime 的 dirty 标记发布，即使总数没有变化也更新宿主。目录只保存本局指针，不跨进程复用。

## 计算与事件入口

`Compute` 配置集中保存八项位置。Runtime 在新对局初始化时读取请求掩码，回写本连接实际掩码；宿主始终按实际值运行。完整重建桥接也会重新初始化。修改配置不在活跃任务中途切换所有权。

| 功能 | 两条路径的计算 | 固定留在 Runtime |
| --- | --- | --- |
| 高级移动攻击、磁电、倒矿、防偷点杀 | 同一个 `planner::Planner` 消费 raw World；按掩码独占相应功能 | 原始快照、原版最终验证、预算、统一事件构造/提交、回执 |
| 高级进驻、飞机均匀攻击 | 同一个 `cooperativeInput/allocate`；内部直接读取，外部只读采集后分配 | 屏幕/选区捕获授权、原版进入查询、容量和武器复核、统一事件 |
| 装车 | 纯 `loading::assign` 可在内部执行或通过不可变任务交给宿主 | 候选/原版合法性矩阵、提交前身份/手动版本/容量复核、在途账本及重试 |
| 维修 | `decisions::shouldRepair` 同一算法，可在内部或宿主筛选 | 原始候选、节流/待观察去重、临提交合法性、维修事件 |

内部规划直接调用与外部相同的 `admitPlannerOrder/admitCooperative`，不写宿主计划载荷或其序号；原有命令 ACK 只由游戏侧写。外部任务 `loadComputed/repairComputed` 是纯计算完成序号，宿主拥有；不代表游戏已下令。结果必须匹配原请求和源时间/帧，过期不延长时限、不重放。战术 150 ms/6 帧，协作及匹配 250 ms/12 帧，都是拒绝阈值而非实测延迟。

还补齐仅开启防偷点杀时的对象索引准备，以及内部协作/计算等待任务的索引与帧唤醒条件。此前单独防偷点杀可能有有效快照却因最终验证找不到对象而不下令。

同帧配额冲突现在返回延后，避免被 `Planner::rejected` 当作目标无效拉黑。进入两种后端前都走同一 Runtime 调度，未增加 Hook、远程写入或独立注入。Runtime 的标准容器使用 DLL 自己的进程堆分配支持；不使用游戏堆，不引入 C++ 异常展开导出。分配失败进入既有 SEH 故障边界。额外计算会占用游戏线程，默认沿用原位置。

## 小地图

`minimap_overlay.h` 只读取桌面已显示雷达画面，不修改雷达状态。按实际游戏尺寸及客户区尺寸转换原版 160×140 像素雷达框，100–400% 镜像，自动缩到客户区内，原雷达左侧至少留空隙，避免自捕获。独立绘制窗口使用 layered + transparent + noactivate，输入穿透；菜单、失焦、聊天或捕获失败隐藏，最高 60 Hz。标准 YR 布局为依据，平台定制雷达布局/独占 DirectDraw 捕获需实机确认；不保证 GDI 可捕获所有平台。

## 验证边界

实际源采样器测试空/部分目录及迟到元数据；实际 DLL 运行计算位置和原版事件构造夹具；单元统计、共享读取连接、进程切换和小地图绘制调用用 ASan/UBSan。容器不支持 LeakSanitizer 线程枚举，关闭泄漏探测，资源句柄平衡由夹具断言。详细结果见 `verification/review-116/` 和 `REVIEW_VERIFICATION.json`。

遗留 `entry_runtime_regression.py` 主程序里的旧科技生产场景缺少当前 CreateObject 兼容桩，在 1.0.15 和本版同样失败；未将它算作通过，也没有修改生产校验来迎合旧断言。其共享实际 DLL 驱动被针对性脚本使用并更新协议 50 布局。未进行 Windows/LBW 实机画面/声音、网络同步及延迟验收。
