# Hotfix16：基础路径与整图延迟调查（进行中）

问题：关闭 xBRZ、素材高刷和额外画质后仍卡顿；场景、新帧间隔大几十毫秒。全图性能优先于流水线扩展。SHP/VXL 混合炮塔、采矿、路径点与阴影缺口仍待后续修复，不能因受控测试通过就标为实机完成。

## 边界与来源

本次是生产源码分析和合成像素/性能夹具，没有重新执行私有游戏 EXE；没有 Windows 实机、物理 GPU、真实联机或 FPS 证据。EXE SHA-256/新增函数地址与 ABI：不适用，未新增反汇编结论。沿用的 native 结构偏移见既有 Hotfix10/15 与对应头文件注释；本次不更改它们。

检查点基线：本地 09f172611a0466fb54709f6530aebb7d35aeccc8，对应远端 Hotfix15 56e6fc2ac844286575869dbb98ceed4432a5e1a2。

## 已确认

1. `SceneRenderer` 的场景耗时包含资源读取、解码、对象光栅、合成与 GPU 等待。新帧是成功完成之间的间隔，不能与场景耗时相加。
2. `Surface::blit` 的原尺寸路径逐像素重复除法/取整和采样分支。新增 1/256 像素对齐的连续行路径；2,304 个旧标量渲染器金值覆盖 RGBA 和深度、半透明、阴影、NaN/no-Z、发光索引和 1/2/4x 光栅密度，完全一致。
3. GPU xBRZ 的当前光照素材缓存原有 128 项限制。160 个 64×64 素材即使低于 16MiB 预算仍全帧抖动淘汰。改为含节点开销的字节预算、地址索引与精确所有权/光照校验。五轮交替合成基准：准备中位 5.736309→0.017936ms，第二帧复用 0→160，像素校验一致。这仅解释开启并放大 xBRZ 的一类开销，不解释用户三项全关时的全部卡顿。
4. 同源调色板在一次 presentation 内共享；下次 presentation 重新采样。生产 Context 夹具 300 次访问只采样一次、299 次命中不新增远程读调用，下一 presentation 能看到 RGB 变化。Context 的默认资源读取仍是 readFresh；新增渲染侧读取统计，不能继续只看采样器读次数。
5. 整图路径的 NativeCanvas 在 fork 上逐对象绘制、复制原生页，然后缩小输出；GPU 请求下的 VXL packet 也可能经 Surface 转回 CPU，整图并非所有对象都由 GPU 光栅。已实现 ObjectCanvas：按页收集有序绘制，不同页并行，精确复用不变页；同一不可变 VXL 和阴影在分页前只物化一次。验证：360 个带阴影/透明的对象，与旧逐对象路径逐像素/深度一致，覆盖移动、移除、顺序、光照、底图改变与预算失败恢复；96 实例只物化一次，下一轮全部复用。
6. 主屏幕状态增加地形、调色板、解码、VXL、对象合成、输出、特效耗时，渲染侧读调用、缓存与 GPU 设备/回退原因。设置页扩大状态区以便读到这些数据。

## 性能检查点与未解决项

旧视口基准的 17.4→6.9ms 是中间实现局部结果，不能作为当前整图性能结论。整图基准为 3840×1920 原生稀疏画布→320×160 输出、固定素材、移动对象，三项额外处理全关；连续行优化后 640/1280 对象仍约 25/43ms，其中对象合成约 18/35ms。分页并行初步将对象段降到约 8/17ms，但 CPU 缩小段升到约 13/14ms，总帧仍约 21/32ms，未达到目标；必须继续查缩小段和实际资产/游戏读取，而不是宣布完成。

物理设备检查没有 /dev/dri 或 NVIDIA 节点，只有已配置的 Lavapipe 软件 Vulkan 可作像素等价验证。硬件性能未知。单帧热点未查完，CPU/GPU 跨帧流水线扩展已按用户要求暂停；草稿未进入此提交。

验证文件：`source/assist/tests/camera_native_rows.cpp`、`object_canvas.cpp`、`gpu_scene_record.cpp`、`game_assets_host_test.py`、`radar_scene.cpp`；数据见 `evidence/render-latency-hotfix16-checkpoint.json`。115 项完整回归和 x64 构建完成于分页批处理加入前；新增分页当前已通过独立对象/场景夹具，完整回归和最终构建需在后续检查点更新。

## 第二检查点：整图输出与 8GiB 设计预算

- CPU 面积缩小按输出行并行，每个工作段有独立积分缓存；不同 CPU 合成页复用既有 RGBA/Z 缓冲。旧快照仍持有页时继续 COW，不覆盖旧帧。
- 整图在全部当前素材、光照、顺序和底图验证后，若原生动态页版本未变，可复用缩小前的合成输出；迷雾、注释和世界特效仍按本次输入处理。CPU 缓存存储未遮罩颜色，GPU 缓存含遮罩时比较当前不可变遮罩计划/alpha 所有者。
- 64 位按 8GiB 总设计预算扩大缓存：所有视图共用 24,576 原生页（约3GiB RGBA+Z）、共享原尺寸材料768MiB、共享 TMP256MiB；单渲染器模型256MiB、姿态32Mi pixel-cost、GPU packet128MiB、光照素材64MiB、CPU VXL物化128MiB，按需分配。32 位保留独立限制。8GiB 是总设计目标，不是已对进程所有分配实施完整硬上限；GDI/驱动和非缓存工作内存不在当前原生页计数内。
- 原生页共享计数改为原子 CAS，16 个并发申请线程验证不突破给定页数和正确释放。GPU packet 改为有索引的 LRU，去掉256项限制；同一共享 VPL 只计费一次。共享图像银行取消4096项限制，保留字节预算。CPU 行团队上限从3名助手扩大到7，按可用核数保留游戏/采样余量。
- 整图 GPU 页上限64位从2048扩大到8192。驱动允许大 storage buffer 时使用按需扩容的单缓冲；单缓冲限制128MiB且支持7个 storage bindings 时使用四个128MiB以内的 raw bank，内核按页索引选bank。小图及旧设备保留四绑定内核；仍保持逐页精确4x4积分、一次最终回读。
- 两个面积 shader 已用官方工具重新编译并验证 SPIR-V。Lavapipe 软件 Vulkan 实际执行2,304个独立原生页，超过旧2048门槛，逐输出像素精确；暖帧零上传/零积分重建，改一页只上传/重建一页，仍一次回读。原面积33帧/3,572,628通道及生产场景642,312通道，最大误差0。软件执行不代表物理GPU性能。
- 新增 `vulkan_area_large.cpp`、`render_memory_budget.cpp`；本轮117项完整回归和重建正在进行。性能最终数据与新产物尚未完成，不用中间基准宣称实机已修复。

## 第三检查点：CPU 重复计算修复与交付

基线为远端 `99c2b3e0a81fdd810b19f9e25eb7e3bb5e5aebdf`，现有本地 1,340 个源码文件的 Git blob 与其逐项一致。本轮没有执行 Vulkan，也没有新增游戏引擎逆向、地址或 ABI 结论。

确认的两项开销：

1. `NativeCanvas::Filter` 的积分表仅活到本次输出结束；同一原生页会被不同行工作段、下次绘制重新扫描。面积不超过 1,024 像素时还先用逐像素浮点权重累计半页工作，再重扫整页构建积分。现将精确积分表绑定到 Page 的 revision，不变页和并行读者共享；写入导致版本失效，COW 旧页保持原结果。大缩小足迹直接走积分，不再先累计半页。共享常驻上限为 x64 256 MiB / x86 32 MiB，超额保留原有每个 Filter 两行页左右的临时路径；不把它宣称为整个进程的硬内存上限。
2. `ObjectCanvas` 命中不变页后仍把所有有对象的页标脏，而 `SceneRenderer` 每次从纯底图重新开始缩小，导致一个对象移动也重算大量静止页。CPU 整图现在从紧邻上一次、未加迷雾/标注/特效的结果继续，只缩小改变和移除的页；背景、尺寸、后端或中间失败导致版本不匹配时仍从完整底图开始。对象顺序、光照、阴影和深度的比较条件不变；每次仍返回完整画面。

三轮交替 CPU 对照，每轮 20 帧，3840×1920 原生整图到 320×160 输出；xBRZ、GPU、素材刷新和额外画质关闭。素材是合成固定图像，不含游戏远程读取成本。表中为三轮帧中位数的中位数：

| 对象 | 运动 | 基线整帧 ms | 修复整帧 ms | 基线输出 ms | 修复输出 ms |
| --- | --- | ---: | ---: | ---: | ---: |
| 640 | 全部移动 | 15.719 | 13.033 | 6.300 | 3.543 |
| 640 | 仅一个移动 | 8.150 | 2.357 | 6.338 | 0.643 |
| 1280 | 全部移动 | 21.882 | 19.936 | 5.910 | 3.433 |
| 1280 | 仅一个移动 | 9.689 | 4.255 | 5.955 | 0.659 |

输出列为每轮该阶段平均耗时的中位数；所有对照的完整输出像素校验和一致。只移动一个对象时输出开销下降明显；全部对象移动时仍主要受对象光栅化限制，不能把这两处修复等同于整个实机卡顿问题已解决。

验证：7 项定向 CPU 检查通过。新增检查覆盖积分暖帧零重建、32 个原生页的跨行共享、COW 与原位修改、释放计费、静止页不脏、移动/移除/顺序/光照/底图变化后的分数面积输出与完整绘制一致。面积 CPU oracle 的 749,296 通道比较最大误差 0；地形局部场景检查比较 8,036,352 像素。没有运行 Vulkan。Zig 0.13.0 全量编译 x64 主程序 + x86 Runtime/broker，通过实际 PE 架构、协议、资源版本与依赖检查；未执行 Windows loader、真实游戏、联机或实机 FPS 验证。
