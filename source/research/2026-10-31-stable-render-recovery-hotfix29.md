# Hotfix29：先恢复完整画面交付，暂停画质增强与跨 API 直出

用户继续报告 GPU 死机、CPU 闪烁，允许恢复此前主体框架，并明确画面效果优先于 xBRZ、超分、颜色增强等功能。本版是恢复候选，不把交叉编译等同于实机问题已消失。

基线：本地 `88bb838ad2a6f68ceba99cd32be1a5392e405163`，远端 `aa558bbbc8498cde6bdb8b6211b79f7a4e58c7b7`。调查前读取现有 INDEX、HF17/HF28 与整合自审和同一 SQLite 笔记。没有执行私有游戏 EXE，没有新增引擎地址或字段偏移。此前支持样本 SHA-256 `268a81b7422b3bb855e1b4a162aadba4d807f88fb9f70feb99118211d8fbb8d0` 仅用于标识既有静态资料，不表示本次执行或重新反汇编。

## 调整

1. 主视口恢复一个绘制工作线程负责素材准备、世界合成和完成帧发布。状态采样与地形读取仍各自独立。删除主视口第二个异步 presentationWorker，减少两个绘制者之间的快照/配置/资源交接。保留已有世界输入、对象、阴影、迷雾和特效适配；这不是把 Vera 的 Rust/wgpu 引擎整体换进来。
2. GPU 仍做 Vulkan 场景计算，但输出走已有的完成 fence → 最终像素回读 → 统一 layered-window 呈现。暂停 Vulkan/D3D11 共享纹理、keyed mutex 和 DirectComposition 直出，且不启用这套 Win32 外部内存设备扩展。主视口、副相机和实景小地图共同遵守这条输出策略。没有把 GPU 开关映射成关闭全部 GPU 计算。
3. CPU 回退恢复原来的完整 Surface 顺序重放。撤回 HF28 新增的输出行分片：附件、原生 Z/A、位移目标读取继续操作同一完整目标，不再每个 band 重入完整素材准备。没有宣称串行必然更快。
4. 完成帧窗口恢复为采样最大 2500 ms、完成最大 1500 ms。HF28 的 100 ms 完成上限会在渲染用时 250 ms 的场景中间撤下已完成图，这条状态机问题可独立验证；尚不能证明用户全部闪烁只有这一原因。UI 轮询、失败重试、touch 均不更新完成时间。菜单、失焦、世界/配置/窗口改变仍立即失效。
5. 等待新图时保持旧图自己的完整相机与坐标，不平移、不延伸边缘、不复制填充。保留世界时去掉原生透孔及旧交互层，避免从错误位置露出原游戏像素。一次光标/选择读取失败不再独立撤掉整张有效世界图。短时视口读取失败仍受 120 ms 的视口证据窗口限制。
6. 运行参数固定原始素材精度、原生 DAC/兼容光照与最近邻采样；移除视频页七个增强选项，不受旧 INI 中开启的额外画质/xBRZ设置影响。光照、单位、粒子与光束内容开关继续使用原设置。
7. CPU/GPU 共用 native-coordinate 的水线裁切取整 helper；修正 0.5x 时 CPU=100、GPU=99 的旧差异。Display 顺序采集在最后一次对象 ID 读取之后再检查帧号，失败不提交部分顺序。

## Vera 参考边界

固定参考为 `ARISAKAHIKARI/vera20k@3d42426b2e9c1b4cf913a7dbbaaf8bf7d3b6bc7f`。

- 本轮读取 `src/render/gpu.rs`：一个生产帧完成后才呈现；surface 超时/遮挡跳过本次获取，不把失败当成一张新空图；失效表面有限重建。
