# 1.0.47-pre.1：功能缺陷修复与计算、采样存储优化

## 基线与证据范围

用户指定以 **1.0.46.4** 为基线，后续版本使用 **1.0.47**。本轮准备 `1.0.47-pre.1`，Windows 文件版本 `1.0.47.1`。基线源码为远端 `f452d1cb95c57f465356b55a3d7b83fb7403a70a`，本地等树提交 `5a0f36704e80cc715215318660e31786c4c26cbc`，完整 tree 为 `74117a0d765d4ae69a38fbebd7a177444c7e2b71`。

本轮承接上一轮只读审查，修改工具箱自己的算法、采样派生结果、缓存寿命及依赖验证。调查前已读取 INDEX、相关统一采样与前两轮性能记录，以及同一份持久 Notebook。没有新增游戏可执行样本、地址、ABI 或字段偏移结论，因此本条的游戏 EXE SHA-256 不适用。没有包含游戏文件或原始转储。

当前定向证据放在 [pre147-optimization](evidence/pre147-optimization/)。完整产品交叉构建、静态 PE、源码同步和安装包回读由冻结后的交付回执另行记录。下面的计数和耗时来自 Linux 宿主受控夹具，不代表 Windows 游戏帧率、物理 GPU 或多人联机验收。

## 导弹分配：保留精确规则，减少候选重访

原实现每次分配都遍历剩余源与目标，满容量下重复访问同一候选。新实现为每个目标建立候选堆，再用一个目标堆选择全局最佳候选。已分配的堆首是该目标真实最佳候选的乐观上界；仅在其成为全局堆首时清理，并重新参加比较。改变目标的伤害、数量等排序键之前，先把该目标移出全局堆。

比较仍保留就绪状态、选择数、现有目标优先、距离、威胁、ID 和最后的原始源/目标下标；完全相同 ID 或距离时仍遵守旧版 source-major 顺序。分配后的 covering、fallback、Advance/Hold/Release 和输出顺序不改。常规最坏候选处理从重复整表扫描降为每条边至多出堆一次；不是通过减少目标、降低频率或省略计算取得收益。

Host 的单一导弹 worker 与 Runtime 的单一 dispatcher 分别拥有固定工作区，容量为 66,304 字节；生产入口不在每次调用中堆分配或把它放在栈上。保留的一参数便利接口会按需建立工作区，但生产两条路径使用显式工作区入口。

冻结的 1.0.46.4 原函数与新函数在 **8,063 个场景**中逐字段、逐项、逐顺序一致，包括四种模式、零/非法计数、重复 ID、完全相同距离、状态与预约、污染工作区复用和满容量。ASan+UBSan 的同组场景通过；容器不支持本次 LeakSanitizer 枚举，后续明确关闭泄漏检查，不能声称 LSan 通过。既有 missile 行为夹具通过。

| 256 源 × 256 目标，四种模式 | 基线中位耗时范围 | 新实现中位耗时范围 |
| --- | ---: | ---: |
| 不同距离 | 26.42–34.17 ms | 1.78–1.79 ms |
| 相同距离与密集竞争 | 30.15–37.90 ms | 2.65–2.77 ms |

这些是同环境配对微基准；不能折算成固定 FPS 提升。Windows x86、Zig 0.13.0、O2 的实际函数目标代码包含的最大固定栈申请为 **8,544 字节**，已同时计算显式栈减法与 `_alloca` 探针，不能把只看 `sub esp` 的较小数字当作完整结果，也不宣称已测量整个游戏线程调用栈。

## 共享快照：只复用存储，每次发布保留新身份

原 Client 对每份新发布重新分配 Snapshot 与 PageBuffer。新池最多保留三个空闲底层对象；最后一个强引用释放后才可归还。池耗尽正常分配后备，旧读者不等待、不被覆盖，新发布不丢弃。既有 Client 互斥边界、seqlock、来源身份和导入完整性检查不变。

直接保留 shared_ptr 对象的初稿被否决：渲染缓存用 weak_ptr 识别发布身份，旧弱引用若能重新 lock 会把新帧误当旧帧。最终实现仅回收裸存储，每次构造独立控制块。归还器也释放对池的持有，过期弱控制块不会继续保留整池页面。断开/退役清理当前空闲缓冲，晚到引用只能归还其原有池。

预热后连续 20 份新发布，28、512、4096 页三组的 Snapshot 大对象和页面分配均从各 **20 次降为 0 次**；每份发布仍有一个必要的小控制块，Linux x64 夹具中合计 800 字节。4096 页组基线的 420,085,760 字节是这 20 次累计页面分配量，不是峰值内存、RSS 或泄漏。2,000 次同帧 acquire 原本与现在都没有额外分配。

代价是保留空闲容量：每池至多三个空闲 Snapshot/page 缓冲，另加仍被读者持有的发布。按当前最大页面容量，每个页面缓冲上限 84,017,152 字节，三个空闲缓冲合计上限 252,051,456 字节；按需增长，并非预分配。常规两缓冲轮换通常低于此上限。

实际 Client 夹具的 6,988 项检查覆盖九份旧发布同时固定、旧 weak 失效后同地址复用、真实调色板缓存更新、增长/坏页/控制块分配失败恢复、退役重连、跨线程归还和 seqlock 交错。ASan+UBSan 通过，LSan 未通过的环境失败单独保留。既有 core 74,634 / 75,357 项检查通过。x86/x64 Windows Client 路径目标代码生成也通过，不是 Windows 执行。

## 地形：复用大数组，只清理上一轮写入的位置

Terrain 同样只在最后一个读者释放后复用底层存储，每次新发布建立新控制块。记录本轮触及的 cell 下标，下次只恢复这些位置的默认颜色、遮罩和素材状态；没有物理 cell 的合法空洞保留与新分配完全相同的默认值。图示/真实素材模式切换、失败事务及多段扫描仍走原完整性判断。交换池槽时短暂持锁，清理大数组在锁外进行。

受控暖态采样的总分配量由 **15,345,816 字节 / 22 次**变为 **141,288 字节 / 18 次**，四次大数组分配降为零，分配字节减少约 **99.08%**。首次和池耗尽仍可正常分配，不能宣称所有情况下零分配。最多保留三个空闲 Terrain 存储，在途读者持有的缓冲另计。

验证覆盖旧 weak 失效、同地址新身份、12 份旧图固定、跨线程归还、缺页与部分失败、模式切换、多段扫描以及未触及空洞的内容一致性；ASan+UBSan 通过。既有 shared scene 与 radar visibility 发布检查通过。

## 科技类型采集：按原生数组合并扫描

原逻辑对 21 条规则分别扫描其类型数组。现在每个不同数组只扫描一次，成员解码一次后与该数组的规则匹配；保留每条规则在原数组中的首次命中，找到全部所需规则即停止，避免长尾反向退化。

既有 500 ms 检查时点、时钟回绕、索引不可用时的立即重建、世界/签名准入、热回调的实时对象身份与级别/成员资格复核均保留；没有新增持久的授权结果缓存。

目标均位于长数组前端时，成员访问也由 118 降至 24。18 组冻结基线对照的捕获身份全部一致，新实现执行 57,529 项检查；既有中途开启等 50 场景 / 179 检查通过。

## 两处功能修复及恢复路径

### VXL 缺失部件不能成为永久残缺缓存

将合法空部件、完整部件与暂时不可读部件区分开。已知无 VXL 的空槽有效，并且不读取其无用 HVA 槽；有资源或槽读取失败时，拒绝整次 ActorArt 发布。身体、普通/额外炮塔与炮管，以及实际需要的缩放、偏移和变体元数据都必须完整。磁盘资源失败时仍允许健康的 live 资源后备。

拒绝不完整缓存之后还发现恢复时效问题：必需 VXL 仍使用可选图像的约 2 秒重试，会阻塞新场景。现将未准备好的必需 VXL 接入已有 16 ms 重试与解码预算；不绕开预算。实际 `pose.voxel=true` 的八组场景在资源恢复后 20 ms 可恢复，151 项检查通过，与健康基准零像素差异。旧头文件负向对照出现 69 项失败和 4,704 个差异像素，健康对照摘要仍相同。

### 暂停显示使用飞机自身的已提交来源

飞机扫描比其他战术采样频率低，不能用其他派生结果的时间戳替飞机续期。新增自己的 match/frame/serial/tick 与数量，失败时回滚数量、IDs 和来源。暂停后同一份确已确认的 sealed 样本可继续显示，不延长原有选择指令的 500 ms 时效。

若刚好暂停在上一轮飞机扫描之后，只从已经固定的 sealed 字节补一次飞机派生结果；无新原始捕获、无 live 读取。补读失败的同一 match/frame/serial 记为已尝试，避免反复遍历不能自行恢复的不可变样本；下一份来源或完整采样仍可重试。

8192 槽飞机表、最后对象字段缺页的受控场景中，首轮仍需 294,898 次读取；修复前下一轮重复 294,898 次，修复后为零。失败保留旧 display stamp/IDs/tick，下一份真实发布恢复。另覆盖有效空名单、时钟回绕、来源失效和原有命令 TTL。

## 暖态依赖检查与未完成项

依赖优化限定在三个 managed 缓存记录全部有效时，把原有 NumPy、SciPy、OpenCV 版本、模块来源和原生功能检查顺序放入一个 `-I -S` 隔离子进程。每一项仍执行原 PROBE_CODE；只在全部完成后写入单独的批量成功标记。缺项或失败回到原逐项检查/修复路径，测试注入自定义 probe 时不会意外启动真实子进程。下载、安装、PowerShell 与取消机制的业务流程不改，也未增加常驻 worker。

13 项控制流检查通过。八批健康缓存的替身 Popen 调用从 24 降到 8，原模块检查仍为 24 次，各项功能断言次数保留。这里实际执行原探测脚本，但版本、来源、功能由合成模块提供：真实子进程、下载、安装和原生扩展执行均为零。覆盖错版本/来源、功能失败、后项正常提前退出、缺元数据、失败回退、取消传播及注入兼容；不据此声称真实科学库已经验收或得到实际耗时收益。

**光标混合画布像素边界缺陷仍未修复。** 自动审批审查先阻止原光标/依赖任务，随后对缩小为纯图像画布兼容性修复的动作仍返回可能存在网络安全风险，没有更具体原因；本轮未继续尝试该动作，也没有把它列为完成。上述依赖项是另行限定的验证进程合并，不是原先的常驻会话方案。

没有修改每逻辑游戏帧最新统一原始采样的要求，没有用降低刷新/采样频率实现这些收益。Host 与 Runtime 的请求计数差异也不直接等于重复采样缺陷。真实 Windows 游戏的视觉、CPU、帧率、物理 GPU 与联机表现仍待现场验证；预发布不能被描述为所有漏洞已清零。

现存 enemy_markers 独立夹具的 freshReads 断言在保存的基线与当前 TacticalSampler 中同样失败；现存 hotkey_host 夹具缺少当前 middle_input_host 的 Win32/UI 接缝而不能编译。本轮没有改写这些旧夹具以让汇总变绿。飞机选择的时效规则由实际生产 selection header 的专项夹具覆盖；这两项旧夹具失败与本轮七组定向通过的范围分开记录。
