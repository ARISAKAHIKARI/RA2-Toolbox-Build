# 覆蓋層閃爍、輸出尺寸合成與 Hook 生命週期

基線 `09455e9e9929ed118689c1d5a82718ddb1b2789c`。使用者現象：懸浮載具乘員氣泡閃爍、右鍵拖屏時建造預定數字閃爍、小地圖及副相機慢且覆蓋物時有時無、小地圖沒有星級；另要求統一可設定顯隱鍵、觀戰／玩家出局／切屏保留包括命令入口的 Hook。

持久 Library SQLite 筆記本本次工具不可存取，保留此頁供後續回填。下列是源碼審查、固定上游來源、受控記憶體／Win32 fixture 和合成基準；沒有實際遊戲畫面、RA2OL 雙機或現場 FPS 的證明。

## 具體原因與修正

1. `main.cpp::paint` 把固定建造欄數字和世界標記放在同一個 camera-bound 非同步 surface，鏡頭提交後舊 World 被隱藏，新 World 未完成時固定數字也消失。數字／側欄提示現在有獨立非 camera-bound 層；頁籤、世界和尺寸身分變化仍會使舊畫面失效。
2. 全部元素暫時空集合時清掉 worker 結果，但保留「上次已畫內容」比較快取。相同元素返回被判不變而不重送。失效與重送狀態已配對。
3. 懸浮／乘員鏈及 native cameo 幾何讀取失敗被當成有效空資料。現在區分有效空和不完整，顯示可在同一身分中短期保留；成功空結果、真正移開、換局／頁籤／尺寸立即按規則失效。舊畫面不能授權點擊，輸入仍要求新鮮讀取。
4. 地形 TMP／Overlay／Smudge 目錄失讀、色盤或必要素材解碼未完成，曾被發布為缺少覆蓋物的完整新圖。改為 checked 目錄與 ground/frozen 完整性返回，未完整候選不替換上次完整實景。有效移除或空資源仍能發布，不會把所有舊物件永久留下。
5. `LastTheater(0x822CF8)` 失讀被默認為有效 0，造成素材 revision 改變、全快取清掉，恢復又清一次。同輪也重讀 revision。現在單次 checked revision；未知不改 key，換 PID／match 不沿用舊 key。
6. main／小地圖／副相機共享 scene bank，多個生產者晚完成的舊觀測可以蓋過新觀測。加入同 PID／match 的觀測時間單調檢查；較新觀測中的真幀回退及新 match 不被永久拒絕。

## 依實際面板尺寸合成

舊小地圖雖然最後輸出是面板尺寸，上游仍建立 `rawWidth×30`、`rawHeight×15` 原生地圖頁面，再完整合成與縮小。副相機固定 640×512 後再縮到常見 320×256，浪費四倍輸出像素。

新模式保留 TMP／底色繪製指令及原生 Z/A，按實際輸出像素重放，深度緩衝跟輸出尺寸配置；不先配置整張地圖的 native 像素頁面。保留 radar 全圖語義與原副相機 640×512 視野，不能把 `region.active=true` 當捷徑而改成裁切。主、副屏取實際所需最大面板尺寸，縮放後的場景寬高一路傳到呈現端。來源世界跨度限制與真正分配的輸出上限分離，6000×3000 等來源不因超過 16M 像素便使小面板 VXL 取樣失效。

小地圖星級從 Techno+0x150 的 veteran 值採樣，使用原生 PIPS frame14／15 表示一星／三星；負值19沿既有來源定義處理，讀取失敗不捏造星級，敵方偽裝不洩漏真實星級。CPU 繪圖和 GPU 命令計畫共用星級來源。

受控 production canvas 樣本：6000×3000 地圖→600×300 面板，舊方法配置1128個 native頁、建立地形約154.159ms；新方法0頁、建立保留指令約1.139ms、輸出合成約6.884ms。這不是實際地圖全流程或GPU／RA2OL FPS；素材、單位量、讀取、陰影與發布仍會耗時。詳見 `output_sized_ground.cpp`、`radar_output_scene.cpp` 及建置證據。

## 額外原生寬度錯誤：HWND 不是一個 bool

支援私有樣本 SHA-256：`268a81b7422b3bb855e1b4a162aadba4d807f88fb9f70feb99118211d8fbb8d0`。實際靜態反組譯核對：

- `FoggedObject::DrawAll 0x4D1890` 讀取 `dword [0xB73550]`，整個 HWND 為0才略過畫面。
- `Techno::GetVisualState 0x70396B` 與建築分支 `0x454552` 同樣讀取整個 DWORD，據此區分有畫面／無畫面的執行環境。
- [固定 YRpp Unsorted.h](https://github.com/Ares-Developers/YRpp/blob/d9795546950fcc75a94325ffc83b44d16ec34ce2/Unsorted.h) 也把 `0xB73550` 定義為 `Game::hWnd`。[固定 Vera20K 查詢語義](https://github.com/YuriPlanet/vera20k/blob/3d42426b2e9c1b4cf913a7dbbaaf8bf7d3b6bc7f/src/sim/cloak_disguise.rs) 區分 graphical_client 與其他隱形可見性條件。

原本 `native_scene_extras`／`native_draw_state` 只讀 uint8；例如 HWND=0x112200 會被誤當無畫面環境，saved building 被漏畫、隱形可見性也走錯分支。現改為完整 uint32，並把誤導的 fogEnabled 命名移除；**不是改成讀 Scenario FogOfWar 開關**。真正 FogOfWar 為 Scenario+1 bit0x10，它和這裡的 HWND 判斷是不同條件。fixture 覆蓋0、1、0x100、0x112200、0x112233以及失讀。

原始遊戲 EXE、私有反組譯及 dump 不提交。證據只保存範圍、雜湊和判斷摘要。

## 統一顯隱和 Hook 所有權

統一版預設 `· / \``（VK_OEM_3），可在影片／顯示設定修改。共用按鍵邊緣偵測器由戰術或統計模組接管，聊天、其他應用、按住鍵切回／接管不觸發。統計、小地圖、副相機、氣泡和其他覆蓋層一起顯隱；顯示隱藏不卸載 Hook、不停建造佇列與指令取樣，也不關 Shift 輸入時鐘。獨立統計程式的舊 Tab 行為保留。

Host 的同執行緒 HWND 重建只更新投遞地址，不送 stop、不解除訊息 Hook 或訂閱。真正換遊戲執行緒仍按舊執行緒存活／清理條件處理；不能把另一個視窗的句柄接到原執行緒上。`host_window_rebind_windows.cpp` 使用本機受控程序的真實隱藏視窗與 HHOOK，沒有掛接遊戲。

光標 `hide.cpp` 原先在讀取／驗證前便清掉 held，暫時讀不到 `WWMouse(0x887640)` 時可能丟掉欠原生的一次 Hide／Show 配對。現在按已保存的物件、虛表與必要槽分成目前／已替換／未知：未知保留責任並重試；確認替換不呼叫舊指標；仍是原物件才配對 Show。短失讀不標永久失效；明確關閉但還原尚未完成時保留命令與映射等待 watchdog。首次 Hide 後才失讀、同名映射重用並切到只讀資源模式，也必須先完成舊責任；未完成不能發布已恢復狀態。Host 的兩秒未顯示檢查移到前台／有效客戶區判斷與恢復呈現之後，切出首輪不會先被當成故障而 stop。

Runtime 將世界身分和命令資格分開：觀戰／出局／切屏、同世界暫停或讀取不完整不再直接整批 reset；命令入口的實體 Hook 亦保留。無法下單時清除本工具的舊工作並保留原驗證，不放行不合法物件／House 命令。實際世界更換、幀回退、明確停用、退出或故障仍執行必要還原；未完成的還原責任不能被新世界覆蓋。研究與 fixture 的最終檔案／結果記錄於本輪 evidence。

## 風險分類與尚未解決的邊界

原生武器／射程查詢維持實驗項，CRC 原值鏡像移除高危名稱；這是依實際功能分類，不代表它們不使用原生呼叫／入口 Hook，亦不等於已完成各平台聯機驗證。

事件所屬方保留仍標高危：若平台在觀戰時改 CurrentPlayer，而未送 OutList 尚有舊 House 事件，`AssistNetworkSend` 的既有清理保護可能返回0而暫停整包發送。直接放行會讓 native sender 改錯 House，清除未經身分驗證的隊列也不安全；本輪沒有以這兩種方式掩蓋此邊界。這個具體條件需獨立隊列與 RA2OL 測試，不能宣稱所有不同步原因已消除。
