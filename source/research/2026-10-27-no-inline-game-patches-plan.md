## 核心術語

「注入 DLL」、「Windows 訊息 Hook」、「inline Hook／改寫遊戲程式碼」、「呼叫原生事件函式」是四件不同的事。

- **注入 DLL**：把我們的 DLL 載入遊戲程序；單憑載入不會改寫遊戲 EXE 的指令。
- **Windows 訊息 Hook**：例如針對遊戲執行緒的 `WH_GETMESSAGE`；由 Windows 訊息 Hook 機制呼叫回調，不等於把遊戲函式開頭改成 JMP。
- **inline Hook／程式碼段補丁**：把遊戲函式或呼叫點的機器碼改成 JMP/CALL/NOP 等，會改變遊戲映像中的可執行位元組。
- **原生事件注入**：在遊戲執行緒呼叫原版事件構造器，再把事件放入正確的原版佇列。若只是呼叫函式並寫入 OutList/DoList，不必改寫被呼叫函式的機器碼；但仍要保證會話路由、事件格式、House、時間戳、順序及執行時機正確。

「不改遊戲程式碼段」不代表「不改任何記憶體」：原生事件會修改佇列資料；原生 Reveal 會改遊戲世界資料；渲染可改 alpha 緩衝；這些都與可執行指令不同。

## 第一輪功能分類（待逐項驗證）

### A. 原則上可採用無 inline patch 的路徑

1. 純讀取、統計、計時器、氣泡、工具面板、外部小地圖／副視圖。
2. 自動裝車、倒礦、維修、一般移動／攻擊／進駐等：若能只在既有遊戲執行緒入口判斷狀態，再用原版構造器及正常 OutList 事件提交，應避免為功能安裝遊戲程式碼補丁。
3. UI 快捷鍵、操作排程可由工具自己的視窗訊息／執行緒回調觸發；但不得從背景執行緒直接修改遊戲世界或直接呼叫非執行緒安全的原版函式。

此分類不代表目前所有實作已達成；要對每項功能檢查是否另有殘留或相依 inline patch。

### B. 可以有替代方案，但語義會改變或需額外證明

1. **透明／半透明黑幕**：目前使用 `0x47F038`、`0x47F274` 兩個遊戲繪製 inline Hook。若嚴格禁止改寫遊戲程式碼，不能再接管這兩處繪製主體。可研究獨立圖像合成／外部覆蓋層，但普通覆蓋層無法顯示遊戲原本根本沒畫出的未探索地形；要達到相同效果可能需獨立重建地圖渲染，且不保證等價。
2. **地圖直接全開**：目前以多處可見性、雷達、重罩／顯示分支補丁達成。可考慮外部只讀地圖呈現，或原生揭示；前者不是遊戲主畫面等價全圖，後者改動世界探索狀態且本機直接呼叫不會自動同步到其他玩家。
3. **原生揭示**：呼叫 `Map::Reveal` 本身不必修改函式程式碼，但直接在本機呼叫會改 House/Cell 資料。若希望多人一致，需找到所有客戶端都會按相同順序執行的既有同步事件／機制；不能把本機呼叫稱為已同步的原生網路事件。
4. **控制全部／跨 House 控制**：目前依賴 `0x50B6F0`、`0x6339BA`、`0x637E40` 補丁改變原生控制判斷。單純用原版事件構造器不能保證接收端接受目標不屬於發令 House 的事件。無 inline patch 方案可能只能保留己方單位的自動命令，不能承諾等價控制敵方／其他玩家。
5. **原生 MegaMission 仲裁、Owner 改寫、科技／放置／原生飛機路徑點**：現有部分實作以改寫呼叫點／判斷分支取得介入位置或放寬原生條件。需逐一判斷能否改成只提交標準事件；若原功能的定義就是改變原版判斷，應標為無法無損替代，而不是悄悄保留 inline patch。

## 設計硬性規則

1. 新分支中，預設禁止新增任何遊戲映像的 inline JMP/CALL/NOP 補丁。
2. 每個功能必須列出：讀取來源、執行入口、原生構造器、最終佇列（OutList/DoList/其他）、事件 House、時間戳／順序，以及是否寫遊戲世界資料。
3. 原版網路命令要在遊戲執行緒提交；Campaign/Skirmish 的本機 DoList 路徑不能冒充 LAN/Internet OutList。
4. 不得為了讓「無 inline patch」看起來成功而直接改寫對端／世界狀態；若原生協定不支援該語義，明確標記為不支援或降級功能。
5. 診斷需要讀取現有摘要與事件，不得額外呼叫會推進同步 RNG 的原版摘要函式。
6. 停用功能後要驗證遊戲程式碼站點沒有被本工具改寫，並檢查沒有殘留的外部 Hook 或舊設定。對外部第三方補丁不做強行恢復。
7. 先建「零 inline patch」的功能白名單和測試；不一次把所有功能改寫，以免無法定位行為回歸。

## 建議實作順序

1. 先做 patch-site audit：列出所有可執行映像寫入的站點、安裝條件、卸載／回滾和當前功能依賴。
2. 將不依賴遊戲程式碼補丁的純讀取／外部顯示功能標記為零 inline patch。
3. 將已使用原生事件的自動命令功能，移除其非必要遊戲入口補丁，保留正常構造器／OutList 提交；逐項驗證事件順序。
4. 將渲染、地圖可見性、控制全部等必須介入原生判斷的功能分為「外部替代」、「語義降級」或「無法無損無 patch」，不假裝同等功能。
5. 最後以靜態指令差分、受控事件測試及實際雙機測試驗證；只有前兩項通過不能宣稱聯機穩定。

## 現階段結論

可以建立一條以「不改寫遊戲可執行程式碼」為預設的新實驗分支。原生事件提交本身不要求改寫事件構造器的機器碼；但目前若干功能的入口、條件放寬及繪製效果確實依賴 inline patch，不能保證全部功能原樣保留。第一步應先盤點與分級，再分批移除，而非直接全局刪掉所有 Hook。

### 第一批候選功能的現有實作審計

- **自動裝車**：`autoload_bridge.h` 的 `enterEvent` 呼叫 `nativeMission(..., mission=7, target=vehicle)`，由共同命令閘道提交事件；此檔沒有自己的遊戲程式碼寫入器。
- **自動維修**：`repairEvent` 呼叫 `nativeObjectEvent(..., EventType::Repair)`，再由共同構造／入隊路徑處理；修理排程本身不需專屬 inline Hook。
- **礦車倒礦**：`external_orders_bridge.h` 將 Planner 產生的礦車任務交由 `nativeMission`，`EventLane::Planning` 和共享預算限制每幀提交量；該路徑不需要獨立安裝遊戲入口補丁。
- 這三項已經採用共用原生事件入口，第一階段主要工作是由全域管理器硬性阻止其他功能的 inline patch 安裝，確保它們可在無新增程式碼補丁的實驗模式下單獨運行，而不是為了「重寫」而改動它們成熟的事件邏輯。
- **尚未完成的驗證**：沒有本輪 Windows 編譯結果、沒有實際啟動後的站點位元組掃描，也沒有雙機測試。全域禁止補丁會讓控制全部、繪製迷霧、直接全圖、原生飛機路徑點等依賴補丁的功能回報不可用；這是嚴格實驗模式的預期降級，不是已修復這些功能。


### 第二輪：原生事件路徑與降級行為（2026-10-27）

#### 原生事件路徑確認

- `submitConstructed()` 將語義事件轉成 `Event`，經 `enqueue()` 按會話選擇單機 DoList 或多人 OutList；它本身不需要對遊戲 EXE 安裝 inline Hook。
- 自動裝車經 `autoload_bridge.h::enterEvent()` 提交 mission 7 的原生 Enter 事件。
- 自動維修經 `repairEvent()` 提交原生 Repair 事件（0x15）。
- 礦車計畫經 `external_orders_bridge.h` 的 Planner 任務提交 `nativeMission()`，最後進入共用命令閘道。
- 上述路徑有源碼契約測試，確認相關功能檔不直接呼叫 `gameentry::patch`。

#### 已知降級／不可宣稱的部分

- `NativeMegaGateway` 位於原生 MegaMission 成功加入 OutList 之後，負責觀察人工命令並更新工具內部的租約、預約、礦車暫停狀態。無 inline patch 模式會阻止它安裝，因此不能保證自動任務在所有情況下都會像原版／原完整工具一樣讓權給人工命令。
- 目前控制全部、黑幕／迷霧繪製、直接全圖、原生飛機路徑點、部分放置／科技適配等功能，仍依賴 inline patch；在此分支中應視為不可用或實驗性降級，不應只看 UI 勾選就認為生效。
- 全域管理器保護已阻止新安裝，但尚未增加所有功能統一的「無 inline patch」能力標籤／UI 提示；各功能的狀態碼仍需逐一核對，避免開關看似開啟但實際安裝被拒。
- CI 在 commit `8092748069f61c028386647b28c9ff8b92bd2c5e` 已通過來源契約與 Win32 構建；更早的 commit `4acd236ce236cca4ab8c22b9f5c5018083fdafa6` 也通過過 Registry policy 單元測試與構建。工作流已恢復該單元測試，等待最新 commit 結果。
- 目前沒有雙機測試證據。不能將「沒有 inline patch」等同「聯機一定穩定」。


### 第三輪：手動命令觀察替代方案評估（2026-10-27）

- 現有 `GameRuntimeHook` 是 `WH_GETMESSAGE`，只在遊戲取出訊息、呼叫 WndProc 前處理；`AssistFilterMessage` 能讀鍵盤／滑鼠狀態，並只在少數增強點擊路徑中抑制原始訊息。它不是原版事件「成功入 OutList」的事後回呼。
- 因此，不能只因看到玩家按下滑鼠，就立即取消某單位的自動任務：點擊可能是框選、建造放置、迷你地圖、側欄、拖曳或未被原版接受的命令。這樣做會讓自動裝車、倒礦、維修錯誤地讓權。
- `NativeMegaGateway` 的獨特價值是位於原生 `QueueMegaMission` 成功追加 OutList 之後，拿到已建立的 EventClass 與 actor ID，再更新工具的手動任務租約。禁用它後，原版命令仍可成功，但工具失去這個精確的事後觀察點。
- 候選替代是「只讀 OutList 差分觀察」或「既有訊息處理後的有限觀察」。兩者都必須先證明不會漏掉已被遊戲消耗的短命事件、能排除工具自己提交的事件、能處理 ring wrap／隊列清空／場景切換，並且不額外呼叫會改變同步 RNG 的遊戲函式。尚未實作，不能宣稱等價。
- 目前最安全的第一輪是保持現有原生事件發送，明確標記「手動命令後自動任務讓權」尚未驗證；先在無 inline patch 模式下做單機行為測試，再用兩端日誌驗證事件提交與任務觀察，不能直接把普通訊息點擊當作已接受命令。
- 最新完整 CI：commit `0525bcf3651056034bd90cf0c3d57137460f6216` 的來源契約、Registry 策略測試及 Windows x86 build 均通過。產物為實驗包，不是正式 release。沒有實際遊戲程序／雙機對局可由 CI 代替。
