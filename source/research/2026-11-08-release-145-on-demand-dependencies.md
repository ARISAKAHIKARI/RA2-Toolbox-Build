# 1.0.45：光标预处理依赖按需获取

## 用户要求与范围

用户认为 1.0.44 Full 过大，要求开源依赖在缺失时从公网下载。本轮仅调整可选光标预处理环境的获取方式和发布包成员，不改变游戏逻辑、共享采样、Broker 协议或渲染算法；保留 1.0.44 的修复。

默认 Full 保留四个配套程序、预处理好的默认光标动画、三套图案、预览和许可。移除的是 `runtime/` 下的 Python 科学计算环境；根目录的 `GameRuntime.dll`、`GameRuntimeHost32.exe` 继续随包提供。

## 体积依据

经 SHA256 核对的 1.0.44 Full 为 147,235,862 字节，共 2,994 个文件。其中 `runtime/` 有 2,552 个文件，解压后为 299,013,588 字节，ZIP 压缩载荷为 103,711,511 字节。

按实际压缩条目及 ZIP 头开销计算，只移除 `runtime/` 时为 43,013,421 字节，约 41.02 MiB，相比原 140.42 MiB 缩小约 70.8%。这只是基于旧包的计算，最终 1.0.45 附件大小还包含新程序、启动脚本和清单的差异，实际数值以发布 manifest 为准。

## 获取方式

只有点击“预处理补帧”或导入需要处理的新光标时才启动准备流程。普通启动、原生游戏辅助和已有光标动画播放不触发依赖下载。

1. C++ 在独立子进程中启动固定的应用内 `engine/prepare_runtime.ps1`，界面通过零超时进程轮询及进度文件更新状态。
2. PowerShell 检查本地私有 CPython；只有缺失或不能使用时才获取官方嵌入式发行包。使用临时目录、完整性校验和独立子进程探测，避免把半安装环境当作可用环境。
3. 仅依赖标准库的 `prepare_runtime.py` 分别检查 NumPy、SciPy 和 OpenCV。健康的旧安装直接复用；缺失或不能使用的组件按固定清单下载。
4. 新组件先解压到独立目录，检查实际 API 和模块来源，再发布组件索引。已发布目录不在原地替换，避免覆盖其他预处理进程已加载的 DLL。
5. 准备成功后自动继续最初的预处理任务。失败显示原因并允许重试；已校验的下载缓存可复用。

依赖固定版本、文件大小和 SHA256 记录在 [runtime-dependencies.json](../engine/runtime-dependencies.json)。Python 来自 `https://www.python.org/`，wheel 来自 `https://files.pythonhosted.org/`；不运行 pip，不从镜像自动换包，也不安装到系统 Python 或修改系统 PATH。

| 组件 | 固定版本 | 官方压缩包字节数 |
| --- | --- | ---: |
| CPython Windows x64 embedded | 3.12.10 | 11,133,606 |
| NumPy CPython 3.12 x64 | 2.2.6 | 12,614,190 |
| SciPy CPython 3.12 x64 | 1.15.3 | 40,966,184 |
| OpenCV Python headless x64 | 4.11.0.86 | 39,402,386 |

这些版本延续原预处理环境的 ABI 和库版本，不称为上游最新版。Python 的 SHA256 取自官方 Sigstore 材料中的摘要，wheel 摘要取自官方 PyPI 元数据。本轮已实际下载四个完整官方包，核对字节数、SHA256、ZIP CRC、解压体积和布局；没有将读取摘要说成已验证 Sigstore 签名。

## 取消、并发与恢复

每次任务在光标包的 `.preprocess/<任务标识>/` 下使用独立进度、日志和取消文件。关闭后立即重新开启不会清除旧任务的取消标志。同一光标包的预处理持有独占锁；依赖安装另有共享目录锁，进程退出会释放操作系统锁。

下载与解压检查取消和时间／体积上限，拒绝不符合清单的文件。ZIP 路径、大小写碰撞、链接和目录边界在提取前验证。校验失败或取消不会发布半成品索引；损坏或不可用的已安装组件需要重新通过探测。新路径优先于旧 `site-packages`，避免旧目录里损坏的同名模块遮住修复后的组件。

PowerShell 启动参数的执行策略仅作用于应用自有子进程，不调用 `Set-ExecutionPolicy`，不写用户／机器策略或注册表；强制组策略仍优先。路径通过 `CreateProcessW` 的字面参数传递，不经 `cmd.exe`。Windows 策略阻止该子进程时，界面保留错误和重试提示。

## 发布包约束

新包明确保留原来的四个 engine 文件，并增加 `prepare_runtime.ps1`、`prepare_runtime.py` 和 `runtime-dependencies.json`。Full 和 Update 都携带完整的七个文件，避免下载器、清单与预处理代码版本不一致。

Update 不包含用户配置、已有 runtime、用户光标或下载缓存，也不主动删除这些内容。正式打包继续要求固定源码、同 Git 树远端绑定、本轮四个配套二进制、PE／ABI 和协议检查、资源基线摘要、逐文件 SHA256、ZIP CRC 及 Full／Update 成员一致性。

## 验证证据与边界

本轮证据索引见 [manifest.json](evidence/release-145-on-demand-20261108/manifest.json)，记录验证输入摘要及实际执行范围。主要检查包括真实 C++ 准备／进度／取消函数的受控执行，下载器的缓存、完整性、路径、取消、锁与发布行为，真实官方归档布局和提取，以及轻量包成员与覆盖更新策略。

冻结前的定向结果：C++ 生产函数在 34 个场景下通过 106 项检查，启用 UBSan；Python 下载器通过 26 个测试，三个真实官方 Windows wheel 的所有成员均完成提取及逐字节比较；Linux PowerShell 7.4.6 执行 73 项生产函数检查，包含真实官方 Python HTTPS 下载及 35 个归档成员的提取；轻量包策略通过 7 个测试。另有 Python 与 PowerShell 的独立审查记录。以上分别记录，不能相加当作真实游戏功能覆盖数量。

检查修复了三个会影响重试的问题：关闭后立即重开共用取消文件、畸形组件索引导致持续失败、直接子进程结束后后代仍持有输出句柄导致收尾无期限等待。PowerShell 事务检查还修正了原子替换的空备份参数，并兼容旧 .NET Framework 缺少 ZIP 外部属性的情况。

Linux PowerShell 仅用于脚本解析及可移植函数的受控检查。它不等同于 Windows PowerShell 5.1、Windows 系统策略、真实 Windows UI 或原生 `.pyd` 的执行验收。完整 Windows 目标交叉编译、静态 PE 检查和最终打包结果另由本轮构建及发行 manifest 记录；历史游戏功能检查不计作本轮重跑。

本轮没有真实 Windows、游戏、物理 GPU 或多人联机验收，也没有新增游戏引擎逆向结论。此前暂停空闲飞机按钮、建造提示 `count==75` 边界及副屏拖动候选不属于本次依赖获取改动。
