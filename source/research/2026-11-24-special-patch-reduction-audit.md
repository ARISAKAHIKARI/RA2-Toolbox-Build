# 六类特殊补丁缩减审计

日期：2026-11-24。基线：`work/latest-ra2-integration`。本记录是源码审计，不代表游戏内或 RA2OL 双机验收。

## 审计原则

区分四种机制，不把它们统称为 Hook：

1. **指令补丁**：改写游戏映像中的指令，改变原生判断、发送或执行流程。
2. **数据指针替换**：改写 vtable/函数指针槽，仍有所有权风险，但不是写入可执行指令。
3. **硬件断点**：不改写指令，命中时修改本次 CPU 上下文；有槽位和命中频率成本。
4. **规则/世界数据写入**：不改写指令，但可能改变本地或联机模拟状态；不能因“无代码补丁”就视为低风险。

优先使用原生事件、只读采样和游戏原有接口；只有无法保持同等语义时才保留补丁，并要求显式启用、签名检查、统一管理器所有权和失败关闭。

## 六类模块结论

### 1. 放置、科技、控制与战术判断（主要入口：placement_bridge）

这是混合模块，不能整体删除。

- **随处建造**：受控模式使用 `0x4A8EB0`；直接模式使用 `0x4A8EC3`、`0x4A918E`。这几处改变原生落点判断，若目标是绕过原生放置限制，原生 Place 事件不能等价替代。
- **原生事件放置**：`placementImplementation=2` 使用普通 Place 事件，不安装上述补丁；但游戏仍按原生规则检查落点。它是安全的完成建筑放置流程，不是“任意位置都能建造”的等价替代。
- **科技解锁**：旧受控/经典/直接实现仍有指令补丁；`TechData=3` 改 Type 规则数据，不改指令但影响所有玩家和 AI；`TechParameters=4` 使用 1 个硬件断点（FullGroup），只在本方原生 CanBuild 查询中修改本次判断，保留原生工厂、阵营、海陆和上限检查。参数模式是当前最接近无代码、保留原生建造流程的路线，但有硬件槽和命中开销，不能宣称已经完成联机实测。
- **控制全部**：参数模式不写代码；Native/Master 模式仍依赖三个控制站点（`0x50B6F0`、`0x6339BA`、`0x637E40`）。跨玩家联机命令还受 Network Sender 所属方保留能力约束。
- **低伤害过滤**：工具箱候选过滤不需要原生补丁；修改游戏全局索敌阈值的原生模式使用 `0x6F7D44`，语义不同且可能影响所有房屋，继续保持显式高危、默认关闭。
- **C4 强制进驻**：`0x51A4D8`、`0x51C32B` 当前被功能可用性策略禁用，Runtime 不应重新安装。保留旧所有权恢复信息，不把停用路径重新开放。
- **飞机路径点**：普通原生事件模式不需要路径补丁；显式 UI Gate/完整到达实验涉及 `0x7E2908`、`0x416AB6`，并非普通路径点功能的前提，继续独立高危开关。

结论：保留可选补丁能力，但不让普通事件路径依赖它们；原生事件模式与绕过游戏限制的模式必须明确区分。

### 2. Direct Modes（direct_modes_bridge）

- **Direct Placement**：两个站点 `0x4A8EC3`、`0x4A918E`，改变原生放置判断。原生 Place 模式可替代“正常规则下放置”，不能替代绕过落点限制。
- **Direct Map**：五个站点 `0x508E60`、`0x508EBA`、`0x508F8F`、`0x577B3A`、`0x6D88FC`，用于真正改变地图可见性/揭示流程。
- **硬件黑幕显示**：`0x6D88FC` 的 1 槽硬件断点只改变显示路径的标志位，不修改 Cell/House 揭示状态；它适合“看见黑幕下的画面”，不等于真正全图、雷达或侦察卫星揭示。

透明/半透明 SHP 素材方案曾在实际画面中无效，已撤回；不再把该方案当作现成替代，也不自动重新启用。

### 3. Network Sender（network_sender_bridge）

- 七个站点：`0x649CA0`、`0x649D61`、`0x649DBC`、`0x649E1E`、`0x64B4EA`、`0x64B660`、`0x64B9D4`。
- 原版发送路径会把事件 House 替换为 CurrentHouse。跨所属方操控需要保留目标 House，故该组负责原生发送/打包路径的所属方适配与缓存一致性。
- 它只在明确请求的多人游戏控制/所属方保留路径上启用；普通本方下令不需要。
- 替代路线是保持本方命令，或使用 Private Out 的硬件断点路径（3 个 DR 槽）/私有队列路径。后两者改变传输拓扑，不是“调用原生发送器即可等价”的简单替代，仍需独立联机验证。

结论：没有已证明等价且更安全的原生 API。保留为显式高危能力，默认关闭；不为普通命令安装。

### 4. CRC MapIsClear Shadow（crc_shadow_bridge）

八个站点：`0x64DCCA`、`0x4F576B`、`0x4FC328`、`0x577ACA`、`0x577BC7`、`0x577CA7`、`0x577DB0`、`0x577F48`。

此机制需要同时观察 House+241 的多类自然写入，并在 CRC 读取时提供原始镜像，同时允许当前地图可见状态保持变化。单纯后台复制数据无法可靠区分同一帧内的自然更新和工具箱揭示写入；简单地在每帧恢复/重写也可能改变同步时序。

可研究的缩减方向是 CRC 计算边界单点适配，但必须先证明所有 CRC 入口、嵌套/重入和调用期间的状态一致性；目前没有证据证明它能安全替代八个观察点。

结论：保持显式高危、默认关闭。不能为了减少站点数量而改成未经验证的整帧回写。

### 5. FrameCommitted（frame_signal_runtime）

站点：`0x55DE81`。

普通产品不需要该补丁：消息边界唤醒和帧号变化轮询已有回退路径。当前代码只在 Hook Diagnostics 显式选择 Native Diagnostic 时尝试安装；未选择时发布 MessageFallback。

结论：产品正常采样不依赖该补丁。保留仅为精确诊断通道，不得把它作为普通 Runtime 调度或功能执行前提。后续可考虑把该能力进一步隔离到诊断构建，但本轮不改变诊断 ABI。

### 6. Native Tooltip（native_tooltip_runtime）

- `0x7F74D8`：文字提供器 vtable 槽，供建造时间文字及隐藏原光标时恢复原生提示文字。
- `0x7F74C8`：布局 vtable 槽，仅隐藏原光标时需要，负责绕过第二次可见性检查并继续原生布局。
- 两者是数据指针替换，不是指令 detour。替换后仍要保留严格的对象身份、原生 ABI、所有权和恢复检查。
- 建造时间单独使用文字槽；隐藏原光标需要文字槽与布局槽。外部覆盖层理论上可替代建造时间展示，但当前没有同等的原生悬停/布局/裁剪实现，不能直接删除。

结论：保留当前两槽语义；管理器现在只对已知数据指针槽使用非执行页面写保护。

## 其他附带站点

- 小地图相机边界 `0x6D8640`：只在边界反转或原生视口跟踪需要时安装；工具箱自己的导航坐标可先做本地限界，但无法保证所有原生相机调用者都被覆盖。
- 高速滚动 `0x4A9840`：当前滚动刷新模式默认关闭；普通产品不应安装。
- 以上不属于六个核心模块，但仍由同一 Risk/Entry Manager 所有权链管理。

## 本轮实际代码改动

`source/shared/source/game_entry_manager.cpp` 新增数据指针槽识别：

- Tooltip 的两个 vtable 槽，以及 `nativeviewportpolicy::Kind::Pointer` 站点，被识别为数据指针。
- 数据指针槽若位于可执行页面则拒绝安装；只使用 `PAGE_READWRITE`，不扩大为 RWX。
- 只有指令补丁使用 `PAGE_EXECUTE_READWRITE` 并刷新指令缓存。
- 写后仍恢复原页面保护，并沿用既有 ownership journal、冲突检测和失败恢复。

新增源码契约检查、六类补丁清单契约，并扩展真实 GameEntryManager 的 Linux 合成内存夹具：验证 Tooltip 指针槽使用 PAGE_READWRITE、恢复 PAGE_READONLY、不调用 FlushInstructionCache；若已知指针槽落在可执行页则在 VirtualProtect 前拒绝。清单契约锁定普通原生事件不回退安装补丁、Network Sender/CRC/Frame 只在显式条件下启用，以及显示断点与真实地图揭示的语义边界。以上由 `.github/workflows/ordinary-input-patch-contract.yml` 执行。
