# pre.13：混合场景暴露的重复地形与 GPU 阶段引用

基线为已交付 pre.12 Runtime `7201805`，连续混合场景源码 `4fe27b6`，完整测量文档提交 `f6b2927`。问题来自含地形、SHP、VXL、动画、粒子和光束的连续变化场景，参见[混合场景测量](2026-11-05-mixed-scene-render-stress.md)。本轮不调查新的游戏 PE、地址、字段、ABI 或 Hook；变更限外部渲染与生成素材的夹具。物理显卡、游戏采样和桌面呈现结果仍需独立验证。

## GPU 多阶段重复候选检查

原生隐形读取必须保留顺序屏障，但每个并行阶段沿用完整 CSR 分箱引用，shader 在取出引用后才检查 `firstDraw/lastDraw`。Medium 第20帧有4,992个draw、3个隐形对象、4个全视口并行阶段和3个局部顺序阶段：有分箱，仍重复约18,320,384次候选检查。不是每像素扫描全部4,992个draw。

候选修复为按阶段组织 CSR 引用，保持原始绘制索引、阶段标志、完整初始／末尾绘制、颜色／深度状态和隐形屏障；顺序阶段继续使用原 CSR。跨阶段的只读 packed run 保留整个原 bin，防止改变旧 shader“先 seek 后检查阶段”的行为。只修改 Host 命令，不修改 GLSL 或嵌入 SPIR-V。

最多65个阶段、额外打包 GPU 命令上限8MiB；无足够收益、无效输入、内存不足或超限均保留原 CSR。该限制只管可选优化，不减少对象或效果，不跳过绘制。CPU 构建临时容器另计。

初步纯 CPU 引用统计 Medium 并行候选18,320,384→4,577,024，顺序候选7,356不变；这不是 GPU 耗时倍数。接线后的实际 Vulkan 必须比较原 CSR 与新 CSR 的最终 RGBA，不能只比较都启用新算法的冷热路径。最终高档数量、测试和构建证据待冻结结果补齐。

## CPU 静态地形前段

混合场景动态对象使大量原生页变化，原实现每页重新回放全部静态地形。可选前缀原型在高档140帧交替对照中，动态合成中位70.145→40.436ms；这是四平面一致的原型数字，不能混入已交付基线的300帧测量。

原型也暴露了两个预算问题，均为采用前阻断：保留旧前台时，可选缓存抢占整批强制 COW 页面，造成反复构建后清空；多视图共享同一页预算时，第二视图无法回收第一视图的可选页。当前改用有明确全局字节计费的独立可选池，输出页仍必须计入原生基础页预算；不得通过 `Page` 拷贝构造继承可选池预算。该部分仍需独立复核与最终性能证据，未通过不得随包发布。
