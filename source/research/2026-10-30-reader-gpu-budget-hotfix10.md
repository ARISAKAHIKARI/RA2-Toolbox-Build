# Hotfix10：批量读取、并行像素计算、GPU 基础档与动画预算

基线是远端 `25f2d60fe6ecc6203cd982206b5f32a0389640f4`，分支 `codex/fix-render-feedback-20261029`。本轮产品修改在外部宿主，不增加游戏内 Hook、原生函数调用或游戏内存写入。既有迷雾模式保持原实现；素材替换是下面单独的可行性实验，没有接入模式切换。

调查前读取 AGENTS、研究索引、迷雾联机审计、动画坐标更正、原生绘制抑制记录，并查询同一持久 SQLite v85 的对应条目。

## 读取与真正的多线程计算

`ProcessReader::prefetch` 对同一采样 epoch 中相邻的对象内存页合并读取，每次最多 16 页／64 KiB，扫描最多约 4096 个候选页。对象字段仍走该线程自己的页缓存，跨 epoch 重新读；孤立页保持惰性读取。预读失败不填缓存、不将整段标成坏页，正常按页及字段回退。4096-byte 页、8192 页存储上限及独立 ReadSession 身份检查保留。

受控 RPM 替身中，16 个相邻对象页及其 32 次字段访问从需要 16 次页读取变为 1 次合并读取；下个 epoch 的新值、部分不可读区域及存储上限仍验证。这个调用数结论不是 Windows ReadProcessMemory 毫秒数。

新增全局有界行计算池：调用线程加最多 3 个常驻辅助线程，至少保留两个硬件线程的余量；任务小于 262144 像素／32 行时直接计算。并行部分只处理不可变输入与不重叠输出行：示意图栅格、原生区域复制、最近邻输出和 CPU 目标深度展开。其他渲染器忙时调用者自行计算，不排队；嵌套调用不等待自己的工作组。远程读取、素材上下文、绘图顺序及 GPU 队列没有被多线程无保护共用。

## 解码名额与 VXL 重复工作

旧普通素材最多 8 项／完成场景，吞吐与已经偏慢的绘制频率绑定。本轮改成实际耗时预算：宿主稳态预算按目标周期的一半取 1–6ms，未就绪时至少 8ms；建筑／建造出售过渡、短时动画弹体、普通单位分配 25%／35%／40%，分别轮转。每组至少允许一次实际尝试，单次不可中断解码可能超过软预算。512 次／组只是异常输入的上限，不是正常固定名额；缓存命中不消耗尝试数。磁盘首次扫描／单个大资源仍可能耗时，这不是完整的独立解码线程。

原来每帧无条件清空并重新光栅化所有 VXL。现在每次仍采集当前 VPL 和色盘，但当完整姿态／阴影投影、色盘与 VPL 修订一致时复用已有结果。当前 VPL 读取失败时禁止该复用，不会把前一次有效光照当成本次成功。没有修订可用性的其他 Assets 实现继续保守实时计算。当前场景的局部光照、深度和阴影叠加照常执行。

## 动画掉帧和 GPU 共用路径

采样到的爆炸、烟雾、附属动画或弹体可能在绘制前已被原版销毁。旧素材色盘刷新失败会拒绝整张场景。本轮仅从该帧移除已失效的短时实例；普通单位／地形素材失败仍保留原有拒绝条件。没有延长已删除动画的生命，也没有补造不存在的动画帧。

GPU 开关不再依赖精细场景；基础档维持原生 VXL 几何及显式最近邻，复用相同建筑部件、动画排序、维修、阴影和迷雾调用链。新增原生页最近邻计划，使用共享的完整输出轴查表，避免 1.5× 等比例连续累加误差落到前一个源像素。分数原生裁剪及缩小仍保持原有面积积分 CPU 底图，再由 GPU 合成对象；不把它们静默替换成最近邻。

GPU 驻留素材计划从每个源反复线性查找改为地址索引加严格 owner／长度／修订检查，空闲区域只建立一次；分箱改为连续计数、偏移及引用数组，保留原绘图顺序。300 个随机重装／淘汰 epoch 与冻结 Hotfix9 算法的 offsets、dirty 和上传字节一致。4096 个源引用的受控 CPU 准备基准，中位数约 3.41ms → 0.228ms；仅此步骤约 15 倍，不代表整帧／GPU／游戏帧率。

删除 DLSS 5 控件、配置读写和宿主处理入口，旧 `RenderDLSS5=1` 不会启动助手。渲染不再生成神经处理引导图；独立历史工具源码保留作历史资料。状态显示增加读取次数、批量页数、实际解码项数／耗时与 GPU 准备／等待／回读分项。

## 迷雾：替换素材能否代替跳过绘制

沿用原版叶函数 `0x47EFE0`／`0x47F250`（thiscall，3 个栈参数，ret 12）、`0x87E8A4` alpha 缓冲，以及 SHP 引用槽 `0x89E790/0x89E794/0x89E760`。本轮支持实验 EXE SHA-256 为 `268a81b7422b3bb855e1b4a162aadba4d807f88fb9f70feb99118211d8fbb8d0`；这是私有样本的原始绘制代码受控执行，不是 Windows 游戏实测。

**叶绘制语义可行**：保留正常绘制调用，把解码后的有效 alpha 索引改为 127，原版得到全透明遮罩；半透明用 `(value+128)/2`，大于 127 的跳过标记保留。普通 PNG 的透明色 0 不能代替这里的透明，原版 SHP 索引承担 alpha 含义。

`assist/tests/shroud_material_capture.py` 将自制的未压缩 32×32 单帧 SHP 放入合成资源槽，执行未修改的两个原版函数。源值 2／64／127／254 × 原素材／透明／半透明 × Shroud／Fog，共 24 案通过。绘制写入只落在目标 alpha、surface 锁计数、栈／SEH；没有游戏代码或模拟数据写入，surface 锁最后为零。证据为 `research/evidence/shroud-material-native.json`。

尚未验证全部 47 个原始 60×30 帧、压缩格式、SHPRef 懒加载、释放与缓存引用、热切换回滚和多人对局。因此本轮没有把可行性实验接到产品开关，也不据此宣称能解决所有不同步。实际接入应持有独立解压／重建副本并恢复原引用，不应逐字节覆盖压缩流或更改 Cell 探索状态。

## 动画后续仍缺的内容

粒子系统、辐射束、波纹和所有 MOD 特效尚未补齐。本次补的是既有 SHP／AnimClass／弹体链路的吞吐、失效处理，以及基础 GPU 的共用合成，不能写成“所有动画已支持”。

另外对同一私有样本的 AnimClass Draw_It 做了静态字段检索：`0x42308D` 读 Type `+0x36A`，`0x423183` 读 Type `+0x2EC`，`0x42309B/0x42318D/0x4231C1` 读 Anim `+0x178`；与固定 YRpp `d9795546950fcc75a94325ffc83b44d16ec34ce2` 的 Translucent／Translucency／TranslucencyLevel 结构对应。这里只确认访问位置，没有受控执行完整透明级别选择，不把级别阈值或混合百分比当作本轮已实现结论。

## 验证边界与入口

- `process_reader_pages_test.py`：合并页、epoch 更新、部分失败回退与存储上限。
- `parallel_rows.cpp`：80 个逐元素正确帧、嵌套调用、200 个并发提交；观察到 4 个计算线程。
- `immutable_atlas_plan.cpp`：300 次与旧算法一致性及限定步骤基准。
- `transient_scene.cpp`：40 个动画不被 160 个普通单位饿死，普通单位可超过 8 项，慢解码服从时间预算，已消失动画不拒绝整帧。
- `native_nearest_plan.cpp`：64 个计划／回退场景、2878500 个逐像素结果；分数比例、边界、明确不启用 xBRZ。
- `gpu_scene_renderer.cpp`：基础／精细、姿态、VPL 可用性、色盘、迷雾、切换、CPU 回放的 66 个场景。当前环境不能创建 Vulkan 实例，实际 GPU 使用为 0／66；不能作为 GPU shader 或硬件画面通过证据。
- `settings_dependencies.cpp`／`render_material_settings.py`：80 个依赖控件、32 组画质配置、旧 DLSS 配置和已删控件无效。
- 既有场景、目标深度、窗口裁剪和 GPU 指令回放回归通过；Windows PE／导入／ABI 静态检查单独执行。

本轮没有运行 Windows UI、真实游戏、联机或 GPU 硬件帧率测试。现网实际刷新率改善仍待用户环境验证。
