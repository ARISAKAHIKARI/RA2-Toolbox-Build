# 独立场景读取与分区点击恢复（Hotfix6）

本次仅调整工具箱宿主线程和呈现策略；没有新增引擎地址、ABI、游戏代码写入或逆向结论，持久逆向笔记保持原版本。

## 读取与绘制

此前 `render_upgrade_host.h` 在同一个 Latest 工作任务里先分页读取地形、单位和建筑姿态，再解码素材、合成世界、等待 GPU 和后处理。一个慢世界帧会拖迟下一次观察。

现在独立的读取任务持有自己的 `ReadSession` 和 Sampler，页面缓存、epoch 和诊断均不跨线程共享。UI 每次有效更新提交最新读取请求；两个任务各自最多保留一个运行任务和一个可替换待处理请求。绘制任务只取最新完成的不可变数据，不等待读取。读取侧保留最近两个已观察逻辑帧和实际时间，慢绘制跳过观察时仍使用最近的一对进行素材插值。重复逻辑帧最多在 8ms 内复用，暂停时继续读取和地形分页。

原有世界身份、视口投影、采样前后逻辑帧前进不超过两帧以及呈现过期检查保留。建筑帧计算抽到 `building_components.h` 复用已验证公式；make/正常资源角色仍由同一采样姿态决定，保留 Hotfix5 的基地车过渡修复。光照/色盘仍在实际绘制时读取。

状态中的“独立采样”是另一任务完成本次读取的耗时，与场景绘制重叠，不能相加理解为串行总耗时。没有修改逻辑模拟速率，也不保证未实测的 FPS 增幅。

## 覆盖层与设置页

相同内容的原生反馈挖孔向量按值判断；null 和空向量等价。合成没有脏区且已有有效可见 DIB 时跳过重复 UpdateLayeredWindow，仍执行需要的窗口位置/层级维护。失败上传会保留完整重传标记，避免重试把未提交 DIB 当成已显示内容。

每次点击左侧分区（包括重复点击当前项）均推进布局序号、重发类别并解除遗留拖动状态。真实内容 HWND 在所属 UI 线程恢复显示/层级；几何未变化时显式执行自己的 WM_SIZE，重新应用子控件位置、可见性与裁剪并重绘。战术类别消息即使类别未变也会重布局，保留原滚动位置；功能依赖导致的禁用状态不改变。

## 简要验证边界

`latest_worker.cpp`、`overlay_incremental.cpp`（新增相同内容/不同向量与 null/empty 断言）、`material_motion.cpp`、`building_components.cpp`、`frontend_restore_test.py`（重复选择的强制布局请求）、`game_assets_host_test.py` 为本地简要验证。最终编译/PE结果写入更新包 Build-info。

Linux 上的确定性 fixture 与 Windows 交叉编译不能证明真实 Windows 输入、DWM 显示或游戏帧率。完整 GPU 覆盖层/最终呈现仍未实现，本次依然使用现有 layered HWND 路径。
