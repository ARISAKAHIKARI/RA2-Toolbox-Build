# pre.11：隐形重绘、读取淘汰和地形采样等待

基线为已发布 pre.10 的 `6476ccf5af5d9783ed69bb27709aa58b0ecdc5f8`。用户认为还有重大耗时 bug，本轮对外部 Host 的读取、CPU 原生画布和采样调度做源码检查及生产函数对照。没有读取新的游戏 PE，没有新增引擎地址、ABI、字段偏移、Hook 或游戏内存写入；支持对象是本项目这一源码版本，不能把下述测试称为实机或联机验收。

## 1. 一个隐形单位使全图 CPU 回放失效

`ObjectCanvas::compose` 原来的 `hasCloak && changed` 分支对所有页面执行顺序回放。即使只有一个隐形单位移动，也会重新构建所有地形页面。该路径用于 SceneRenderer 的非 detail CPU 原生合成，以及整图 GPU 失败后的 CPU 回退；成功的 GPU 绘制不是本项测量对象。

隐形位移会读取其他像素，不能只重绘它的目标页：读取的源页可能包含绘制顺序更晚的对象，直接复用源页的最终像素会破坏顺序。本次按实际线性 `cloakWords` 位移建立读写页面的无向连通分量，保守纳入跨行、负偏移和附件。只有包含失效页的分量按原始全局顺序回放，其他页面复用。单独作为位移源的底图页也记录身份和 revision。若分配时淘汰了预计算以外的缓存页，整次事务冷重试；预算真正不足时拒绝发布，不发布缺页结果。

4096×2048、4096 个保留 TMP、64 个普通对象及一个每次移动的隐形对象，三轮交替受控测量：
- 原实现 135.221 / 145.460 / 129.616 ms，每次重画 512 页。
- 修正后 1.307 / 1.395 / 1.416 ms，每次重画 2 页、复用 510 页。

这只是这个 CPU compose 范围，不是整局 FPS。32 组完整 RGBA / depth / native-Z / alpha 对照覆盖冷/暖回放、页面边界、晚画的源对象、源页单独变动、链式隐形、正负/跨行/越界位移、附件/高度/裁切、2×/3×素材、非整页宽度、旧前台持有和预算失败恢复。已有 ObjectCanvas 回归亦通过。旧基线在位移源单独变动的反例中出现预期错误像素，新版通过。测试入口 `assist/tests/object_cloak_replay.cpp`，支持 `--correctness` 和 `--benchmark`；原始轮次见 `evidence/render-cost-fixes-pre11.json`。

## 2. 缓存仍有旧页，却淘汰本轮刚读取的页

ProcessReader 固定保留 8192 个 4KiB 页面，原 FIFO 只记录存储槽创建顺序。进入新 epoch 后刷新已有页面没有更新顺序，插入新页时会淘汰当前有效页，而留下旧 epoch 的槽。这不是必须超过 32MiB 才触发的容量问题。

修正使用可复用链表节点；只有完整页面成功读取（包括 prefetch）后用 O(1) splice 晋升。旧页面优先复用，失败/未读槽置于前部。缓存命中路径不增加顺序操作，重新绑定不额外分配页面或顺序节点。缓存上限、每轮新鲜度、直接 fresh 读取及失败回退不变。内部增加 pageEvictions / pageCurrentEvictions，未改变 Shared 结构或跨进程 ABI。

生产头文件加受控 Win32 读取替身：
- 1 个当前页、8191 个旧页，插入新页后重读当前页：额外读取 1→0。
- 4096 个当前页 + 4096 个新预取页，实际工作集正好 8192 页：预取仍为 256 次，后续不必要重读 4096→0。
- 原回归及新增预取已有旧页晋升、失败槽优先、零暖态分配、跨页/新 epoch/关闭/失读恢复通过；ASan/UBSan 通过。

`assist/tests/process_reader_pages_test.py` 是可重跑入口。容量之外的 field-major 扫描突增仍存在，本次没有扩大预算，也没有证明目标游戏当次触发了本模式。替身调用次数不能冒充真实 Windows syscall 时间。

## 3. 空网格消耗采样任务预算

主屏地形 worker 的 `step(reveal,8192,true)` 与观察窗 fallback 的 `step(reveal,16384,true)` 漏接已有 compactTraversal 参数。预算被 512×512 网格的空槽消耗，主屏始终需要 32 个任务槽完成一次地形银行；60Hz 时首末任务之间约 517ms，完整周期约 533ms，另加实际工作时间。这是调度等待，不是 CPU 单次扫描耗时。

两处改为第四参数 true，沿用现有紧凑遍历，只让实际准入 Cell 消耗预算。地图几何变化、短读和整份提交规则仍由原 Sampler 处理。真实生产 Sampler 对照：

| 几何边长 | 准入 Cell | 主屏 8192 预算 | 观察窗 16384 预算 |
| --- | ---: | ---: | ---: |
| 64 | 8128 | 32→1 个任务 | 16→1 个任务 |
| 128 | 32640 | 32→4 个任务 | 16→2 个任务 |

`assist/tests/radar_sampler_compact.cpp` 覆盖三种预算、显隐两模式、全部 Terrain/Geometry/CellArt/颜色/遮罩相等、短读恢复，以及完整和半途地图更换。紧凑遍历多一次本地准入扫描，CPU 本身约 5–9ms，某些小负载可能略慢；不把减少等待写成 CPU 减少半秒。
