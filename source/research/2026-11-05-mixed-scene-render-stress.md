# 地形、SHP、VXL、动画与粒子混合场景持续渲染

本轮补充连续变化的完整混合场景测量，记录每帧计算耗时。此前提到的 **47 是验证用例数，不是 47 FPS**。下列结果也不等于游戏帧率：没有启动游戏、读取游戏进程、运行游戏模拟或呈现到桌面。

固定测试源码为 [`4fe27b6bd1c258df0c502ae2154638880034f913`](https://github.com/ARISAKAHIKARI/RA2-Toolbox-Build/commit/4fe27b6bd1c258df0c502ae2154638880034f913)，基于 pre.12 Runtime 来源 `7201805`。完整报告、输入摘要及构建身份保存在 [证据 JSON](evidence/mixed-scene-render-stress-20261105.json)。本轮没有调查新的游戏 PE、地址、字段或 ABI，也没有包含私人素材或 dump。

## 场景与测量范围

素材由程序生成合法的 TMP、SHP RLE、VXL span stream 与 HVA 二进制，再经生产解码和绘制函数进入场景。它们是有实际可见内容的合成素材，不是游戏资产抓取。种子固定为 `23063`。

| 项目 | Medium | High |
| --- | ---: | ---: |
| 原尺寸世界 | 3840×1920 | 7680×3840 |
| TMP 地形实例 | 4,096 | 16,384 |
| SHP 单位 | 256 | 1,024 |
| VXL 单位 | 128 | 512 |
| 动画 SHP | 64 | 256 |
| 每帧粒子点 | 192 | 768 |
| 每帧光束段 | 24 | 96 |
| CPU 最终全图输出 | 512×256 | 512×256 |

两档共用 16 个解码 TMP、64 个 SHP RLE 帧和车身／炮塔／炮管三个 VXL/HVA 零件。组合模型有 1,710 个原始体素、1,362 个暴露面；三个零件各有四个 HVA 动画帧，预先准备 **32 个共享姿态、84,612 个三角形**。单位位置、SHP 动画和效果持续变化，部分 VXL 使用位移隐形。

32 个 VXL 姿态完成冷光栅化后，持续阶段复用这些姿态；测量帧中新 VXL 光栅化作业为零。因此这里没有覆盖每个单位都产生独立新姿态或每帧重解码素材的最坏负载。原生 Z 测试保持开启；合成单位使用明确的 `nativeZAdjust=-96`，用于该测试的可见层次，不作为真实游戏对象深度的验证。

CPU 路径为 `ObjectCanvas → NativeCanvas::present → WorldEffects::Painter`。初始化、哈希检查和预览生成不计入持续帧耗时。读游戏内存、资产发现、游戏逻辑、显示刷新和桌面呈现均不在计时范围内。

## CPU：300 帧持续变化与五次全局失效

环境为 AMD EPYC 9V74，容器可见 9 个逻辑处理器，cgroup CPU 配额为 8 核；编译器为 g++ 13.3.0，`-O2 -pthread`。每档先预热 20 帧，再连续测量 300 帧，300 帧输出指纹均发生变化。每 60 帧切换全局地形光照，测量窗口包含五次地形全局失效；包括初始化在内共更新六次。

下表单位为 ms，数值依次为中位数／P95／P99。分阶段百分位与完整帧百分位独立统计，不能把各阶段 P95 或中位数相加当作完整帧结果。

| 原尺寸世界合成 | 17.717／23.718／27.944 | 68.041／76.247／79.004 |

## GPU 视口：软件 Vulkan 正确性与阶段耗时

CI [run 41956498175](https://github.com/ARISAKAHIKARI/RA2-Toolbox-Build/actions/runs/41956498175) 的 [视口作业 127012544581](https://github.com/ARISAKAHIKARI/RA2-Toolbox-Build/actions/runs/41956498175/job/127012544581) 已成功。使用 Medium 世界，输出为 **1280×720**，预热 20 帧、连续测量 120 个移动帧。输出指纹 120 个均不同；计时循环结束后，对首／中／末三份冻结场景分别做冷 GPU 对照，共 **2,764,800 个 RGBA word 精确相等**。这是同一生产 GPU 路径的冷热对照，不是与真实游戏画面的对照。

设备为 **llvmpipe（LLVM 20.1.2，256 bits）软件 Vulkan**，不是物理 GPU。该环境下完整计算中位数约 **2.650 秒／帧**，主要时间在 fence 等待；不能用它推断显卡性能或游戏 FPS。CPU 和 GPU 测量的输出尺寸、执行环境及路径不同，也不构成 CPU／GPU 性能对照。

| 视口阶段 | 中位数 ms | P95 ms | P99 ms |
| --- | ---: | ---: | ---: |
| 世界更新 | 0.069 | 0.092 | 0.518 |
| CPU 绘制计划 | 0.266 | 0.305 | 1.684 |
| GPU 准备 | 1.872 | 2.063 | 2.203 |
| GPU fence 等待 | 2,647.491 | 2,678.177 | 2,718.528 |
| RGBA 回读复制 | 0.515 | 0.583 | 0.613 |
| GPU 后端整体 | 2,650.083 | 2,680.743 | 2,720.960 |
| 更新＋计划＋渲染 | 2,650.435 | 2,681.074 | 2,721.316 |

测量窗口在第 40、100 帧改变全局地形光照。每帧记录 4,992 个 scene draws、216 个效果命令、8 次 dispatch 和一次完整 RGBA 回读；窗口内没有新增上传、VXL 光栅化或 native prefix 重建。冷首帧为 11,376.103 ms；这些软件执行数值只用于解释本次 CI 行为。

## GPU 全图面积缩小：持续上传与未采集的子阶段

[面积缩小作业 127012544537](https://github.com/ARISAKAHIKARI/RA2-Toolbox-Build/actions/runs/41956498175/job/127012544537) 已成功。路径先处理 **3840×1920** 的 Medium 世界，再输出 **512×256**。同样预热 20 帧，测量 120 个移动帧；120 个输出指纹均不同，计时结束后的三个冷 GPU 对照累计 **393,216 个 RGBA word 精确相等**。

| 全图面积缩小阶段 | 中位数 ms | P95 ms | P99 ms |
| --- | ---: | ---: | ---: |
| 世界更新 | 0.080 | 0.098 | 0.358 |
| CPU 绘制计划 | 0.549 | 0.601 | 1.604 |
| GPU 后端整体 | 7,303.029 | 7,422.409 | 8,566.046 |
| 更新＋计划＋渲染 | 7,303.649 | 7,423.065 | 8,568.032 |
| GPU 准备／fence 等待／回读复制 | 未采集 | 未采集 | 未采集 |

**面积缩小后端没有实现准备、等待、回读复制三个子阶段的独立计时。原始 JSON 中这些字段的 0 是未采集占位值，不能解释为零耗时。** 后端整体约 7.303 秒／帧及完整计算约 7.304 秒／帧来自外层计时，仍是有效的软件 Vulkan 观测。两条 GPU 路径均为 llvmpipe；它们和 CPU 报告不是同一受控硬件环境，不能据此评价物理 GPU 相对 CPU 的快慢。

每帧上传和 native prefix 重建的中位数均为 **239 页**，上传字节中位数为 **17,126,994 字节（约 17.13 MB）**。第 40、100 帧两次全局光照失效均变化 282 页，分别上传 19,957,104 和 19,957,168 字节。全程合计上传 28,757 页、2,060,322,912 字节；每帧 11 次 dispatch、一次 524,288 字节的最终 RGBA 回读。该结果保留了全图路径的上传与重建成本，没有把小尺寸输出当作低工作量的保证，也没有证明全量重画已经足够快。

原始面积缩小结果文件的 SHA-256 为 `df2b6d5ad828f36d2e2012cb7785e116798d37f1532baf1d2853ce1e7e961e76`；完整 120 帧记录及计时可用性说明已合入证据 JSON。
