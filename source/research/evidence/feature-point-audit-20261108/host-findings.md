# Host 与控制台逐点审查

已登记并完成本轮源码追踪的共享功能/机制共 44 项。这里包含基础设施，不等于独立产品功能数量；与渲染/战术清单可能有交叉，不能相加形成虚假的全量覆盖率。每项入口、已查路径和验证缺口见同名 JSON。

## 确认的问题

`BROKER-LOCK-01`：x64 Host 在 Broker 初始启动/重连期间同步等待，并占用共享 `Host::mutex`。生产 `Client` 与从当前源码提取的 `clear/reapTargets/pulse` 在受控边界运行：100 次健康 pulse 没有正等待；恢复的 3000ms 与 2000ms 等待边界各由另一条真实 C++ 线程竞争同一互斥量，两次都不可取得。注入 2990+1990ms 应答延迟产生 4980ms 虚拟时间；失败后 249 次每次4ms pulse不重复等待。8项检查通过。

这是启动/恢复串行等待的确认，不是普通健康运行帧率问题或死锁证据。生产锁/生命周期设计尚未修改。移出共享锁需保留目标身份、旧 Broker 进程与 mailbox 退休等语义，不能仅删除锁或提前关闭句柄。

## 范围澄清

手动进程识别规则保存经 `process_target_selection.h::publish` 同步写整节，成功后才更换策略；失败在对应设置页展示并保留旧策略。因此不能说所有保存入口都异步。尚无实际磁盘延迟测量，也未把它列为已证实缺陷。

其余条目本轮是源码追踪，没有声称已运行所有现有测试。未执行真实 Windows、游戏、GPU、多人联机验证。
