# 平台强制注入条件下的只读代码差异探测

## 问题与本轮证据范围

用户只能提供平台强制注入后的游戏现场，原程序家族为普通 `gamemd-spawn` 与 `gamemdAres`。需要在不取得“未注入运行状态”的条件下定位代码差异、候选 Hook 链和工具箱入口交集，并为后续兼容分析或独立实现功能提供线索。

本轮未获得用户当前 EXE / 平台 DLL 的文件字节或 SHA-256，也没有运行该平台。程序名不作为支持某一精确构建或证明模块来源的依据。本轮交付的是通用探测设施；报告记录现场实际基准 SHA-256、进程身份与模块布局。没有新增平台私有函数 ABI、字段偏移或确定的功能语义结论。

## 基准与比较

默认读取已加载模块所对应的磁盘文件；可额外选择相同构建的原始主程序 EXE。该文件无需启动。PE 文件内容先映射到 RVA 布局，支持的基址重定位按实际加载地址归一化，支持的 IAT / 延迟 IAT / TLS 等加载器写入范围在报告中明确排除，再比较可执行节的有效虚拟范围。

PE 机器类型、时间戳、映像大小、入口与节布局检查用于识别明显不对应的基准，不能证明文件为未修改原版。即使文件哈希稳定，也只能证明报告使用了哪份基准。磁盘上原有的静态平台补丁可能不会出现在磁盘与内存差异里。未知重定位、无效布局、加载期间变化、不可读区域、预算和取消均必须明确降低覆盖范围，不能转换成“未发现 Hook”的结论。

## 读写与生命周期边界

扫描在 Host 后台按需执行，不依赖 GameRuntime 注入成功。界面允许手动指定 PID，Windows 采集绑定实际打开的进程及创建身份。模块列表、页面和字节只读采集；不执行目标代码，不写目标内存，不挂起线程，不附加调试器，不为扫描安装新 Hook。

采集有模块/文件/内存/差异/链长和时间预算，支持取消。扫描结果保留逐模块覆盖信息，模块消失、读取失败和变化现场不得作为可靠相等字节。取消/关闭不在 UI 线程等待扫描结束。输出只保存元数据与有限字节样本，不保存完整游戏文件或全进程转储。

## 解释边界

差异是观测事实；控制转移和功能用途是不同层级的推断。有限字节模式解析提供直接/间接转移候选、目标地址、目标所在模块和有界链，未确认的指令边界仍标为未确认。不能仅凭差异中出现 E9/FF25 就宣称识别了完整函数或确切 Hook。

差异可能包含工具箱自身、合法模组或平台的代码修改。本工具不凭地址交集排除自有补丁或认定写入者；动态代码差异数量不能直接称为“平台 Hook 数量”。

附近导出与 `.syhks00` 等可读取声明用于提供名称线索。声明不等于安装证据，目标地址位于某个模块也不等于证明该模块写入了原代码。工具箱 161 个目录项及相关签名范围的交集只是参考地址映射，不能凭程序名认定该构建的地址语义与参考版一致。

已有 15 项静态适配交集记录继续保留其原有意义：它们来自固定上游写入范围与本项目依赖的静态比较。本次动态报告是用户现场的新证据来源，不把该旧数量当作本次已发现 Hook 数，也不自动改变逐入口签名策略。

本工具不从报告自动卸载、恢复或直接调用第三方 Hook，不声称自动还原平台功能。后续适配需结合实际报告、同版本原始代码与调用上下文验证；独立功能实现还需要对输入、输出与副作用分别取证。

## 源码与验证

- 纯解析/归一化/差异核心：`source/shared/source/platform_hook_probe_core.h`。
- Windows 只读采集与有界分析：`source/shared/source/platform_hook_probe_windows.h`。
- 报告模型与 JSON / HTML：`source/shared/source/platform_hook_probe_report.h`。
- 调试页后台任务与原生/WebView 控件：`source/assist/source/platform_hook_probe_ui.h`、`debug_entries_ui.h` 及控制台前端。
- 同源码受控测试与摘要绑定：`source/research/evidence/platform-hook-detector-release-validation-20261107.json`。

本轮必要受控验证：PE 核心 14 个场景分别通过优化构建和 ASan/UBSan；每轮 2204 次 checks 包含样本构造边界，不把两轮相加为更多场景。采集与报告 24 个生产算法场景通过 ASan/UBSan，并实际解析 JSON / HTML，验证恶意标签仅作为文本输出。UI 生命周期 11 个场景、98 项断言通过，Debug store 16 场景与共用 store 30 场景通过。LeakSanitizer 因容器 `/proc` / ptrace 条件不可用而关闭，没有宣称泄漏检查通过。

实际浏览器启动尝试因缺少 Chromium headless shell 失败，未宣称完成 DOM / 视觉实测。额外的旧 `web_console_contract_test.py` 在未修改的 pre.9 代码上命中既有夹具漂移：夹具要求 2 MiB + 1 字节的消息被拒绝，但生产 `OutgoingLimit` 已为 8 MiB。该项与本轮修改无关，明确未计入通过项，也未借机改变消息协议。

测试的通过项、实际数量及执行环境以该聚合记录和原始收据为准。PE/重定位/范围与读取失败、差异候选、报告转义、UI 状态等受控样本不能证明用户当前平台已完成兼容。Windows 目标交叉编译和静态 PE/ABI 校验也不能推定真实 Windows、游戏或多人会话已执行。

默认限制为 512 个模块、单基准文件 64 MiB、基准读取请求合计 512 MiB、单归一化映像 256 MiB、可执行节比较 256 MiB、含双读与元数据的远程读取请求合计 768 MiB、4096 个差异、256 条链且每链最多 8 跳。差异样本最多 32 字节；声明/导出有全局与逐模块上限，单份报告文件最多 32 MiB。扫描阶段 37 秒，总协作截止 45 秒，为链追踪与结束复验预留时间；这些时间检查不能中断已进入内核的操作系统或文件系统调用，所以 UI 始终不等待扫描工作线程。

## 排除的假设与未决项

1. 不要求存在未注入平台的运行时快照；可靠磁盘基准可用于代码比较。
2. 不以文件名或零差异证明原版身份、所有 Hook 均被发现，或平台完全无冲突。
3. 不把正常加载器变化、未读区域或不同构建的代码整体差异当成平台 Hook。
4. 不从目标模块、最近导出或声明推导作者归属或完整功能语义。
5. 只看映像可执行节并不覆盖任意数据/vtable/IAT 重定向、硬件断点、内核拦截或瞬时修改；报告明确标注范围。
6. 当前用户平台的具体改写点、回调作用和与工具箱的实际交集，仍需用户运行本版后生成的现场报告。
