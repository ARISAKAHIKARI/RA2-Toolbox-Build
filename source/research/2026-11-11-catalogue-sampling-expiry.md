# 1.0.49-fix.2：有效目录依赖提前过期导致周期性缺样本

问题：气泡、数字闪烁的“采样失败”为什么发生，是否就是游戏内存读失败？

## 固定基线与证据范围

对照为本地 fix.1 提交 `351e11c5895751ad0ccff5669eda8b417b899bb1`，等价 GitHub 提交 `721bd236f3e426e145c5c8478e8cfd762e6c76ec`，完整树 `0e5098a517dd0554b39bebe511b4b618ec419c7c`。本轮使用实际 `TacticalSampler`、`ProcessReader`、`CaptureGraph`、共享内存发布和请求租期代码；Win32 和游戏字节由已有 `world_frame_core.cpp` fixture 提供。

这是源码及受控执行证据，没有本次用户实机日志，不能唯一确认现场每一次闪烁/快捷键失效的原因。没有新增原生调用、网络事件或游戏 ABI。沿用的原版 1.001 EXE 身份为 `268a81b7422b3bb855e1b4a162aadba4d807f88fb9f70feb99118211d8fbb8d0`、`c287d62a4d6a25b547e9339d071dd6e03adcf545699062e478aaeee38c60e89a`；没有在这些 EXE 上进行本轮实机验收。

## 已确认的因果链

`TacticalSampler::sample` 对已经完整的类型目录每 500ms 复查；`Client::pruneRequests` 把超过 250ms 未重新请求的页面从下一帧采集列表移除。Base capture 只展开实际存在对象的类型，不能保证所有未出场兵种的目录数组和类型页都包含在内。

因此：目录缓存仍有效 → 页需求先过期 → 下一次目录复查读取缺失页 → `ProcessReader::frameRead` 将整个 `WorldFrameScope` 标为不完整 → Host 放弃候选样本 → 下次发布重新补页。成功数据与错误标签不矛盾：底层内存读取可以全部成功，只是所需页没有进入已封口样本。首次发现一个新依赖的补页延迟正常；已经成功的目录反复失去依赖是不合理的。

类型目录头沿用 `0xA8B218 / 0xA8E348 / 0xA83CE0 / 0xA83C68`；元数据字段沿用 ID `+0x24`、TechLevel `+0x634`、Owners `+0x6CC`、Insignificant `+0x232`、Spawned `+0xD54`、Cameo `+0x6D6`，无新增地址推断。

受控对照在预热后 1,000 个逻辑帧中得到 **44 个不完整样本**，实际内存读取失败为 **0**。修复后相同连续运行得到 **0 个不完整样本**。这些是测试场景计数，不是现场发生率或 FPS 数据。

## 修复

- 记录目录元数据访问的页面集合；消费者继续使用该目录时只续订依赖，不重复解析目录，也不把旧字节冒充新数据。500ms 目录复查频率、250ms 通用页面租期均不变。
- 不完整发现先合并旧依赖，完整目录成功后替换集合；暂停的相机快路径也续订。重置、世界/House 切换或不再使用时停止续订，由原租期释放。
- 暂停恢复测试另发现侧栏 UI 的三个页面也会过期。原路径把侧栏 Cameo 数量和页签 Y 当世界数据：数量 `0x87F7E8 + 0x1544 + tab*3988 + 84`，位置 `0x87F7E8 + 0x1544 + 44`。现改走已有本地 UI 读取域，与相机/选择保持一致；对象、生产对象和目录仍从共享封口样本读取。
- 真正缺失/不可读的目录页仍然使候选不完整；不放宽世界、连接或完整性校验，不给对象读取增加 live RPM 后备，不修改网络与指令提交。

## 验证与剩余边界

`source/assist/tests/catalogue_frame_sampling.py` 驱动实际生产头，`--baseline-ref 351e11c5895751ad0ccff5669eda8b417b899bb1` 为负对照。覆盖持续 1,000 帧、暂停相机快路径和恢复、元数据变更、真正不可读与恢复、reset 后释放依赖。`world_frame_core_test.py` 覆盖 transport/Runtime/ProcessReader 的现有边界。

同页缓存/双缓冲同步仍可因发布与读取交错暂时没有可接受样本；`Client::acquire` 只有两次即时尝试，`accepts` 遇 observation seqlock 写入直接拒绝。这是代码允许的暂时未确认路径，未测得用户现场命中次数，本轮没有凭猜测放宽这些校验。切局、失联、无效对象和分配/映射失败也应拒绝样本。

fix.1 的 120ms 同身份显示保留负责短暂未确认的视觉连续性；本轮修的是可稳定复现的缺页根因。不能把短时保留称为全部采样原因已解决，也不能把本测试等同于解决所有输入 Hook 故障。
