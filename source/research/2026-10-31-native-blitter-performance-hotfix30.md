# Hotfix30：原生尺寸专用内核、完整 A 查表与整帧整数 SIMD

用户授权在 YRpp 调研后继续实现性能改进。第一优先仍是稳定、正确的画面。基于 Hotfix29 已确认恢复可用的框架，累积 step1 的初始化优化，保持单一主绘制者、完整 Surface 回放、完成像素回读和 layered compositor。没有恢复输出行分片、第二个呈现线程或跨 API 共享纹理直出；附加画质选项继续停用。正式 latest 仍为 v1.0.38。

调查前复核研究索引、HF29/step1/YRpp 笔记与同一 SQLite v109。固定参考 `CnCNet/YRpp@d9795546950fcc75a94325ffc83b44d16ec34ce2`，具体源码位置和 blob 见前一篇 YRpp 笔记。本次是本工程实现与可移植 CPU 受控测试，没有新私有游戏反汇编或原生执行。

## 问题与实现

1. 旧原生色盘快速路径只覆盖大图和 A=127。新增 `native_palette_lookup.h`，按行数、亮度、RGB倍率及 scalar/special 状态缓存不可变数学表，完整覆盖 A=0..255；当前 FullColorData 表每次绘制重新绑定并持有共享所有权。分别为 RGB555/565 懒初始化65536项解码表。缓存最多4096项，每渲染线程约18MiB数学表，活跃绘制持有自己的共享引用。没有缓存可变色盘像素或将不同帧的色盘内容混用。
2. `Surface::blit` 在原生1x、indexed、原生Z且无目标位移/混色/阴影时，一次选择有无色盘表、跳过Z/只读Z/读写Z及有无逐像素深度的模板内核。行起点、行Z、A基址不再逐像素决定；透明零alpha连续区间一起推进源/目标。部分透明仍保留原运算。特殊材质、缩放和附件顺序沿用原有回退。这里扫描的是已解码行，**没有实现压缩源 RLE 缓存**，不能将其描述为完整移植 YRpp RLE。
3. 整帧 `nativeBase` 原先逐像素执行3个通道乘除。新增 `native_base_shade.h`，SSE2每批4像素，保持原alpha字节；A=127整组直接跳过。每通道仍精确等于 `min(255, channel*A/127)`。先将u16乘积截到32385，再令 `y=x+1`，用 `(y+(y>>7)+(y>>14))>>7` 精确除127，最后pack；保留无SSE2编译与运行时标量路径。它是相同整数运算的向量化，不是颜色增强或改变舍入。
4. `prepareWorldOnly` 在真实ground快照前不再创建两个后续未使用的 `NativeCanvas::fork()`。fork会共享像素页但复制整个map索引节点；真实packet.ground快照仍保留。此项只作控制流验证，未单独量出其耗时收益。

没有照搬上游可疑的 Plain Alpha/Z 指针与Z写回实现；保持本工程已验证算子。实现过程没有增加游戏入口调用、地址、字段偏移或ABI变化。历史支持样本 SHA-256 `268a81b7422b3bb855e1b4a162aadba4d807f88fb9f70feb99118211d8fbb8d0` 仅用于关联既有原生研究，本次未执行该样本。Assist82/Runtime4/entry3/frame-signal1保持不变。

## 正确性验证

- `native_palette_lookup.cpp`：6029568组精确对照，比较旧 `Palette::apply`；覆盖全部256个A、555/565、源alpha、色盘表/计算回退、发光索引、brightness clamp、行数及LRU淘汰生命周期。测试为本工程新旧行为一致性，非原游戏像素认证。
- `native_base_shade.cpp`：全部65536组channel/A，独立标量预期，原alpha保持、非对齐起点/尾数、neutral/dark，以及SSE2和无SSE2编译回退。
- `native_indexed_blitter.cpp`：同一夹具分别编译旧step1和新头文件，1024配置×8次有序绘制；逐次纳入ARGB/float-Z/u16-Z/A，8192次绘制总摘要相同 `10270135044812603347`。包含全部4类梯度、读/写/skip Z、NaN、等深度、形状/coverage、部分透明、全A、555/565、色盘表、裁剪、分数原生坐标，以及阴影/packed混色/位移/附件/缩放回退。
- `frame_replay_initialization.cpp`：32种回放布局与HF29四平面摘要相同；破坏Surface尺寸后重放也相同。`gpu_scene_record.cpp`：36组有序shadow/attachment/SHP CPU回放及fallback；`render_recovery.cpp`：完成帧保持、相机/配置失效、四种水线缩放、最终Display fence。
- 历史 `camera_native_rows` 固定摘要在HF29和step1已经相同地失败；此轮没有修改其golden或把该项声明为通过。新的回归对照不代替原生游戏验收。

## CPU 回放测量

每变体三轮，轮次交替；每轮暖场3次后取15次draw中位数，再取三轮中位数。A循环0..127，零物件也包含整帧A运算。输入准备、游戏读取、源解码、窗口呈现和GPU均不计入。所有变体/轮次对应场景的四平面摘要一致。完整原始轮次见 `evidence/native-blitter-hotfix30.json`。

| 场景 | HF29 | 仅初始化候选 | Hotfix30 | 相对仅初始化减少 |
| --- | ---: | ---: | ---: | ---: |
| 1280×720 / 0物件 | 7.867ms | 6.047ms | 1.436ms | 76.3% |
| 1280×720 / 160物件 | 13.739ms | 12.002ms | 4.262ms | 64.5% |
| 2560×1440 / 0物件 | 30.119ms | 26.889ms | 7.263ms | 73.0% |
| 2560×1440 / 160物件 | 38.316ms | 34.056ms | 12.505ms | 63.3% |

此前约33ms是另一批受控回放的测量；本批同一初始化候选为34.056ms。应比较本批成对数据，不能拼成实机FPS或承诺所有地图都达到12.5ms。此轮没有分别隔离查表/内核/SIMD每项收益，也没有量两个fork的独立收益。调度与系统负载使单轮波动，原始样本保留。
