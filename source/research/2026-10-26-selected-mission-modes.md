# 32 种任务、任务事件与 Sleep / Guard / Harmless 按键

## 问题、样本和证据边界

问题：除 Sticky 外还有哪些任务？逐项设置会怎样？哪些能用联机事件请求？给所选单位增加 Sleep、Guard、Harmless 三种设置操作。

原版样本 EXE SHA-256：`7b8a068535d6af06845edf95ae829b113d00c02909330e16f197426cd7db94b6`。沿用用户已有捕获的 `.mem/.valid`，不发布 EXE、映射图像或原始反汇编。表中规则来自这个运行样本；MOD 可以覆盖 MissionControl 和对象处理器。

证据是有效捕获字节的反汇编、原版指令受控 x86 执行、编译后 Runtime 的合成世界检查。没有本次 Windows 实机、完整战斗或双机联机通过的证据。特别是“没有反击”和“不会进行任何自动索敌”是两个不同命题，不能仅靠 Retaliate=no 证明后者。

## 通过什么事件设置

Sleep、Guard、Sticky、Harmless 都可由 **MegaMission 事件（事件类型十六进制 04）携带任务编号**：分别为十进制 0、5、6、23。不是四种不同的 EventType。事件同时包含所属方、执行者的原版 TargetClass 身份及任务相关的目标/目的地。

构造器 `0x4C6860` 填写 Event，不负责传播；统一网关联机时送 OutList，单机时送 DoList。接收端解析事件后进入原版任务排队/对象处理路径。`Foot` 的任务预处理 `0x4DF0E0` 对 0、5、23 返回原编号；29 则有特殊转换。调用原版 `QueueMegaMission=0x646E90` 是另一种发送后端，联机时仍追加原版 OutList。

构造器为 x86 `__thiscall`：ECX 指向临时事件，栈上的 10 个参数依次为 `player, actorID, actorTag, mission, targetID, targetTag, destinationID, destinationTag, nearestID, nearestTag`，返回时清理 `0x28` 字节。包内原版字段如下：

| 字段 | 事件内偏移 | 含义 |
|---|---|---|
| EventType | `+00`，1 字节 | 构造器填写 04 |
| House | `+02`，1 字节 | 命令所属方索引，不是任意控制授权 |
| Frame | `+03`，4 字节 | 构造时读取当前帧，投递时再由原版/统一网关调度 |
| Actor | `+07`，5 字节 | 32 位网络 ID 加类型标记 |
| Mission | `+0C`，1 字节 | 任务编号，不是 ForceMission 开关 |
| Target | `+0E`，5 字节 | 攻击/交互目标引用 |
| Destination | `+13`，5 字节 | 移动/进入目的地引用 |
| 辅助引用 nearest | `+18`，5 字节 | 保留第三组引用；用途要按具体消费路径核对 |
| Planning | `+1D`，1 字节 | 构造器置 0；原生规划追加设 1、内部执行设 2，不能当通用强制标记 |

引用不是本机裸指针。项目支持空引用 `(0,0)`、格子标记 `0x0B` 和 Techno 网络身份标记 `0x34`。某辆坦克攻击另一辆坦克是 actor 指向前者、mission=1、target 指向后者；移动为 mission=2 加 destination 格子；装车为 mission=7 加 destination 运输车；Sleep/Guard/Harmless 则三个附加引用均为空。每个事件指定一个执行者，多选由多条事件表达。

因此必须区分：**构造成功 → 入队成功 → 各端消费 → 对象接受并切换 → 行为符合预期**。UI 只报告已入队的单位数量。

任务字段能够携带任务表中的编号，不代表随意对任何对象发送都有效。Enter 需要目的地和对应进入能力；Attack 需要目标；Harvest 需要采矿上下文；建筑和飞机专用任务不能给坦克凭空增加能力。有些原版任务主要由引擎内部设置，不能因枚举里有名字就推断普通玩家输入能自然产生它。

`QueueMission=0x5B35E0` 排入对象 `+B4`；`NextMission=0x5B3570` 推进到当前任务 `+AC`，受对象 readiness 约束。`ForceMission=0x5B2FD0` 是本地任务函数，不是联机事件；当前没有可通用解除普通战车 Sticky 的原版事件组合。

事件类型也不能和任务编号混淆：例如 **Unload 任务=十进制 16**，而 **Sell 事件类型=十六进制 16**，两者完全不同。原版 Idle、Scatter、Sell 等事件有各自对象执行语义，不能视为把同名数字写入任务栏。

## 每个任务设置后意味着什么

“设置”以下均指原版最终接受了任务，且目标、目的地、能力和内部上下文符合前置条件。直接修改 `+AC` 并不等价。空处理器仅说明该任务自身没有在这里推进逻辑，不代表对象其他 AI 全部停止。

| 编号 | 任务 | 设置后的作用、适用对象及限制 |
|---:|---|---|
| 0 | Sleep，休眠 | 样本规则 Zombie=yes、Retaliate=no、Scatter=no。自身处理器只返回 450，未设置自动恢复；适合实验休眠留枪。新任务可替换，完整战斗中是否有其他路径重新索敌仍需实测。 |
| 1 | Attack，攻击 | 四类对象都有专用攻击处理器。按原版武器、射程、弹药、目标有效性继续攻击；无合法目标不等于持续锁定。 |
| 2 | Move，移动 | 载具、步兵、飞机有专用处理器；需要目的地并受寻路/通行限制。建筑的这个任务处理器为空。移动不是“不攻击”保证，样本允许反击和散开。 |
| 3 | QMove，排队移动 | 在任务 AI 中落入默认 Sleep 处理器，不是独立完整移动处理器。真正的路径点队列另有 PlanningToken 等上下文；单发 3 不能承诺排队移动。 |
| 4 | Retreat，撤退 | 地面 Foot 及飞机有撤退处理器，建筑为空。不是瞬移或全局自动撤出战场；撤退目的和后续取决于所属方、地图与原版上下文，不适合作通用驻守。 |
| 5 | Guard，驻守 | 四类对象有普通警戒处理器。恢复正常自主警戒/战斗行为；不是绝对不移动。不同于 G 的 AreaGuard=11。不能承诺解除 Sticky。 |
| 6 | Sticky，粘滞驻守 | 分派到相同的 Guard 虚函数，但规则 Paralyzed=yes，且普通 Unit readiness 对当前 6 直接拒绝推进。仍可按原版警戒/反击路径战斗；常规新任务可积在待执行栏。 |
| 7 | Enter，进入 | 地面 Foot 与飞机有处理器，需要目的地对象及进入资格。可用于装载、进驻、停靠等原生过程；给普通步兵发 Enter 不会增加 C4 或工程师能力。 |
| 8 | Capture，占领/进入目标 | Foot 及建筑有对应处理器。工程师、间谍等具体效果还受类型、目标和关系判断；不能让任意单位变成工程师。 |
| 9 | Eaten，被吞食 | Foot 的特殊交互任务，建筑为空。依赖吞食/相关对象上下文，不是通用的待机或隐身模式。没有完整执行证据，不应任意施加。 |
| 10 | Harvest，采集 | 载具、步兵、建筑各有处理器，飞机为空。依赖矿车/奴隶/资源与归属设施等条件；普通战车不会凭任务编号产生采矿能力。 |
| 11 | AreaGuard，区域警戒 | 四类对象都有处理器，是默认 G 的区域警戒任务。可搜索、接敌并改变位置，适合守区域；不适合要求严格留枪或原地不追击的分配。 |
| 12 | Return，返回 | 此样本四类对象都指向基类空处理器。不能把“发 Return=12”直接解释为通用返航或倒矿；正常倒矿还有 Enter、对接和设施状态。 |
| 13 | Stop，停止 | 此任务处理器为空。实际停止输入可能先清目标/目的地并执行对象级逻辑；仅发送任务 13 不能等同于完整按 S，更不能绕过 Sticky readiness。 |
| 14 | Ambush，伏击 | 此样本四类对象都为空处理器，但规则不等同 Sleep。不能根据名称保证“敌人靠近才醒”或自动伏击；缺少完整行为证据。 |
| 15 | Hunt，猎杀 | 地面单位与飞机有处理器，建筑为空。用于主动寻找/接近敌人，可能依赖 AI/团队上下文；不适合需要留枪、留位的单位。普通玩家对象完整效果待实测。 |
| 16 | Unload，卸载/展开 | 四类对象都有相应处理器。可能卸乘员、展开或执行类型专用交互；不是所有对象都能卸载，也不是安全的通用待机。 |
| 17 | Sabotage，破坏 | 与 Capture 共用任务分派入口，但当前任务编号及规则不同。依赖原生破坏/进入能力和目标上下文，不会凭空赋予 C4。 |
| 18 | Construction，建造中 | 只有建筑有专用处理器，其他三类为空。是建筑生成/建造动画等流程中的任务；任意施加不能免费建造，可能破坏现有流程。 |
| 19 | Selling，变卖中 | 只有建筑有专用处理器。QueueMission 对当前 Selling 直接忽略普通新请求；不能当普通安全待机。仅设该任务不等同合法 Sell 事件，不保证退款或销毁。 |
| 20 | Repair，修理 | 载具和建筑有专用处理器，步兵/飞机为空。需要维修设施、链接或其他原版上下文；不是持续锁血/无限回血开关。 |
| 21 | Rescue，营救 | Foot 共享专用处理器，建筑为空。普通 Unit readiness 对当前 21 同样直接拒绝推进，是值得避开的特殊流程任务；不作为通用姿态开放。 |
| 22 | Missile，导弹流程 | 只有建筑有专用处理器；用于相关建筑/武器内部流程，不会让坦克凭空获得导弹或超级武器。 |
| 23 | Harmless，无害 | 自身处理器只返回 450。样本 NoThreat=yes、Retaliate=no、Scatter=yes；NoThreat 在敌方自动威胁筛选中按候选目标的任务读取。不是无敌，不保证手动攻击免疫，也不适合严格原地不散开。 |
| 24 | Open，开启 | 只有建筑有专用处理器，其他三类为空。建筑开启/交互的类型专用流程，不能把任意对象变成门或开关。 |
| 25 | Patrol，巡逻 | 载具、步兵、飞机有专用处理器，建筑为空。需要巡逻位置/路径上下文，可能主动接敌；单发无目的地任务不能保证形成往返线路。 |
| 26 | ParadropApproach，空投接近 | 只有飞机有专用处理器。用于空投进场过程，要求航线、乘员和任务上下文；地面对象仅为空处理器。 |
| 27 | ParadropOverfly，空投飞越 | 只有飞机有专用处理器。空投经过目标区域的下一阶段；不应独立当普通飞机移动命令。 |
| 28 | Wait，等待 | 自身处理器为空，原生规划过程中会使用。QueueMission 特判当前 Wait 收到 Guard=5 时不排入，不能简单拿它替代可恢复的 Sleep。其他请求不应一概说都被锁住。 |
| 29 | AttackMove，攻击移动 | 事件先经过 `4DF0E0`，有目的地/目标时通常转换为 Move=2 或 Attack=1，并在支持的对象上保存 `+5C4/+5C8/+5CC` 等辅助状态。直接把当前任务写成 29，AI 落入默认 Sleep 处理器，不等于正常攻击移动。 |
| 30 | SpyplaneApproach，侦察机接近 | 只有飞机有专用处理器；侦察飞行进场阶段，需要侦察任务上下文，不是普通战机侦察能力开关。 |
| 31 | SpyplaneOverfly，侦察机飞越 | 只有飞机有专用处理器；侦察飞越阶段，与进场、目的地和后续离场流程配套。 |

## 三种模式对火力分配的意义

- Sleep：候选“留枪”任务，自身空处理器不会因返回值 450 自动醒来。受控执行中，普通空闲对象可经新 Attack/Move/Guard 任务退出；完整战斗触发路径仍待实际测试。不会追回已经发射的弹体。
- Guard：恢复普通自主战斗，可能抢先选敌/开火，适合作为交还原生控制的任务。
- Harmless：样本不反击、允许散开，并改变敌方对它的自动威胁筛选；会同时影响双方战斗选择，不能只当成“留枪但其他行为完全不变”。

手动设置是一次命令，不是永久覆盖。移动、攻击、自动功能后续重新下令及原版特殊流程都可能改变任务；应结合任务回执观察实际切换，不能把“已发送 Sleep”算作“确认单位不会再开火”。

## 实现和验证

版本 `1.0.39-pre.2` 增加三组按钮和可配置快捷键，默认不绑定；支持原有组合键、双击与冲突检查。配置键为 `[Hotkeys] SleepMode / GuardMode / HarmlessMode`。IPC 协议升为 74，新增命令 29/30/31，Shared 布局大小未改变。

显式按钮命令允许工具窗口位于前台，仍保留 simulationReady、对局身份、有效期和聊天检查；自动指针策略原有的游戏前台限制保持不变。

范围为所选己方、存活、可下令的步兵和战车，排除建筑、Aircraft、装载中、超时空作用中、停用及已由 Sticky 占用的对象。使用既有 nativeMission 网关和原版 MegaMission 构造器，单机 DoList、联机 OutList。重复按键仍设置相同任务，不作切换。停止旧自动意图时使用 `cancelNative(p,false)`，避免触发单机本地 ForceMission 解除 Sticky。取消的是旧规划/回执元数据；若随后的提交失败，不承诺恢复旧自动任务。

新证据与测试路径：

- `assist/tests/mission_dispatch_capture.py`：读取 32 项真实分派和四类虚表、MissionControl；执行 28 个基类空处理器，均返回 450 且未写对象；执行 0/5/23/29 的 5 个原版任务预处理分支。
- `assist/tests/selected_mode_runtime.py`：编译后 Runtime 的 100 个场景，覆盖四种会话、三种任务、原版构造器序列化、重复设置、前后命令顺序、工具按钮无游戏前台时提交、选择过滤、队列满/最后一个槽位、过期/聊天/不支持会话及工具 Sticky 隔离。
- `assist/tests/network_state_capture.py`、`sticky_guard_runtime.py`：既有原版排队/readiness 及 Sticky 回归证据，不能据此声称新三种模式的战斗效果或实际联机通过。
- 对应记录见 `verification/review-139-pre2-mission-modes/`；最终 PE32、资源版本、依赖和 Host/Runtime ABI 由 `tools/verify_windows_outputs.py` 检查。

## 关键地址、规则字段及排除的解释

`MissionClass::AI=0x5B3060`，32 项分发表 `0x5B34E8`。Unit/Infantry/Building/Aircraft 虚表分别为 `0x7F5C70 / 0x7EB058 / 0x7E3EBC / 0x7E22A4`。完整处理器清单见验证 JSON；本文不把名字当处理器实证。

MissionControl 数组 `0xA8E3A8`，步长 `0x20`；`+4..+9` 依次为 NoThreat、Zombie、Recruitable、Paralyzed、Retaliate、Scatter。`+0x10/+0x18` 为 Rate/AARate 双精度值。Sleep 虚函数槽 `+0x204`、原版基类处理器 `0x5B2E10`；Harmless `+0x208 / 0x5B2E20`；Guard 和 Sticky 均调用 `+0x21C`，但规则及 readiness 不同。普通 Unit readiness `0x744270` 对当前任务 6/21 直接返回 false。Harmless NoThreat 证据在 `Techno::CanAutoTargetObject=0x6F7CA0` 的 `0x6F7DFF..0x6F7E0B`：读取的是候选目标的任务规则。

排除：450 是持续到期自动转 Guard；NoThreat 是无敌/隐身；Return 数字就是倒矿；Stop 数字等同完整 S 操作；任务 29 的裸字段等同攻击移动；MegaMission 可以强制解除 Sticky；给任意单位特殊任务就能增加该类型的能力。未完成：完整战斗中 Sleep 的所有自动退出来源、Harmless 的所有索敌/受击路径、各种 MOD、真实网络同步及每个特殊任务完整流程。
