# 1.0.46-pre.2：插帧按需缓存、包体积与第二轮性能检查

## 问题与证据边界

用户指出：Update 只有约 3.8 MiB，Full 仍约 41 MiB；插帧应当从游戏原始资源计算并缓存，不必随包分发。同时继续检查关闭硬件断点、计算位置全部选工具箱时的开销。

本轮基线为本地 `e6a157fe4b51e330915eaaa58f8192f5cdbce168`，公开等价源码提交为 `7201e614db0680aa172d906d318ee4600edd3639`。调查对象是工具箱生产源码与已发布包；没有新增游戏可执行文件、函数地址、ABI 或偏移结论，也未读取或发布用户私有游戏转储。游戏二进制 SHA-256：本轮不适用。此前原生接口结论沿用已有研究，不据此增加兼容性声明。

证据目录：[cursor-cache-import-20261108](evidence/cursor-cache-import-20261108/)。控制执行、目标代码生成、实际 ZIP 审计与真实游戏运行须分别理解；本轮没有原生 Windows、真实游戏、物理 GPU 或联机验收。

## Full 的实际组成

按 pre.1 实际 ZIP 中央目录统计，Full 为 43,029,752 字节（41.036369 MiB），Update 为 4,005,682 字节（3.820116 MiB）。Full 内 388 个 `.dis` 的压缩载荷合计 20.573278 MiB；4 份 `preview.html` 为 16.209094 MiB；4 个配套 EXE/DLL 为 3.761765 MiB。剩余部分是基础素材、engine、许可证、说明与 ZIP 开销。

因此继续移除 Python 运行库不会消除这次的主要差值：1.0.45 已经把该运行库改为按需下载，本次剩余大头是生成物。新策略精确排除这 392 个文件，并禁止任意大小写的 timelines、DIS/TL15、preview.html、工作任务和缓存目录进入 Full 或 Update。保留默认图案及三套主题的原图、色盘和少量元数据；七个 engine 文件必须与当前冻结源码逐字节相符。

以旧二进制作估算，轻量 Full 约 4.20 MiB；实际新包体积由冻结构建后的 `release-manifest.json` 记录，不能把估算冒充新包测量结果。覆盖安装检查保留用户配置、已有 runtime、生成结果、预览和用户样式。

## 当前游戏原图与内容缓存

默认图案在读取到当前游戏的有效原始 SHA 和色盘后同步显示并确认来源。非 hide 模式也发起只读原始资源获取，已有 517 帧本地缓存不再阻止重新确认。只有资源提交序列、字节范围、SHA 布局与非透明性均通过后，才允许默认图案的自动生成。450 与 517 帧由现有 Python 引擎支持；其他可显示布局没有据此新增插帧支持声明。

缓存身份取决于规范化原图、色盘及 groups 三项内容。相同内容复用相同目录；只换色盘也会切换身份。键用于定位，落盘时还逐字节校验三个不可变源文件，避免仅依赖摘要碰撞假设。`pairs.txt` 是 groups 的派生索引，不参与不可变身份，否则引擎正常重写索引后下一批就会与自身冲突。派生索引必须完整解析；残缺帧对、溢出整数、越界、自连或坏尾部均拒绝整表，不接纳前缀。

选择自定义主题时，游戏资源采集不会把主题素材替换为默认图案。来源相同的再次确认不重置播放状态；同 epoch 已落盘的源文件不逐批重复校验写入。首次落盘、任务目录和进程创建仍在 Host 路径进行，没有宣称 UI 完全无同步文件操作。

## 按需队列、后台计算与增量接入

绘制只对实际观察到且未驻留的有效动画帧对排队；队列去重且有 512 对上限，自动任务每批最多四对。无动画需求、关闭补帧或默认来源尚未确认时，不自动启动计算和下载。任务通过现有固定来源、长度与 SHA256 校验的依赖准备流程运行；光流保持单线程，工作进程设为低优先级。等待期间显示原帧。

工作任务的 request.json 明确区分 pairs、all、preview。普通自动批次只生成指定帧对，不附带预览；手动预处理可准备全部，手动预览才构建内嵌页面。完整有效的 DIS 被逐段解析到 EOF 并校验端点与摘要后直接复用，不调用光流配置、设置或绘制。坏缓存重建；取消保留已提交段，移除未完成临时文件，不覆盖已有预览。

独立任务目录、既有 profile 锁和源 epoch 防止旧任务混入新来源。取消或失败阻止无休止自动重试；可显式重试。完成只调度后台解码与增量接入，不重新停止 Hook。新加入的段不会要求每批重新解析整个已加载银行。

独立复核发现：`RasterCache` 使用 Frame 地址作键，替换旧时间轴后地址可被新 Frame 复用，导致返回旧像素。确定性同地址对象重建反例复现此事。生产 `acceptPlaybackBank` 现在仅在全量替换或实际覆盖旧段时清理 raster、activeMotion 及提交哨兵；纯新增及容量拒绝保留有效状态。测试直接执行实际函数和真实 playback.h。

## 本轮落地的导入优化

`Snapshot::import` 原先先 `Page{}` 清零，再赋值整个已经初始化的传输页。新增直接复制构造的 PageBuffer append，避免每页 5,128 字节的重复初始化；capture 仍保留原有清零，以正确初始化读失败和未读字节。

使用发布所用 Zig 0.13.0、Windows x64、O2 生成 LLVM IR：基线保留一处完整 Page 清零，当前为零，必要页面复制保留。28/512/4096/8192 页对应每次分别移除 143,584 / 2,625,536 / 21,004,288 / 42,008,576 字节的重复初始化。受控真实 Client 路径的分配次数、发布内容摘要、跨帧持有及同帧去重保持一致。合成耗时受分配器和首触页等影响，小样本也出现变慢；不从这些时间推导均匀 CPU 提升或游戏 FPS。

## 已确认但没有在本版修改的热点

1. ValueTask/Runtime Input 整体复制：即使只有少量有效输入，unload、missile、load 输入结构仍分别约 4.49 MB、1.07 MB、0.84 MB。真实 Host 函数受控执行 500 次仍各有 500 次分配与整结构复制。下一步应使用有所有权约束的空闲缓冲复用与有效前缀，同时保留二维边缘默认值、load 可变输入、序列锁及历史来源。
2. AntiTheft 对同一 sealed 样本重复扫描：1,024 建筑、无合格塔的 100 次调用产生 102,400 次候选检查、1,126,500 次 sealed 读取、零 live 读取。配置改变可在同一个 raw token 下改变结果，去重必须包含完整来源、本方身份和稳定配置序列，不能只看帧号或缓存未完成结果。
3. 导弹分配的重复候选访问：128×128 为 1,056,768 次，256×256 为 8,421,376 次。排序候选与惰性删除可能降低重复工作，但必须保留伤害、威胁、准备度、现目标、距离、ID、平分规则及 pending/reserve 语义。
4. Client 新快照仍有完整所有者和页面分配。固定三个槽且忙时直接丢弃获取不安全，现存消费者可跨多帧持有旧 token；未来复用必须有非阻塞分配后备。同帧一百次获取已经零额外分配。
5. request 订阅修剪可利用最近过期时刻跳过稳定集合的全扫描；必须保留 250 ms 生存期、2 ms 容差与时间回绕语义。本版未更改 transport。

上述条目是已测得的进一步工作，未计入本版收益。本轮发布收据只计实际重跑的 world_import、cursor_ondemand、cursor_precompute_cache、lightweight_package 四组；pre.1 的旧证据保留但不冒充重跑。完整 Windows 目标构建、PE/架构/协议、冻结源码对应关系与包摘要在构建完成后另行记录。
