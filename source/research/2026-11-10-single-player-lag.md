# 单机卡顿修复：寻路清理与心控连线计算

## 问题与结论

用户要求搜集光棱线、心控线、探测线的 GPU 修复与原版寻路性能问题，优先保持原有效果。此次交付两个独立、默认关闭的单机开关：A* 队列清理批量写零；心控连线循环减少重复投影并以整数计算固定抛物线。没有更换 A* 搜索算法，没有降低寻路/索敌频率，没有 GPU 接管原生光束，也未开放联机。

支持核对的私有 EXE SHA256：`268a81b7422b3bb855e1b4a162aadba4d807f88fb9f70feb99118211d8fbb8d0`。仅提交地址、短入口签名和语义范围哈希，不分发 EXE、原生代码转储或游戏素材。

## 原生地址与等价边界

### AStar::Clear

`0x42A5B0..0x42A68D`，thiscall ECX=this、无栈参数。替换入口前 6 字节，完整尾部 216 字节 FNV-1a=`A4AC3F17` 必须一致；调试“跳过校验”不豁免此要求。

- this+0C/10：两种节点池，计数位于池+180000/+100000。
- this+14/68：常规/分层队列。队列+0 为有符号有效计数、+8 为元素指针数组。
- 原版每次循环重新取队列字段，清理 `[0,count]`（含零号位）；count<0 不清元素但仍把计数置零。
- 新适配器使用 `rep stosd`，保留以上范围和两个池的复位；不触碰未使用的队列槽。
- this+28 为搜索编号。普通调用只递增编号；原版并非每次清空整张地图。旧值 FFFFFFFF 时走静态重放的原版入口，由原版清理全图/分层标记后归一到 1。
- 没有节点排序、浮点评分、相同代价决策、路线缓存或帧时序改动。原版队列的异常大计数行为没有另行修复。

### Techno::Draw_A_Link_To

原函数 `0x704E40..0x705262`，两个 Coord（各 12 字节）和 4 字节 RGB 参数，ret 1C。仅替换循环入口 `0x70508A` 的 7 字节，沿用原函数的栈帧、端点矩形和一次 wall-clock 取样，结束回到 `0x705256` 原生尾声。

- 新循环仍产生 32 段；固定高度 `512 - 2*(i-16)^2` 与原生 x87 常量计算对照。
- 坐标加乘先按 x86 uint32 回绕，再进行有符号 /32（向零截断）；不能用算术右移替代负数除法。
- `0x6D2140` 原生投影，this=全局 `0x887324`；保留原生高度计算和视口 Y 偏移。每条曲线总投影次数从 66 变为 35。
- 在裁剪前保存上一端点；`0x7BC2B0` 会修改两端点，不能缓存裁剪后的结果。
- 使用原生 `0x6612C0` RGB 调整、像素格式位移参数和 Temp Surface (`0x88731C`) vtable+30 画线。没有重采样或改变颜色/遮挡路径。
- 原函数两部分、投影函数完整 306 字节以及 0.0625/16/1/512 常量均严格核对哈希。按页边界分块读取，避免中央补丁管理器拒绝跨页读取。非原生投影实现可能有副作用，因此不能跳过校验。
- Tactical 在 `0x6D47BF`、`0x6D47F6` 重复调用控制者 DrawLinks。直接“只画第一次”会改变交叠次序；即使保留最后一次，也需处理每次调用的实时时钟差异。本次没有这种去重。

## 生命周期与接口

`single_player_lag_policy.h`、`single_player_lag_bridge.h`。仍由 GameEntryManager 唯一写入原生补丁；只允许 session 0/5 安装。两个热入口独立检查当前 session，切到联机而维护尚未运行时也立即走原生路径。关闭、停止、只读切换、世界重建和故障清理都会请求恢复，外来代码不被覆盖。临时失焦/界面隐藏不作为删除此性能补丁的理由。

UI 位于显示设置、单机 FPS 下方；9538/9539 独立开关，9540 显示状态及实际加速次数。INI `SinglePlayer/LagFix` 位 0/1，默认 0；冷启动 Runtime 依赖包含两位。Assist105 在协议尾部追加 20 字节字段，Shared 按 8 字节对齐后为 23162632；Host 和 Runtime 必须成对更新。

## 已执行验证与限制

- 完整 Windows 目标交叉编译（Host x64、Runtime/Broker x86），PE、导入、版本、协议和配套依赖静态验证。
- Windows x86/x64 声明：915 项大小、对齐、字段偏移一致；生产设置开关、INI 持久化、掩码、反馈、共享字段与 167 项冷启动依赖检查通过。
- `assist/tests/single_player_lag_runtime.py` 对编译后的 Runtime 入口进行实际安装/卸载并执行原生例程：14 组；39 组 A* 内存比较（负计数、空队列、满队列、随机计数、编号回绕、前后哨兵）；368 组原生绘制参数比较（RGB565/555、正负坐标、视口、时钟和颜色）。
- 原生投影/裁剪/颜色/矩形交集实际执行；仅 Win32、时钟与最终 Surface 提交为夹具。原生/优化版有序绘制参数完全相同。投影 66→35；该夹具总执行指令 5111720→3753404，不可当作 CPU 时间或游戏 FPS。
- 验证原生/补丁切换时显式刷新 Unicorn 翻译缓存，避免缓存旧基本块造成假通过。
- 没有 Windows 实机、截图、完整游戏寻路路线或两端联机验证。旧 `ui_geometry_test.py` 的 Win32/界面桩已落后当前基线，未能编译；没有把它记录为通过。独立的生产设置处理器检查通过。
- 尝试直接运行 32 位原生机器码微基准时，当前 Linux 内核拒绝执行 32 位 ELF；没有发布耗时或 FPS 提升百分比。

## 尚未完成

光棱/普通激光、心灵探测线的 GPU 接管。原版 LaserDraw 普通路径会取随机数，不能直接跳过 Draw_It 再称仿真无影响；需要核对随机数、Z/A、混色及遮挡。现有外部 GPU 场景重绘不能自动减少原版同一遍绘制的成本。临时增加锁屏包装也尚无证据能减少该路径的真实开销，未加入。

寻路清理具有进一步做联机等效验证的条件，但本次只启用单机。Build_Reachable_Subzones 的行为错误、节点缓冲区扩容及完整 GPU 迁移另行处理，不能与此次等价清理混称已完成。
