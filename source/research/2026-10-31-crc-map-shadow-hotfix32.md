# Hotfix32：全图 MapIsClear 原值镜像与功能启用时机

## 问题、样本与证据范围

用户要求将 CRC 原值镜像放入实验功能，随后报告部分功能疑似开局启用会在战网掉线、局中启用又无效。后者没有指定功能名、运行日志或错误类型；不能认定为同一个缺陷，也不能把断开连接直接等同 CRC 不同步。

支持的原生静态样本 SHA-256：`268a81b7422b3bb855e1b4a162aadba4d807f88fb9f70feb99118211d8fbb8d0`。实际发布 Runtime 在 Unicorn 的受控 Win32/世界夹具中执行；不是 Windows 加载、完整游戏、战网或双机认证。私有游戏文件和原始转储不发布。

## 实验功能

高级/实验页新增默认关闭的“全图 CRC 原值镜像”，INI 为 `Experimental/CrcMapIsClearShadow`。Host/Runtime Assist ABI 升为83，Shared为6580496字节；三件程序必须一同更新。Runtime传输4、入口管理3、帧信号1保持原协议。

只在原生 `ComputeGameCRC(0x64DAB0)` 的 `0x64DCCA` 输入叶子替换 House `+0x241 MapIsClear` 的 BL，不重新执行 CRC，不恢复旧的整体 CRC，不额外调用同步 RNG，不改 FrameInfo 或平台校验。先执行原始 BL 读取，禁用、异常或来源不可信时返回真实输入。回调保存 GPR、EFLAGS、完整 x87/SSE 状态和 LastError，受 SEH 边界保护。

| 站点 | 被覆盖指令 / ABI | 用途 |
| --- | --- | --- |
| `64DCCA/6` | `mov bl,[ecx+241h]`，ECX=House | CRC输入，仅替换保存的BL |
| `4F576B/6` | `mov [ebp+241h],bl`，EBP=House | 构造期使旧身份镜像失效 |
| `4FC328/7` | `mov byte ptr [ecx+241h],1` | 自然写入 |
| `577ACA/6` | `mov [ecx+241h],bl` | 自然写入 |
| `577BC7/7` | `mov byte ptr [ecx+241h],0` | 自然写入 |
| `577CA7/7` | 同上 | 自然写入 |
| `577DB0/6` | `mov [ecx+241h],bl` | 原生Reveal；仅明确包围的本工具调用算工具写入 |
| `577F48/7` | `mov byte ptr [ecx+241h],1` | 自然写入 |

所有写入叶子回放真实指令；自然同值写入也更新基线。镜像绑定对局epoch、House指针、UniqueID和索引，并核对Scenario、House数组、当前House、模式和帧方向。未知写入、无法解释的帧倒退、指针复用或错误会停止替换并拒绝继续工具揭示。观察到原生House重建可建立新身份；未观察到重建的读档/倒退不沿用旧镜像。

八处签名全部匹配才安装，部分失败回滚，关闭/断开遵循统一补丁所有权。只有身份仍匹配、真实字段仍等于预期工具值且在游戏线程执行时，才恢复这个字段；恢复未完成时保留连接和既有镜像。已探索的Cell、Visionary `+0x240` 等其他副作用不回滚。

仅允许 LAN/Internet 的“自动地图全开”原生调用路径，必须在本局首次工具揭示前启用。直接全图和已知 Ares/Phobos 扩展拒绝启用；自然触发器/败北写入继续按真实值参与 CRC。未知扩展、间接/批量写入及同值的未知写入仍属覆盖缺口。普通静态样本并不代表战网运行期代码完全相同。

## 功能启用时机复核

`bridge.cpp::tick` 的功能应用在有效House、运行标志、可投递会话、非负有效帧和可见战术视图后进行；加载/暂停时保留请求并延后。`placementTick` 每次可运行Tick按当前请求更新随处建造、地图绘制、控制等补丁，不是只在开局安装。Host修改地图策略时重置自动揭示的对局记录并重新排队，科技模式也有局中显式发送和状态对账路径。因此“局中统一不生效”这一假设不获代码支持。

确有两类不同的锁存：

- `computeApplied` 仅在新对局epoch由 `computeRequested` 取得；这是计算分工锁存，原UI已说明“下一局生效”，不等于普通功能开关锁存。
- 启动 `signatures()` 结果由 `checked/good` 缓存。首次拒绝会停在 `status=-1`，之后即使字节恢复也不会自动重试。先前平台实机笔记已确认这条拒绝路径；本轮没有证据证明用户当前遇到了它，也没有放宽签名检查。

另外，低伤害过滤在联机未打开其联机子项时，只影响工具自动命令；跨玩家操控的部分模式等待事件所属方适配就绪。已安装判断补丁也只影响以后经过该路径的行为，不会自动重建此前生成的对象、任务或探索状态。游戏本身锁步同步要求各端得到相同结果：本机局中修改实际模拟输入可能改变以后路径，直接CRC列表未列出某字段也不代表安全。此处是机制分析，尚非对本次掉线根因的证明。

本版补充Host日志：请求/生效计算分工、建造和控制补丁状态、House适配状态、CRC镜像状态/跟踪/替代/错误次数。地图揭示的镜像未就绪错误有独立提示，避免误报成嘲讽冷却。没有凭时序猜测重写全局生命周期。

## 验证与未决项

- `assist/tests/crc_shadow_model.cpp` 使用实际产品策略，覆盖身份、自然写入及同值、未知写入、重建和回退。
- `assist/tests/crc_shadow_runtime.py`：21项实际DLL/原生叶子验证。执行真实原生CRC及Reveal开头的真实旗标写入，随后跳过Cell/Visionary后半段。原值0/显示值1时CRC与原值对照相同；位移及同步RNG变化仍反映在CRC；六个自然写入和构造叶子保持寄存器/FP。含默认关、单机/模式/过晚启用、读写站点冲突、扩展、未知写入、复用、关闭前空窗、帧倒退和停止恢复。
- `assist/tests/feature_lifecycle_runtime.py`：实际DLL受控比较首次就绪前开启与局中开启、暂停后恢复、计算分工新epoch锁存、启动签名拒绝缓存。不能模拟战网踢出或完整游戏。
- HF31网络分组默认关回归及最终PE/ABI检查随交付附带。正式latest保持v1.0.38，渲染框架沿用HF30。

仍待实测：用户具体功能和模式、掉线界面/双方日志、相同地图配置的开局/局中对照，完整原生揭示对Cell/Visionary/RNG的影响，以及平台附加完整性检查。镜像一个输入已获受控验证，不等于完整全图联机安全；不应以此掩盖真实同步分叉。
