# 原值镜像研究与当前功能的CRC影响分类

用户同意维护“未修改时应有的原值”，并追问工具箱哪些功能会被游戏CRC校验。本轮在Hotfix31后独立研究分支进行；不新增生产CRC Hook，不修改FrameInfo、本机CRC历史或不同步报错，不生成新Hotfix二进制。当前实际交付仍为Hotfix31。

调查前检索INDEX、network-event-audit、shroud-network-audit、trainer-map-cheatcheck、ordinary-desync-triage、Hardened原理和同一SQLite v111。原版CRC已知输入沿用既有证据；本轮新增的是当前PE上的输入替代机制验证、字段候选扫描及原值状态模型。样本SHA256为268a81b7422b3bb855e1b4a162aadba4d807f88fb9f70feb99118211d8fbb8d0，非旧7b8a原EXE/2fcb重建夹具。没有发布私有EXE、raw映像或反汇编转储。

## “游戏CRC”不是给每个功能逐项验算

原版ComputeGameCRC=64DAB0混入：Infantry位置/主朝向；Unit位置/主副朝向；Building位置/主朝向；各House+241 MapIsClear；五个显示层及Logic列表中对象的位置和RTTI（排除特定本地动画）；一次同步Scenario RNG输出。顺序、数量、量化后的数值都会参与。Z、生命、钱、当前任务、目标指针、TechLevel、像素、程序代码并非该函数的逐项直接输入。没有直接读取不代表改动不会间接影响后续状态。

输入按ROL32(H,1)+v混合，是游戏称作CRC的同步摘要，不等于逐字节标准CRC32。结果AC51FC、历史B04474以及FrameInfo的Frame/Delay/CRC协同参与各端比较，不能复用开启功能前的旧CRC。

| 当前功能 | 对原版战局摘要的关系 |
| --- | --- |
| 单位统计、标记、载员/计时气泡、外部小地图/副相机/渲染升级、高刷光标 | 外部读取和最终像素本身不直接入摘要；若另有原生调用副作用，必须单独审查 |
| 黑幕透明/半透明、材质替换 | alpha/SHP像素及已查绘图站点字节不作为直接输入；不能把整个原生绘制链一概认定无间接副作用 |
| 原生全图/自动地图揭示 | 577D90会写MapIsClear，直接影响摘要；同时写Visionary与Cell状态，不能用单字段匹配证明完整安全 |
| 直接全图 | 可见性/雷达/SpySat等补丁可能到达Reveal；当前不能当作纯显示白名单 |
| 自动装车、倒矿、维修、进驻、移动攻击、CS、磁电、飞机分配、队形、躲避等 | 算法本地计算不直接入摘要；原版事件在各端一致执行属于正常战局变化。执行内容/顺序分歧会通过移动、对象出现/死亡或RNG影响摘要 |
| 控制其他玩家、保留House、敌方变卖、整方自毁 | House事件字节不是直接摘要输入；权限验证另算，执行结果/同House排序/接收快取问题可间接造成分歧 |
| 科技解锁、科技加强、任意建造 | 侧栏图标不直接入摘要，TechLevel本身亦未被该函数逐项读；实际生产、建筑出现及类型/规则后继影响仍可能导致分歧 |
| 飞机原生规划、Sticky等任务操作 | 任务字段不是直接输入；本机DoList推进或任务执行若与其他端不同，位置、顺序、RNG等会随后体现 |

上述仅限原版战局摘要。已分析固定CnCNet Hardened v17另有代码区CRC、特定资料及地圖/规则/事件验证；不能说所有平台都有，也不能把它们等同FrameInfo CRC。原值镜像不会自动解决代码完整性扫描、事件拒绝或模拟已分歧的问题。

## 首个候选MapIsClear：新静态证据

固定YRpp d979554的HouseClass声明Visionary和MapIsClear相邻，HouseClass.h blob e578deaf617dfc3a603073b80f14c8aa4b3e993c；CRC.h blob555ffa0b219df8aa072cccc947160c997f39ed34给出CRCEngine bool入口4A1CA0。

对本次PE可执行节进行线性指令候选扫描，包含ESP以外基址（包含EBP）及跨+241字节的宽访问，共24个候选操作数。十个使用精确+241；其中三处读：502FFF（随后传入4A1CA0）、64DCCA（全局摘要）、64E250（CRC诊断区域）。七处明确写：4F576B、4FC328、577ACA、577BC7、577CA7、577DB0、577F48。4F576B以EBP为对象基址，属于初始化候选，不能因为EBP常作栈帧就漏掉。

这不是完整xref证明：某些同偏移属于其他类，宽访问、初始化、载入/还原、地址运算和模块扩展都必须继续核对。没有发现普通读取者不等于已证明仅供显示。尤其完整Reveal还修改Visionary/Cell且存在已知条件RNG路径。因此本轮尚未将MapIsClear加入生产安全白名单。

## 原值模型与原生输入替代验证

测试专用crc_shadow_model.h不被生产代码包含。它以epoch、House指针、ID与索引绑定原值：重复工具改动不把自己的值重新采为原值；真实自然写入即使写出相同显示值也更新原值；真实重新罩幕可更新为0；不明来源/非法值阻断替代；指针重用、换局和帧回退失效。模型依赖调用者准确提供自然写入来源，目前没有接入真实写入Hook。单纯轮询被覆盖后的内存无法发现自然的同值写入。

crc_shadow_inputs_probe.py运行当前PE真实64DAB0和其RNG，独立摘要预期沿用network_state_capture.py；原生日志作为替身。仅在模拟器64DCCA原指令 `mov bl,[ecx+241]` 处替换BL输入，继续64DCD0，不改真实House字段、不重算完整CRC、不改接收比较。

14项通过：原始0、修改1的正反对照；内存保持1而仅摘要输入取原值0；移动、转向、RNG、列表顺序与数量各自仍改变摘要，替代后匹配同场景未改旗标预期；自然原值变为1时摘要同步变为相应合法值。每例在同一原生日志替身条件下只执行一次CRC，RNG索引与基线一致。另通过当前PE13项直接输入矩阵和原值模型边界检查。没有执行完整Reveal、世界tick、自然写入Hook、真实网络或多人游戏。

模型中的同值自然写入是模拟来源事件，不构成对真实自然写入覆盖的证明。logger替身沿用既有模型，RNG调用数只用于相同模型间对照，不能冒充完整游戏日志路径的RNG次数。

给已有network_state_capture.py增加PE输入时，仅在PE模式运行13项CRC矩阵；原capture模式保留原测试流程。旧捕获专用FrameInfo比较端点不适用于当前PE，试跑在那里失败，未把它改成通过或纳入新PE验证结论。

## 当前结论

已证明“只替代已知原生CRC输入、维持正常世界输入与RNG推进”在受控模型中成立，支持用户提出的原值镜像方向。尚未证明MapIsClear或完整全图模式可以安全在真实联机启用，也没有实现自然写入全覆盖。下一步必须先区分工具/自然写入、补齐初始化和载入生命周期以及Cell/可见性副作用，再决定是否加入明确默认关闭的产品实验。
