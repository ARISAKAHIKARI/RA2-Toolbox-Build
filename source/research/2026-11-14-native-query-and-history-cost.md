# pre.4：继续减少游戏线程的查询与来源历史成本

基线为已发布 pre.3：`a2c4ed3e2cf3749706d7a60cd4ead6f486fb7db0`。本轮修改自有调度、缓存及数据交接，没有新增引擎地址、ABI、偏移或可执行样本结论。Shared 布局、协议版本和输入容量不变。

## 改动

- 反向躲弹的继续任务决策接入普通躲弹的 Host/Runtime 选择。历史游标第三格标记生产模式；晚到的旧模式结果不提交。原生移动、实时身份和权限复核保留在游戏线程。
- 同一次非泵消息的躲弹分发建立封存单位所在格索引，使用固定容量散列表和尾链保持原名单顺序，无逐对象分配或排序。来源序号、对局、House、功能配置序列参与绑定；失败或配置写入中不发布缓存。同帧的后续分发重新判断 Runtime Sticky 资格。
- 发令额度耗尽时，已采集的弹体保持未处理和原始截止帧，暂停无效的原生地形查询；活动任务维护仍执行。
- 自动装车的只读合法性查询批次在进入时验证一次现有 Runtime 租约。每一对候选仍调用原来的受保护原生判断，失败立即终止该批；实际提交和重试仍独立验证权限。
- 导弹矩阵按来源行复用控制记录位置、按目标列复用运动记录位置，只复用本次封存观察。执行阶段仍重新查找当前状态。
- 装车与导弹的 FrameHistory 改存执行需要的观察字段。完整输入、composition 和候选矩阵仍交给求解器；执行原本不读取的矩阵不再重复保存。新观察副本按有效计数复制，16 份历史、任务号、ID、令牌和原始时间戳均保留。

## 受控证据

- `reverse_dodge_hotpath.py` 对 pre.3：18 组共同场景摘要相同，64 弹体、512 单位首次名单访问 32768→512；额外验证队列满后恢复且不延长原有八帧期限。
- `dodge_compute_routing.py`：11 组，两个模式与两个计算位置、切换模式、未完成/竞争结果及关闭后的任务维护。
- `tactical_frame_sampling.py`：32 组装车分配同时对照旧版与 pre.3；原生判断次数相同，每批租约校验一次；拒绝没有租约的原生调用。导弹 1024 组 Edge 与 pre.3 逐字节一致，逻辑字段读取 264729→17440。这是封存页内的字段读取数，不是跨进程采样读取数。
- `compute_observation.cpp`：装车观察 843816→53280 字节，导弹 1066008→17432 字节；16+16 份历史共分配 1132032 字节，最大一次 53304，之后 984 次保留没有新分配。各一个源/载具和射手/目标的历史复制合计 208 字节。数值为 Linux x64 夹具结果，Windows x86 结果另存发布流水线。
- `missile_manual_capacity.py`：23 项实际抽取的所有权、容量和执行路径；新增观察生产由显式采样桩完成，未替换被测提交代码。
- 原有输入重置约 199 万检查、8063 个分配器等价场景、封存采样核心与八组请求保留回归继续运行。
- `value_task_input.py --current-only` 验证当前输入复制、worker 所有权、队列、序列锁、污染尾部与非法计数。历史分配性能对照要求优化前基线；当前模式不把 pre.3 当作尚未优化的旧实现。

## 范围

没有降低采样频率或候选上限，没有截断矩阵，也没有把原生虚函数移到不受支持的后台线程。原生查询本体仍同步执行；本轮消除重复查找、重复入口校验和大副本。受控结果及 Windows 构建不替代实际对局逻辑帧测量。
