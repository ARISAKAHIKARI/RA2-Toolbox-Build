# 功能收納、渲染耗時與副相機連續定位

基線為 f05d3e1131843f0d38e0333ab081c9c42ac6f32d。本輪處理功能子設定收納、重複 CPU/讀取工作、副相機中心跳動，以及光標和 DDraw 入口的後續回報。無遊戲規則、指令或顯示品質降級；本輪只讀外部渲染改動不寫遊戲記憶體。Cursor 的原生顯示修復另見[雙槽提示框紀錄](2026-11-02-cursor-hide-tooltip-layout.md)。

## 功能收納與光標介面

原先只有三組摺疊，本輪擴為九組：飛機火力分配及配額、隊形、防空火控、喝彩／嘲諷、組合選兵、高級移動攻擊、礦車卸礦類型、科技許可清單、計算模式。主開關不收起，科技開關／實作模式／狀態也保留。展開按鈕用動態群組查找；搜尋與焦點定位會展開目標，收起時將焦點移到可見的按鈕。原設定 ID、值、快捷鍵及載入語義不變。實際分類、排版、點擊、焦點與搜尋路由隔離測試為 x86/x64 各 2235 項。

刪除「配置 DDraw 高刷」及「恢復 DDraw 配置」兩個入口及點擊路由，回收 52px 版面；未修改使用者 ddraw.ini。隱藏原光標不再標高危，保存的 hide/keep/sha 選擇不再被啟動遷移改成 keep。Cursor 通訊升為 v155，須成套更新宿主、Runtime 和 broker。保留使用者現在選擇的 keep，不擅自將所有 keep 改成 hide。

## 造成額外耗時的實作

- Timeline 先前每次觀測都把上一幀每個 Marker 複製進 map；改為依身份查找所持有陣列的索引，交換前後緩衝區重用容量。相位為零時略過無作用的逐物件處理；同幀成員變更、重複身份及過期相位語義保持。
- VXL body、shadow 及角度改變先前重算相同 HVA 幾何。新增有限 LRU，依不可變幾何身份、獨立 body/turret HVA 幀重用變換及面相容檢查；色盤、光線、VPL、陰影、後座仍按當前輸入計算。記錄的 cache charged-bytes 是快取計費量，不能當成整個程序實際占用。
- 實景小地圖整圖更新的 Cell 指標分散，逐項讀取造成頁快取反覆淘汰。快取 Cell 世代與範圍對應的頁地址計畫，讀取 epoch 仍重新預取資料並驗證每個 Cell。跨頁覆蓋、失讀回退和來源搬移失效保持。第一版每次重建／排序計畫雖減少讀取次數但較慢，已捨棄；正式版重用地址計畫。局部副相機不預取整圖。
- 同一份世界畫面給三個副相機時，先前各複製 Frame、各建排序。改為保留不可變 owner，三個視角共用一次 InstanceOrder；chrono 換 owner、即時可變資料或身份不合時仍走各自路徑，不借用過期排序。

## 副相機為何跳格

副相機已讀取單位 +0x9C 的精細世界座標，並非一開始就只取 Cell 中心。錯誤是後續又以較舊 SceneBank Marker 覆蓋新中心，讓鏡頭停到下一次 bank 發布。

現在僅在本次 watch 的私有 Frame 副本更新經核對目標，camera、body、shadow、depth、clip 和 lighting 使用同一新座標，不改共享 bank 的時間戳或資料。確認原生 vtable、UID、type、owner、目的 Cell、XYZ、橋面與 layer 前後一致；重新取得可見性、材質及姿態，保留 detail 所選的精細角度。載具／駐軍使用已驗證的空間宿主；chrono、偽裝沿用配對舊世界，移動建築等待完整 bank。單一目標失讀僅保留該視角，世界／幀或 chrono 中途改變則拒絕本次更新。

固定 SceneBank，讓原生座標連續八次每次移動 32 世界單位：舊版中心不動，新版每次跟隨，圖像相應改變。另驗證失讀與恢復、Drive 陰影、原地姿態／材質／圖層、fine256 方向、無炮塔、carrier/garrison、UID／Cell 替換、chrono 開始。這是受控反例與修復驗證，尚未代替遊戲現場流暢度驗收。

## 前後對照結果

| 固定測試場景 | 基線 | 本輪 | 範圍 |
| --- | ---: | ---: | --- |
| 4096 actors 的 Timeline 觀測 | 1.742 ms | 0.361 ms | 80 次新觀測平均；3504 語義對照 |
| VXL 96 動態姿態 body+shadow | 68.948 ms | 61.335 ms | x64 CPU，3 輪中位數彙整 |
| VXL 同場景 GPU 輸入準備 | 63.758 ms | 56.407 ms | CPU 準備成本，非 GPU 執行時間 |
| 10000 Cell 整圖 SceneRenderer | 2.048 ms | 1.846 ms | 3 輪均值；實際讀取次數 829→60 |
| 2048 actors 三相機 Pipeline | 24.635 ms | 23.015 ms | 包含新共同排序 0.849 ms；66 組 RGBA/Z/A 相等 |
| 1024 actors 完整 watch 更新 | 2.692 ms | 2.290 ms | 20 次×3 相機，包含新鮮座標額外讀取 |

完整 watch 的 read 入口數為 22239→22668；準備階段 0.542→0.596 ms，相機總段 1.946→1.574 ms，完整成本仍下降。數字來自最終實作，沒有拿較早僅排序優化的結果代替。VXL x86 亦對照通過，兩架構各 90 輸出案例一致，SHP 96 項與 VPL 失敗／競態回歸通過。地形完整 RGBA 相等，覆蓋同幀燈光變更、來源搬移及失讀後恢復。

這些是各固定場景的局部／完整受控 CPU 計時，不能相加為整體提速，也不是遊戲 FPS。小地圖每五秒增加 sampling/render RPM、prefetch pages 和 VXL cache 統計，供後續現場找剩餘瓶頸；沒有逐幀寫檔。

## 構建與限制

完整 x64 宿主、x86 GameRuntime、x86 broker 及診斷版已通過 PE、735 項跨位元通訊 ABI、編譯後 Runtime 與冷啟用檢查。另依使用者選擇合入 [MO 新操作](2026-11-02-mo-controls-scoped-merge.md)，保留本輪渲染與光標修正。最終結果與來源／二進位雜湊見 [render-ui-followup-build.json](evidence/render-ui-followup-build.json)。Cursor 原生完整文字／佈局測試見其獨立紀錄；52 個已登記站點中為 48 個排程、3 個禁用、1 個 Cursor 專用佈局槽，Assist-only 診斷器會明確略過最後一項。

本輪未啟動、停止或注入使用者正在執行的遊戲，未做 RA2OL 雙機同步或實際硬體 GPU 驗收。原始私有 PE 不隨來源或套件發布。持久研究 Library 本次無法使用，已保留本筆記及索引供後續寫回。
