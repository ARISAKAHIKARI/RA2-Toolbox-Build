# 严格无代码写入：策略一致性与真实 Windows 管理器测试

分支：`experiment/no-inline-game-patches-20261027`。
基线：`47346708d6d9d9da897b7cc2d00c35c4a8bfd6db`。

本次保留已经落地的严格管理器、Entry ABI v4、Runtime v5、实际二进制策略导出校验和完整功能标记，不用旧基线覆盖这些更新。

## 补齐项

- Registry 的 `mayApplyPatch()` 也对 Install、Restore、Deny 和其余枚举值全部返回 false。此前产品管理器已经拒绝全部 Patch 请求，但旧辅助函数与旧单元测试仍表示 Restore 允许；现在消除这一不一致。
- Registry 继续保留历史所有权/冲突的纯元数据模型。测试调用其 `commit()` 只是改变测试进程内的记录，不是写入游戏指令，也不授予产品写入许可。
- 新增 `strict_code_write_manager.cpp`，直接包含产品管理器，在合法执行许可下尝试不同目标地址和长度、模拟旧所有权的恢复请求、无效 ABI，以及正常 Inspect/Validate/Leave。961 项检查确认补丁请求被拒、canary 字节不变且执行许可仍可正常清理。
- 新测试在 Windows CI 的普通 C++ 测试组里构建，**不使用 mocks include 路径**，所以运行真实 Windows API。原来的带 mock 测试也保留；两者不是实机游戏测试。
- 自动装车的实际按钮为 `111`，补上可见的“待实测”标记及满载、人工接管、双机验证未完成说明，保留原设置和快捷键。

控制全部、透明/半透明/直接全图以及其他代码补丁功能的等价替代仍未实现。原生事件路线保留不代表已通过真实对局；OutList 观察仍然仅诊断，手动命令自动接管未实现。
