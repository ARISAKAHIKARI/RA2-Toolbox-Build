# 1.0.44：Broker、建造预定与素材选项修复

## 范围与证据边界

本轮响应用户要求：修复 Broker，固定建造预定队列与候选面板交界，置灰光标及显示全图中的 SHA/SHP 替换选项，并交付正式 Release。同时关闭逐功能审查中已受控复现的旧预定跨局问题。

这是 Host 生命周期、UI 坐标和操作准入修复；没有新增游戏地址、ABI、原生事件或引擎逆向结论。Assist 101 / Cursor 155 / Runtime 4 保持不变。前序逐功能审查见 [报告](2026-11-08-feature-point-audit.md)及[清单](2026-11-08-feature-point-audit-checklist.md)。源码审查覆盖不等同于 Windows、实机游戏或多人验收。

## Broker

`runtime_broker_client.h` 将启动、单请求应答、正常退出和异常退休保存为有期限的阶段。Host 的既有轮询推进这些阶段；显式等待 API 均用零超时。3 秒启动、2 秒应答和 1 秒退出仍作为未完成阶段的超时期限。线程被调度回来时先处理已经到达的合法 ACK；没有 ACK 才按原始期限超时，不用每次轮询刷新期限。

单一 mailbox 保存 PID、thread、window、Host intent、Broker generation 和 request sequence。其他目标可以观察完成状态，但不能覆盖仍由原目标持有的请求。取消尚未确认的 Install 时先接住迟到 ACK，再移除其返回的准确 token，完成后才允许释放旧 Control 映射。真实错误可能伴随半安装 Hook，因此异常路径继续退休准确的 CreateProcess 句柄；退出未被证明前不复用 mailbox、不启动替代 helper。

`host_game_input.h` 保留 pending Target 与订阅，在 ACK 前保持 `enabled=0`。已确认退出但还未完成异步 Remove 的旧进程对象不能被相同 PID 的新进程复用。正常 pending 以既有节奏推进，真实失败后保留完整退避间隔。Assist 和 Cursor 将 `ERROR_IO_PENDING` 显示为连接中并短重试，不把它升级为版本错误或长时间失败退避。

这项修复移除的是明确的持锁正超时等待。CreateProcess、TerminateProcess 等系统调用仍是同步 API；没有据此宣称消除所有 Windows 调度延迟或提升整局 FPS。

## 建造预定

原 `Layout::top` 与动态 `headerHeight` 共同决定候选区位置，队列增大时按钮发生位移。新布局把候选区顶部作为独立锚点，仅由视口与缩放决定，队列向上扩展。绘制矩形、笔画和点击命中统一使用相对该锚点取整的 `pointY`，避免分数缩放时一像素偏移；字体高度和圆角等长度继续使用原缩放。

默认几何中队列从 0 增至 5 项，旧交界坐标为 `266,282,306,330,354,378`，修复后均为 `266`。受控检查覆盖 117 组变换和 240,552 个队列/内容状态，修复后交界漂移、固定屏幕点误命中、队列影响行数均为零。实际 `capture/promotion/proc` 代码另验证 `0,1,2,3,4,5,32,128,4,1,0` 队列序列中的固定点点击；异步新画面尚未提交时仍拒绝使用新几何输入。

原结构容量 32、单位预定容量 128、最多五项可见堆叠与原生单位生产窗口 30 均保留。小视口仍按可用空间约束缩放和可见候选行数。

### 旧预定跨局

`serviceCommandQueue` 将消费的原始 Item 传入 `send`。原 PID、match、类型目录 hash 和创建时间保持不变；内层读取后如果 PID、对局、连接、目录或有效期改变，在发布或回排前返回预定失败 `-13`。同局忙时保留原创建时间，不通过反复回排延长旧意图寿命。

原审查六场景中四个旧意图被发布或盖成新 match，修复后六个均拒绝。扩展 18 场景/146 检查覆盖两种预定命令、ready/busy、同局正常对照、目录变化、PID/连接变化与读取期间过期。Host Book 取消仍不能撤回已经发布的原生生产请求；本修复是在发布前阻止旧意图，未声称新增原生撤销能力。

## SHA/SHP 选项

- 光标“透明 SHA”和“安装 SHA”置灰；安装 handler 同时改为无写入的提示，旧排队动作不能改写文件。
- 显示全图旧半透明/透明 SHP 素材策略 5/6 显示为已停用，不能选择；旧存储值仍按关闭处理，策略 0..4 保持原行为。
- 现代 console 的模型传输逐项 `optionEnabled`，DOM 设置 `option.disabled`，发送端和原生 owner-thread 均校验；owner-thread 读取当前 HWND 的 mask，不能靠旧 snapshot 绕过。
- 原生下拉点击禁用项时恢复已有选择，而不是跳到第零项。已有 SHA 显示偏好和现有文件不自动改写；保留用户显式“恢复 SHA”的撤销入口。

本轮受控执行使用 Linux 上的实际生产头文件/提取生产函数与明确的 Win32、GDI、进程或快照替身。Windows 目标交叉编译不是 Windows 执行；没有本轮用户游戏、物理 GPU、DPI 实机或多人联机验收。旧 `auto_settings_ui_test.py` 的缺失 stub 编译失败不计作通过；新路径另有定向执行。独立 Hook Diagnostics 的 pending 兼容改动没有纳入产品包的执行验收。
