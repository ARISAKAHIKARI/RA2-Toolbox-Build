# Hotfix17：最新内存状态、1000 Hz 采样、GPU 回读与有界退出

基线 `594af4b4c24858714f92a70af042365903fe62aa`，合并用户指定分支 `codex/render-cpu-gpu-parity-20261030` 的 `ddf0002f795524fdc80760a0c8ae244746d4d52f`。共同祖先是 `b422be861e705120ea12069630588c54fda72364`。这是生产源码审计、便携式行为/像素夹具与 Windows 交叉编译，没有执行 Vulkan、游戏 EXE 或真实显卡测试。

## 用户截图与延迟含义

截图报告场景 14.2 ms、新帧间隔 15.0 ms、观测 11.6 ms、GPU 准备 2.1 / 等待 1.0 / 回读整理 4.2 ms、地形 4.6 ms、输出 7.5 ms，设备为 RTX 5080。这些是用户提供的读数，不是本环境实测。输出已包含在场景内；新帧是完成间隔，不能与场景耗时累加。

旧“观测”来自 `Timeline::interval()`，是不同游戏逻辑帧的观测时间差，不是每次独立读取的实际间隔。旧 `Timeline::sample()` 还把刚收到的状态向上一观测插值，主动增加一个观测间隔的视觉延迟。世界场景原本已读取内存中的对象/相机/姿态/光照，没有等待原生 DirectDraw 表面或原生 Present。

## 本次修复

- 主视图、副相机、实景小地图使用 `materialmotion::latest()`：立即使用最新内存状态；同一游戏帧号下的新读取也生效，同一份采样可以反复绘制。移除生产路径上的延迟观测插值，不推演未观测单位位置。保留当前可见性、对象身份、地图与配置失效检查。
- 轻量采样固定目标 **1000 Hz / 1 ms**，地形分页、场景绘制和覆盖层呈现保持独立。Windows 采样/绘制 worker 使用可被配置/失效/退出打断的高精度一次性计时器；不排队补跑错过的帧，也不依赖粗粒度条件变量超时达到 1 ms。实际采样间隔、逻辑状态更新间隔分别显示；目标不是实测承诺。
- GPU 回读优先选择 HOST_CACHED 的可映射内存，上传仍优先 coherent；非 coherent 回读继续在 fence 完成后 invalidate。原评分把 coherent、uncached 内存排在 cached、noncoherent 内存前，可能导致慢速 CPU 读取。设备实际提供的类型仍决定结果，界面显示最终选择。依据：[Khronos memory flags](https://docs.vulkan.org/refpages/latest/refpages/source/VkMemoryPropertyFlagBits.html)。
- 三槽输出池只复用没有任何发布者/alias 像素读者持有的 Scene；同尺寸暖帧不重新分配、清零再 memcpy。三槽全部被占用时临时分配，既不等待读者，也不覆盖旧图。GPU 面积输出直接填充调用方可复用向量。
- 同一 presentation 的地形验证/探测/绘制共享逐格光照计算；下次 presentation 必须重采样，地形 bank 提交前最后一次竞态检查仍强制重新计算。
- 主视图 GPU 深度计划按地形 revision 保留带边界的原生 Z 平面。附近拖屏只重建横纵采样轴，不反复复制/上传整张 Z 平面；地形变更、区域越界和 reset 失效。原生深度仍使用精确最近邻，未更改遮挡算法。
- 根据实际相机速度、上一帧绘制耗时和呈现周期，把移动轴预绘边缘从默认 96 扩展到最多 384 个原生像素，保留 16 Mi 像素总限制。相机速度使用高精度毫秒时钟，避免高频轮询被 GetTickCount 的重复值清掉。短暂撕裂读取保留上个完整相机/反馈组最多 32 ms，不续租、不跨世界/配置，并清除旧原生裁孔；正常移动仍直接平移/裁剪不可变预绘图。超出预绘/时限的跳转仍需新场景，未声称任何速度下均不会露原画。
- 确认关闭后，在恢复、join、驱动释放之前启动独立 2 秒退出期限。超时只结束工具箱自身，不终止游戏、不卸载游戏线程仍可能执行的 gate。正常恢复先完成仍正常退出。该期限不在用户尚未接受关闭确认时启动。
- 新配置默认优先硬件 GPU；保留用户已保存的明确关闭设置。GPU 与额外画质/xBRZ 解耦，不因使用 GPU 自动增加画质工作量；设备不可用继续 CPU 回退。没有运行每次启动的 CPU/GPU 竞速基准。

## 合并指定分支的处理

逐项核对该分支相对共同祖先的 14 个文件，保留后续 Hotfix13–16 已有的等效/更完整实现：

| 分支变更 | 最终处理 |
| --- | --- |
| 独立地形 worker、不可变 terrain API | 保留当前三 worker 与 `terrainFrame/useTerrain/seedTerrain` 的职责区分，不重复引入第二套扫描器 |
| 基础 GPU 与额外画质解耦 | 当前 Profile/SceneRenderer 已支持，保留同源主视图/副相机/小地图路径 |
| 额外画质、xBRZ 独立开关 | 保留 `RenderProcessing` 和现有设置依赖；兼容导入 `RenderExtraQuality`，新键优先，不恢复已移除的 DLSS 控件 |
| VPL revision 缓存 | 保留当前 revision + available 双校验、完整姿态/模型/动画键；合入夹具并补齐它的 available 接口 |
| 对象覆盖计数 | 合入 `objectCoverage()` 与界面对象 n/n；不是原生全部特效完整度证明 |
| 快速游戏帧跳变 | 主采样原已按实际时间检查；副相机/小地图读取结束也改用时龄，保留地图身份与帧号不倒退检查；加入 elapsed 参数的兼容 helper |
| 观测插值延迟上限 | 旧 Timeline 上限收紧为 100 ms；生产显示使用 latest，不再等待该缓冲 |
| 编译工作流、研究笔记、对齐夹具 | 合入；当前交付本地编译，提交使用 `[skip ci]`，不触发 Vulkan 测试 |

原分支笔记保留为历史记录，其中当时的 DLSS 与特效状态不覆盖后续版本。作为呈现对照，核对了 [cnc-ddraw 279a057 的 d3d9_render_main](https://github.com/FunkyFr3sh/cnc-ddraw/blob/279a057ee7e1e4d584b56141c014ab01f3c6ee6d/src/render_d3d9.c)：它分开更新主表面纹理与绘制/Present，支持通过 minfps 配置独立重呈现；它不是从单位状态重建世界，不能把两者开销直接等同，也不能据此断言当前有“两倍”端到端延迟。

## 验证与界限

15 项定向 C++ 检查通过，另有设置读写、原子相机提交、显示入口、渲染集成和设置布局 5 项检查。关键结果：345,600 个 GPU 计划的 Z 采样与 CPU 原生深度逐点一致；20 次邻近拖屏共用同一个深度平面（仅 CPU 计划检查，不加载 Vulkan）；基础/精细对象覆盖均 6/6；VPL 不变时 3 个 VXL 下一帧新增栅格次数为 0，VPL 改变后重绘 3 个；渲染阻塞期间采样持续，且无需改变状态/游戏帧号即可重复绘制。退出期限通过 Win32 mock 检查自身进程句柄、2 秒参数、幂等与线程创建失败退路。

Zig 0.13.0 编译 x64 主程序 + x86 Runtime/broker；实际 PE 架构、共享 ABI、版本、导出与 DLL 依赖检查通过。没有执行 Windows loader、真实游戏、真实 GPU、联机或 input-to-photon 测量；不以这些夹具宣称 5080 的 4.2 ms 回读已降至某个数值，也不把 1000 Hz 目标写成已达到。证据见 `evidence/render-hotfix17-final.json`。

本项未增加游戏引擎逆向结论、PE 地址/ABI/字段偏移，未运行私有可执行文件；新增 EXE SHA-256 指交付工具箱，不是被逆向的游戏 EXE。无需新增引擎 notebook 条目。
