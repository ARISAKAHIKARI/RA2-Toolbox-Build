# 1.0.46 修订：输入交接、同样本检测和订阅过期扫描

## 问题与证据范围

用户要求继续优化“不开硬件断点、所有计算放在工具箱，游戏仍会卡”的路径，并明确将本轮改动并入同一个 1.0.46 正式版。功能对照基线为本地 `e5e9abd69cdf2963f7bef3dd8fbc3e12c4537a63`；最初发布的 1.0.46 只改变版本及发布元数据，相关功能代码与该基线相同。

调查前检索了 INDEX、统一世界采样、16 份来源历史、导弹栈临时、前两轮性能记录，以及同一个 `RA2-Reverse-Engineering-Notes.sqlite` 的 version 165。这里研究的是工具箱自己的数据交接，没有新增游戏入口、ABI、字段偏移或可执行样本结论；本条游戏 EXE SHA-256 不适用。没有发布游戏文件或原始转储。

证据位于 [release-146-revision-20261108](evidence/release-146-revision-20261108/)。下面的操作计数、受控线程执行和 Windows 目标代码生成分别列明，均不能换算成真实游戏 FPS。完整产品构建、PE、包体及公开源码/附件验证由最终发布收据另行绑定。

## 大输入复用与有效范围复制

原来每次 Host 接收一个请求都会分配并复制固定容量 Input，即使只有一个源和一个目标也要搬运整块。现在 `ValueTask` 使用独占可移动 lease；一个执行项、一个可替换 pending 项和外部持有者各自拥有输入，仍被持有的缓冲绝不复用。每类任务最多保留三个空闲 Input；池耗尽正常分配后备，不丢请求、不降低采样频率。

池的互斥量只保护空闲指针交换。复制、计算、分配、释放淘汰输入以及等待不在锁内进行。lease 持有独立池状态，任务析构后仍可安全归还外部持有的输入；任务自身先停止并加入 worker，再销毁计算器和池。既有 generation/task/sequence、来源和时效检查保持原位。

新增 `compute_input_copy.h` 先复制计数头并校验本地计数，再复制实际有效范围。负数或越界计数回退原有固定大小的整块复制，不把不可信计数当作 memcpy 长度。相同 helper 接入 Host、Runtime 发布、missile capture、装车 cohort 和 16 槽 `FrameHistory`，共享结构的 ABI 和容量均不改变。

| 输入，每次各一个源和目标 | 原复制字节 | 新复制字节 | 预热后 500 次 Host 提交的大 Input 分配 |
| --- | ---: | ---: | ---: |
| unload | 4,485,140 | 149 | 500 → 0 |
| missile | 1,066,008 | 108 | 500 → 0 |
| load | 843,816 | 6,265 | 500 → 0 |

新旧夹具都执行同一个被阻塞的首项与最新 pending 两项，减少的是交接工作，没有通过少做计算取得结果。实际 unload Runtime 发布还保留一份来源历史，其两次复制由每次 8,970,280 字节降为 298 字节；16 个历史槽、serial 和游标均保留。

unload 复制有效 Source、Target 和 action 矩阵；missile 复制有效 Source、Target、Edge，保留 `close=1` 等非零默认值，原采集 placement-new 初始化不改。load 复制有效士兵、车辆、令牌和兼容矩阵，并保留每辆有效车辆的完整 composition 类型计数行：实际分配器会追加类型并读取旧 count 之后的值，不能只保留旧有效列。可变装车计算只改独占输入。

中等输入与满容量均已比较。满容量时复制量接近或等于整块，不能宣称同样的字节收益。500 次提交仍有 500 个小 Request 分配，worker 的 Result 分配也仍存在；首次默认初始化、后备分配和首次建立 16 个大历史槽的成本也保留。三类空闲池合计最多保留约 18.296 MiB 输入存储，在途或外部持有的输入另计，这是减少反复分配的内存取舍。

专项真实生产入口夹具通过 67 场景、4,406 检查，分别以 UBSan 和 ASan+UBSan 执行；未启用 LeakSanitizer。覆盖零/小/满容量、增长收缩、污染尾部、非法计数、装车追加类型、池耗尽、分配失败、在途/pending 析构和外部 lease 延迟归还。既有 240 帧 planner/worker 回归和整合 tactical-frame 回归通过。

Zig 0.13.0 的 Windows x86/x64、O2、`-fno-builtin` 目标代码生成确认复制函数没有整块 memset，也没有 MiB 级栈临时；x64 的实际 acquire/submit/destructor 路径编译成 COFF 对象。目标 Input 大小与表中一致。这里没有运行 Windows 产物，汇编中的最大显式栈减法也不是完整线程栈测量。

## 同一完整样本中的 AntiTheft 检测复用

防偷塔功能原来会对同一份 sealed 世界样本反复遍历建筑，确认是否有合格防御塔。现在只缓存这个资格检测结果，键包含完整 `worldframe::Key`、本方 House 及稳定的功能配置序列。换来源、换配置、换本方或读取不完整立即失效，不能只用帧号去重。

“没有合格塔”必须完整检查合法建筑名单后才可缓存；“存在合格塔”仍需已检查前缀的读取完整。坏名单和缺页不会缓存成阴性。缓存命中后，真实规划所需的 world 投影及其完整性复核仍执行；后续投影失败或来源/配置变化会走既有回滚，不能发布混合样本。最终游戏命令的 live 身份和权限检查不改变。

相同完整来源预热后再调用 100 次，1,024 个建筑且无合格塔或合格塔在末尾时，候选检查由 102,400 次降为 0，该检测范围内的 sealed 读取由 1,126,500 次降为 0；新旧 live 读取均为 0，实际发布 world 的有效内容摘要相同。这个数字仅指缓存的资格检测边界，不表示整个功能每次都零读取。

实际生产 publisher 和真实 sealed-read 的 41 场景、606 检查及 UBSan 通过；包含全部来源键字段失效、同帧配置变化、House 变化、空/非法/缺页名单、阳性前缀、新样本依赖更新和晚到投影失败。改变有效防御塔来源时会绕过本功能的旧帧抑制，阴性到阴性不无故重算其他功能。

## 按最近过期时刻跳过无效订阅扫描

Client 以前每隔 2 ms 就遍历全部订阅页，检查 250 ms 生存期，即使所有页面都刚被续订。现在保存“最早可能过期”的相对时限；未到时直接跳过全表扫描，到时再检查真实时间戳并重算下次时限。新增订阅不可能比已有时限更早过期，续订只推迟过期，因此不需要为每次更新维护堆或排序表。

2 ms 原有可执行时点、严格 `age > 250` 条件、无符号时钟回绕、原互斥量、发布顺序、修订号和心跳语义都保留。重新打开映射或附着时重置时限，没有改变协议、采样频率或空闲时长。

在 500 Hz、1 秒、持续续订的稳定集合中，全表扫描由 500 次降为 3 次：128 / 4,096 / 8,192 页的访问分别从 64,000 / 2,048,000 / 4,096,000 次降到 384 / 12,288 / 24,576 次，减少 99.4%。交错过期时仍执行确有必要的扫描；不会为了减少计数而延迟清理。

19 场景、8,150 次操作生成的 869,348 字节完整订阅发布轨迹与基线逐字节一致，包括页面顺序、时钟、修订和心跳。UBSan、既有 368 项订阅检查和 74,634 / 75,357 项 core 检查通过。使用实际 Client/Server 配合受控 OS 边界，不是原生 Windows 映射或游戏负载实测。

## 结论与未决项

本轮落地的是三处已复现的重复工作，不把优化归因于硬件断点，也没有削减用户选定功能。拒绝复用仍被 worker 持有的输入、只按 frame 缓存防御资格、把缺页当作空名单、清零整个输入替代复制、忽略装车可扩展行尾，以及到时仍跳过订阅清理。

导弹分配器的重复候选访问、Client 完整快照的所有者/页面池化仍未修改。实际 Windows 游戏 CPU、帧率、视觉与多人同步仍待现场观察；受控数量减少本身不构成这些结果的保证。
