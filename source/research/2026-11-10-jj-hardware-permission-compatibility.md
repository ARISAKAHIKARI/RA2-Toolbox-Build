# JJ 硬件科技：更正现场前提与可选生产许可重查兼容

## 当前现场事实与结论边界

用户更正：其“高危旧版实现”可以生产，但缺总统／校车；科技全开参数拦截与科技加强精确等级两种硬件模式在 JJ 都只能显示图标，实际生产未被允许，同样模式在其他平台可用。以上是用户实测反馈，本轮没有连接用户游戏。旧版的具体子模式没有新的配置证据，不能把所有“旧版”都等同于规则字段写入。

因此撤回前一轮以“非硬件也失败”为前提、优先怀疑共用联机入队／发送链路的排序。此前源码核对的维护频率未变、原生日志不足以证明 OutList 被清空等结论仍成立。该对照支持优先检查平台差异和许可覆盖；并不证明 JJ 清除 DR、拦截 VEH、一定多调用了 CanBuild，或一定有独立规则检查。

## 已确认的产品覆盖范围与兼容候选

冻结基线为本地 `250dffe`（远端等价分支头 `611c16290ebeb4660c94142ee0e16257cb2381d0`）。Full 回调只接受 draw/prune 返回点；Exact 除这两处，只额外接受本工具持有效 token 的 probe。因而同一原生函数从其他来源重新询问相同本方类型，默认不会获得这些权限。这是当前产品有意限定的范围，不是已证明的 JJ 调用轨迹。

1.0.49-pre.3 增加共用、默认关闭的“高危：硬件科技生产许可重查兼容”，INI `[Experimental] TechProductionCompatibility=1`。两个硬件科技模式开启此项后可处理其他来源的原生 CanBuild 查询。默认关闭仍使用原有范围；高危旧版各实现及私有 OutList 三种模式保留。

- Full 仍要求本方、同局、许可表 Type vtable/UID 与全部原生签名匹配。只将本次查询的 buildLimitOnly 从 0 改为 1，原生后续上限继续执行。
- Exact 仍要求本方寄存器/栈、21 类预计算名单、当前 Type 等级、数组来源/槽位、完整签名及已发布权限匹配；只修改原两处比较结果。可选的“按等级 1 比较”保持独立；未启用时不能因兼容项而获得第二槽效果。
- 扩展调用的 includeProduction 必须为规范 0/1，返回位置有效下界与栈整数溢出边界受限。工具自己的 probe 返回点仍需 token，不能借兼容开关绕过。
- 不修改规则或游戏指令，不增设/轮换 DR，不改变 500ms 维护、图标刷新频率、事件构造、取消或传输。原生函数已触发的断点次数不因该选项本身增加，但更多候选会执行既有许可检查，整体开销未测量。
- 两个“额外许可放行”计数只在成功修改非原有来源的查询时增长；不是 Produce 数量或生产完成数。激活日志附带已有硬件状态/命中与额外放行计数，沿用原 cadence，不增加热路径日志、时钟或扫描。

扩展可涉及模拟阶段的查询，单端修改可能影响联机一致性，故为高危、显式开启，默认不影响其他平台的原有行为。关闭立即恢复原范围，游戏可能取消依赖额外许可的在产项目。此候选只覆盖同一原生函数，不能处理平台复制函数、独立读取规则、其他线程或被替换而不可达的原生比较。不能宣称已修复 JJ。

## 既有映像与 ABI 依据

本轮沿用已核验支持 PE SHA-256 `268a81b7422b3bb855e1b4a162aadba4d807f88fb9f70feb99118211d8fbb8d0` 的记录，没有重新读取或发布私人 PE / dump。完整原生链证据见 [原生事件研究](2026-10-26-network-event-audit.md)、[早期科技路径](2026-10-22-tech-131.md)及 [候选/即时校验研究](2026-11-08-hardware-precomputed-tech-and-owned-dispatch.md)。

## 验证

`assist/tests/tech_production_compatibility.py` 提取实际生产 callback/world/signature/identity 函数，与固定基线比较，使用合成内存和调用上下文。复用既有 322 场景，包括 131136 组 flags 对照；新增 21 类型 × 3 断点路径 × 2 include × 3 调用来源及失效边界。

- 固定基线原行为：132826 检查、322 callback 场景通过。
- 相同基线按新增权限契约运行：明确在“额外本方调用获准”断言失败，编译成功，构成负向对照。
- 当前源码：138087 检查、1651 callback 场景通过；覆盖开关关闭/开启/关闭、非本方、不在名单、即时换局/身份/数组/签名失效、无效参数/栈、私有 probe token 及可选比较独立性。UBSan 启用。
- 收尾补充首次初始化边界：即使 probe 返回地址尚未登记，仍按内部 stub 的固定返回位置排除。固定中间提交 `e1b9465` 在新增 cold-probe 断言失败，修正后通过；不会借兼容项省略 token。
- 既有预定准入专项 74 例通过（原生调用边界为替身）。
- x86 Windows 目标独立编译得到 Assist107、Shared=23162680 字节；完整配套构建/PE 静态检查另见交付收据。

没有执行 JJ、Windows #DB/VEH 或真实联机；受控调用位置是合成输入，不能用测试中的地址声称已识别 JJ 的检查入口。总统/校车在当前源中已经属于增强名单且有工具目录例外，旧版缺项的实际 Type/阵营/工厂/刷新原因仍未确认，本候选不宣称解决。
