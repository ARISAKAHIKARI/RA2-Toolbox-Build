# 優先不改寫遊戲程式碼：功能遷移與高危清單

日期：2026-11-01（UTC+8）。修改基線：1523de0b7ad1d6d23d922a6410c159b364fc60e9。
使用者要求所有功能盡量不改寫遊戲程式碼，無法等價替代者保留並標「高危」。這是新的整體實現要求，取代上一輪普通幀通知啟用策略；切屏生命週期、科技獨立開關與陰影發布修正保留。

## 參照與結論

已讀取歷史分支 [experiment/no-inline-game-patches-20261027](https://github.com/ARISAKAHIKARI/RA2-Toolbox-Build/tree/87c8b05805619e4add9bee33bb2fda6704b7d23e) 的設計、只讀 OutList 觀察、完整 UI 清單與嚴格管理器結果。該分支用拒絕所有 Patch 保證不寫程式碼，但若干功能只是不可用；其 OutList 輪詢只供診斷，不能重建已消耗事件或保證手動命令的事後接管。因此本輪採取可用的事件／取樣途徑，沒有把診斷候選計數假冒等價任務仲裁，沒有合入一律禁止補丁的管理器。

對照 [v0.7.20 源碼](https://github.com/ARISAKAHIKARI/RA2-Toolbox-Build/tree/50f59d03fda6c37ce2c35927565cabb372d8e94e/source)：其管理器 applyPatch 一律 PatchDenied；WH_GETMESSAGE 和 WH_CALLWNDPROCRET 載入 Runtime／調度，再呼叫原生構造器，聯機寫 OutList。普通功能能生效，不需要各自的 inline detour。command_gateway.h、mega_queue_backend.h、object_event_backend.h、vanilla_constructor_catalog.h 與本輪前基線內容相同；event_delivery.h 僅 inline 改 constexpr。整個 bridge 與全部功能演算法並不相同，不能將這些檔案一致外推成全部行為一致。

「Windows 訊息 Hook」「遊戲映像的指令／虛表補丁」「正常呼叫原生函式」必須分清。原生事件仍寫佇列資料；不改程式碼不保證無資料副作用或 RA2OL 穩定。本輪沒有證明 RA2OL 的完整性檢測是 OOS 根因。

## 設定遷移與交付

舊版默認保存的 NativeMegaGateway／BuildTimeTooltip 首次使用本版關閉；新的 Compatibility.NoCodeWriteDefaultsVersion 記錄遷移，之後使用者明確開啟的高危選項正常保存。光標舊預設隱藏模式也遷移為保留原光標，之後可在標高危的選項中重新選取。其他原有明確高危選項保留，不把已有高危配置聲稱為零補丁模式。

請退出遊戲和舊工具箱後成套替換 EXE／DLL／broker，再開新程序；新版本不能接管另一份舊 DLL 的補丁所有權。更新包不含私有遊戲 EXE、dump 或完整素材。
