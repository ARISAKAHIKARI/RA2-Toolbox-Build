# 切出游戏后控制台无响应：撤掉截图／DWM 控件承载

用户在 Hotfix3 实机反馈：切出游戏后具体按钮和滚动条仍无法操作，大分区可切换。Hotfix3 的空闲抓图调度没有解决此问题，不能称为已修好。

此次不再让内容控件依赖 DWM cloak/uncloak、前台进程检测和静态截图。`frontend_panes.h` 撤去 DWM 设备调用与同步 WM_PRINT，主窗口不再绘制看起来可以点击的页面截图。内容页保留独立线程的真实 popup HWND，无跨线程 parent/owner，使用原生输入。可见性仅由主窗口可见／最小化、选中页面、真实移动和关闭状态决定；前台属于其他应用时只禁止提升 Z 顺序，不关闭已经显示的设置页。隐藏页不会在外部应用上方新弹出。

原代码在失焦时撤下全部真实控件，并留下页面截图，这是能从代码确认的状态转换；没有用户现场线程栈，不能断言每次卡死只由它造成。新方案移除此状态转换。拖动主窗口时只发异步隐藏请求，主窗口不等待工作线程；松手显示真实控件。相比旧方案，内容工作线程忙时不能保证旧位置的 popup 立即消失，优先保障输入和主窗口无同步等待。

额外处理被中断的移动：WM_CANCELMODE、WM_ACTIVATEAPP 失焦和定时器核对 GUI_INMOVESIZE，避免漏掉 WM_EXITSIZEMOVE 后永久停在移动模式。HWND 已销毁时继续拒绝旧消息。保留 pending/processing/executing 的最新状态合并，旧 DPI 工作完成前复核最新布局，避免切页后旧页晚到。

`frontend_visibility_test.py` 直接执行生产方法，10,000 次外部应用／主窗口／内容页前台切换、最小化／关闭约束、丢失结束移动事件和 GUI 查询失败通过。`frontend_panes_windows.cpp` 改为原生窗口的 WindowFromPoint 实际命中测试，12 次前台往返后通过 SendInput 点击按钮和系统滚动条，并保留 10,000→1 忙线程布局合并。该测试需要交互式 Windows 桌面；本地交叉编译不等于已执行，更不等于用户游戏环境确认。

本次没有新增游戏偏移、Hook、注入调用或私有游戏反汇编结论。此前 DLL 退出等待等修正保留。基地车展开／收起、独立采样和 GPU 直出仍是后续工作，不计入本修复包完成范围。
