# 1.0.52-pre.19 预定、装车与躲弹恢复

以集成分支 `00bc3ad4` 为基线。其中 `1d293546` 已把 Host 读页的租约版本与 Runtime 严格索引分开，本次保留该修正。

用户提供的 pre.18 单机日志里，Ctrl+F 已进入 Host 指令队列。一个 5 秒窗口有 309 次候选索引接收、0 次严格索引接收，Runtime 也没有报告异常。建筑预定遇到等待索引直至过期的 `-7`。日志另有单位预定的事件受理记录，缺少原生工厂的后续证据。日志足以确认这两条路径能吃掉用户操作，无法确定每一个原生 Produce 最终被接受、拒绝或取消。

- Ctrl+F 保存原始选区和手动命令版本。异步计算、缺页和容量等待属于独立装车任务，公共命令回执在任务受理后提交。另一次按键可替换尚未分配的选区，已经送出的单位依照各自的任务与版本继续。单机的候选样本可用于分配，到实际 Enter 仍需要当前身份、权限和容量证明。沿用协同进驻的共享座位核验，候选直提限于可完整核验的小规模名单。
- 两种躲弹在单机可由上一份封口样本发现威胁。正向再检查存活、归属、手动命令版本和当前威胁，倒车还检查弹体 UID、目标格与可通行性。候选缺失时保留活动状态。联机沿用严格索引和原生提交。
- 单位预定把事件已受理与原生工厂已接收分开。预定后续消费来自封口的 Resources 样本，按相同型号核对在制品和原生排队项。重复 ACK、变成在制品的原有同型号、其他型号及缺页都不会误出队。队首迟迟未确认时保留并暂停后续提交，支持主动移除，避免猜测并重发。建筑原任务与当前合法性继续核验，资源页和候选 UID 就绪时，单机可提交这类已指定对象的请求。

改动沿用已知 FactoryClass 和动态向量布局，未重新反汇编游戏映像。

主要回归入口为 [战术采样](../assist/tests/tactical_frame_sampling.py)、[躲弹路由](../assist/tests/dodge_compute_routing.py)、[倒车躲弹热点](../assist/tests/reverse_dodge_hotpath.py)、[预定队列](../assist/tests/construction_host_test.py) 和 [原生预定准入](../assist/tests/construction_batch_runtime_test.py)。替身测试与配套 Windows 构建不代表实际单机或联机对局。
