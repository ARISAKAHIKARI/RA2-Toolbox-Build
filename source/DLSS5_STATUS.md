# 64 位工具箱与 DLSS 5 实验路径

## 组件与安装

- `RA2Toolbox.exe`：64 位外部界面、读取、计算和场景渲染。
- `GameRuntime.dll`：原有 32 位游戏内 Runtime，协议保持 Assist 80、Runtime 4。
- `GameRuntimeHost32.exe`：32 位辅助进程，只负责安装和卸载原有两类消息 Hook。控制器 PID、命令邮箱与调度仍属于工具箱。
- `RA2NeuralRenderer.exe`：独立的可选 64 位神经渲染进程，调用 NVIDIA NGX Neural Rendering。主工具箱不加载 NVIDIA SDK。

更新时关闭游戏和工具箱，一起替换包中的上述组件，保留现有 INI。默认 x86 构建仍可单独使用，不把 64 位 DLL 注入 32 位游戏。

DLSS 运行库未放进默认更新包。将 `Install-DLSS5Runtime.ps1` 放在工具箱 EXE 同目录后执行，安装固定版本的官方运行库；源码中的脚本和离线安装说明位于 `neural_renderer/`。安装程序检查下载包、成员 SHA-256、x64 架构及 NVIDIA 签名，不更改游戏或 INI；原文件被占用或安装失败时保留原安装。

## 启用与状态

在战场信息中的渲染设置启用：

1. 渲染升级。
2. Vulkan GPU 场景与小地图，场景精细度选择“精细”。
3. DLSS 5 神经渲染（64 位 · 实验）。

DLSS 默认关闭、沿用自动保存，键为 `Assist.ini` 的 `[Display] RenderDLSS5`。它不会自动更改 Vulkan 开关。状态行只在实际完成神经渲染后显示已处理；缺少组件、设备或输入不满足、初始化失败、超时均保留普通画面，并显示原因。第一次启用需要加载模型。32 位主程序保留该设置，但不会执行神经处理。

## 当前处理范围

NGX 接收完成的世界画面、逐像素运动、反向正交深度及保护遮罩。文字、血条、指令线、交互面板和高刷光标仍在随后叠加。透明和被保护像素保留原始颜色；全保护画面直接跳过，不视为设备故障。

运动来自当前与前次实际渲染的相机、独立游戏对象及绘制位置。相同姿态的平移可以连续追踪；无法可靠对应的动画、姿态、遮挡、地图或场景变化会重置历史。只在实际神经处理成功后推进其消费序号，跳过或失败不会把两条历史误接在一起。取消令牌绑定到 UI 提交的请求，关闭后旧任务不能重新启动后端。

首版通过共享帧向独立进程传递颜色及引导数据，神经进程上传为 Vulkan 图像并回读结果；最终仍使用现有 Win32 呈现。存在额外传输和推理开销，不保证提高 FPS。小地图继续沿用自身 GPU 面积缩小和迷雾路径，没有额外运行此神经模型。原生游戏绘制保持开启。

## 构建与验证边界

`build-zig-x64.sh` 使用 Zig 0.13.0 构建 x64 主程序、x86 Runtime 和 x86 辅助程序；默认 `build-zig.sh` 仍构建 x86。独立神经进程使用 `neural_renderer/build-msvc.cmd`、MSVC x64 和单独取得的 NVIDIA SDK；获取工具为 `tools/fetch_neural_sdk.py`，SDK 不进入源码归档。

`verify_crossbit_abi.py` 使用真实 Windows x86/x64 编译器目标检查协议、尺寸、对齐及字段偏移。PE 验证显式区分组件架构。跨位数 Hook、神经进程协议、失败回退和像素保护有受控 Windows 夹具；引导图另有软件 Vulkan 像素对照。这些验证不能证明 NVIDIA 硬件推理效果、真实游戏画质、联机稳定性或 FPS。

NVIDIA SDK 与运行库受随附许可证约束；神经进程的说明与许可证位于 `neural_renderer/NOTICE.txt` 及 `neural_renderer/licenses/`。本实验集成不代表 NVIDIA 的赞助或背书。
