# 1.0.23：修复联机飞机路径记录被 Z 规划状态拒绝

## 已复现的错误

1.0.22 把联机飞机路径切换为普通 Move 事件，但 `pointerTick()` 仍对所有非取消输入统一检查 `DisplayClass::PlanningMode`（`0x87F7E8 + 0x11B3`）。使用 Z 进入规划模式时，飞机路径记录请求也被这条检查返回 -4。宿主 `airway::capture()` 对负回执直接返回，没有显示失败。

因此，即便原生路径开关已经显示“联机兼容”，路径仍可能一个点都没有记录。上一版测试覆盖了宿主选择事件后端和直接提交 AirPathMove，但没有把原生规划状态置为 true 后执行实际 Runtime 点击记录。这是本轮确认并补齐的测试缺口，不是飞机原生补丁重新启用。

## 修正

- 仅 `AirWaypoint` 记录操作允许在原生规划状态中通过；该操作仍验证对局、归属、对象身份、时效、鼠标位置及飞机状态，并等待原始点击后一逻辑帧。
- 其他增强下令继续受原生规划模式限制。没有清除 PlanningMode、修改原版任务或新增补丁、Hook、DLL、执行入口。
- 按住 Z 时宿主只记录；松开 Z 后经统一命令队列和 GameRuntime 提交普通 Move，观察到抵达后才续发下一点。收到事件回执不视为已经抵达。
- 记录请求失败会显示原因并写入日志；记录成功写入飞机数量、目标格和对局标识，便于区分未捕获、未接收及后续未执行。

依据：[YRpp DisplayClass](https://github.com/Phobos-developers/YRpp/blob/master/DisplayClass.h) 的 PlanningMode 字段，并核对当前源码读取位置。

## 当前仍允许的游戏代码修改

| 功能 | 位置数 | 范围 |
|---|---:|---|
| 绘制未揭示区域 | 2 | 黑幕/迷雾绘制入口 |
| 科技全开 | 2 | 侧栏绘制、重检的 CanBuild 调用点 |
| 任意建造 | 1 | 建造邻接检查入口 |
| C4 测试 | 1 | 步兵 C4 能力标志读取指令 |
| 飞机原生路径点 | 2 | 仅单机；联机继续使用普通移动事件 |

这些位置统一经 GameEntryManager 写入，并非无条件全部安装。跨玩家控制的五处选择补丁权限已在 1.0.21 移除，旧帧/任务/CS/事件等补丁继续禁止。

常规装车、维修、倒矿等主要提交原生命令，Tab 和可选原生点击屏蔽走现有 Windows 消息入口，不覆盖游戏函数。旧地图全开直接调用揭图函数；选择、侧栏刷新等也有本地状态操作。故“不覆盖原版函数”不能推出“绝不会不同步”。正确的事件、执行时机、状态归属与平台兼容性仍需分别验证。

本版只修复飞机路径输入阻断，未修改上述前三项功能；用户报告的战网断线根因仍未证实。

## 验证范围

- 使用 1.0.22 实际 DLL，在战网 EXE 的两种联机会话、两种路径开关、左右点击共 8 个场景复现 -4。
- 使用本版实际 DLL，在两份用户提供的 EXE 上各执行同样 8 个场景：规划模式开启时记录成功、无即时事件、原生规划标志和飞机对象保持不变；用回执中的 token 提交 Move 后只增加 OutList；普通增强操作仍被规划状态拒绝。联机无飞机代码补丁。
- 编译执行实际宿主路径代码，验证两点顺序、Z 按住等待、松开执行、抵达后续发、最新 token、失败提示、攻击/停止/换局取消及单机原生模式。
- 两份 EXE 分别回归统一入口，并验证宿主鼠标分发、PE/ABI、源码边界。

世界对象、鼠标命中、Windows API 和部分原生查询为测试夹具；宿主抵达位置由测试设置，没有运行真实飞机物理、完整游戏循环、平台扩展 DLL 或双机联机。不能把这些结果当作实机飞行成功或战网断线修复证明。文件版本 1.0.23.0，Assist 协议仍为 52。
