# 1.0.13 Beta 修复与验证

本轮范围为跨局图标、建筑预定、额外索敌距离、修饰键和卸载后续行动。继承 1.0.12 碉堡/维修厂/船厂修复，没有新增注入 DLL 或 Hook。

## 图标

此前两个消费者各用一个 IconCache，预定读不到统计学到的图标；缓存身份还包含 DLL/EXE 内容，平台重建插件或工具更新可能导致同一资源集缓存失配。初始异步扫描未完成时 remember 会直接失败，未显示的已加载图标也不会预热。

现在两个模块使用同一个 EXE 内的缓存实例、工作线程和写者，以及 cache/icons。身份保留游戏路径和资源文件指纹，排除无关的可执行文件内容变化。重复 open 幂等，初始扫描期间学习的数据先存内存再合并写盘，类型 ID/图标名按不区分大小写匹配。统计重建对局对象时保留图标；每轮采样优先显示项，再预热已在游戏内加载的其他图标，解码预算仍为四个。旧两目录按可验证指纹合并，不盲目跨 MOD 导入。

没有实现从未加载过的 SHP 的完整资源解包；此类图标首次出现仍可能等待游戏加载。复用期间原生成功解码的数据会刷新统计缓存。

## 预定

- 五项每张高 48 游戏像素、偏移 24，后加入项绘制在上层，编号显示在未被覆盖的上半部；所有坐标继续经过现有游戏/客户端分辨率和用户缩放变换。
- 右键叠放区域弹出最后加入的一项，Shift 右键清空本类别。原生侧栏使用现有外部输入管理器观察按下/释放，验证代次、坐标、大小、序号及有效时间后取消对应类型的最新预定。
- 不拦截原生右键动作，原版暂停/取消仍执行。仅撤销外部未提交任务；已提交头项保留等待原版生产确认，清空其余项，避免声称撤回已经发出的事件。
- 已接受的新工厂产品先于旧建筑指针进行识别，避免旧建筑出售/对象复用导致误清队列。
- 最后一项进入生产后，面板跟随当前产品保留，不再因补充图标列表为空而隐藏。
- Book 记录首次观察到“已放置且工厂空闲”的实际游戏帧。只在游戏帧严格推进后才允许 ProduceReserved；时间流逝、失败读帧、暂停都不会满足此条件。新父项/取消/换局均重置门槛。命令继续通过统一队列和 Runtime 原版生产校验。

## 高级移动攻击

NativeOrders.TargetRangeExtraCells 默认 2，UI 可设置 0–30。外部网格候选范围、候选合法性、当前目标合法性与 Runtime 最终复核同时使用它。不会写武器 Range。≤2% 伤害比例过滤保持不变；磁电/防偷逻辑原有范围不改变。

Shared 增加范围字段，Assist 协议提升至 47，映射前缀同步变更，禁止混用旧 EXE/DLL。

## 按住键

Windows HOTKEY_CLASS 把 Ctrl/Shift/Alt 当作组合前缀，不会保存单独修饰键。现有现代 UI 子类增加按住键模式，保存修饰键的单独按下/释放结果，并发送正常设置变更通知。组合键交给原控件，空键、程序加载、失焦和销毁均处理。高级移动/磁电的按住键不再注册没有实际行为的全局热键，由现有鼠标输入管理器读取按住状态。

## 智能卸载

工程师/间谍/C4 合法性改为 YRpp 对象虚函数 MouseOverObject，通过已有 GuardedEnterAction 边界，避免固定实现入口绕过 MOD 覆盖。工程师接受原版 Capture 与多工程师 Damage 动作，按原版任务 Capture 构造；仍需原版允许，不修改 Capturable、规则或任务内存。

出舱时残留 Enter 且目标刚清空可短暂继续跟踪，但不在该过渡态发后续命令。正常 Move/排队 Move 等待完成；Sticky 驻守允许进入后续处理。专职单位的合法性重试窗口从完成出舱开始，而不是从落地开始计算。工程师的候选包含非己方、非盟友的原版可占领建筑（含中立科技建筑），再按距离/对象 ID 排序。停止指令、手工接管、关闭功能等原有取消条件保留。

## 验证和局限

结果见 verification/review-113 和 REVIEW_VERIFICATION.json。主机回归执行实际生产实现；Runtime 回归执行实际生成的 x86 DLL 和参考 EXE 的事件构造器，但游戏状态、窗口 API、原版合法性结果按夹具提供。控件测试使用 Win32 控件行为模型，不是 Windows 实机绘制验证。未进行真实网络对战、LBW 或实际寻路/占领/侧栏刷新验收。历史报告只代表对应版本。
