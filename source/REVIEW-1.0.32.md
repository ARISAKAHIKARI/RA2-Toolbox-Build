# 1.0.32：恢复跨玩家手动事件，继续隔离切换玩家

界面/标签/包名 1.0.32，Windows 文件版本 1.0.32.0；Assist 60、Runtime 4、入口管理器 3。共享布局未变，EXE/DLL 成套更新。

用户要求打开现有可走联机路径的功能，并再次报告切换玩家崩溃。本版恢复手动操控其他玩家单位及出售其他玩家建筑；单独的 SwitchAvailable=false 使切换控件禁用，Runtime 在修改玩家上下文前拒绝请求。普通自动化仍按原所属方限制。

两个开关各自保存；首次迁移没有 PlayerCommandOptionsVersion 时按用户要求默认开启，迁移后标记为 1，此后尊重各自保存值。禁用的切换控件不能清空另外两个设置。

手动单位选择使用 Alt+左键，Shift 可追加；Alt+右键下达 Move/Attack。出售模式按增强出售键点击其他玩家建筑，以建筑实际所属方提交原版 Sell。仍走 submitConstructed / authorizePlayerOrder / enqueue；没有直接调用本地事件执行器，也没有切换 CurrentPlayer 或写对象 Owner。

恢复五个选择层 CALL 白名单，由现有统一入口管理器安装/恢复；不改共用 House 判定或原版事件接收器。组内外部补丁冲突会回滚已装站点并保留外部字节。具体地址、样本和研究范围见研究索引。

最终 DLL 的两个游戏样本各 45 项受控检查通过，总计 90 项；覆盖恢复后的提交开关、所属方事件、选择 CALL、关闭恢复/冲突回滚、拒绝切换以及保留的科技功能回归。设置 UI、补丁策略、架构和 Windows PE/ABI/版本检查也通过。见 [验证摘要](verification/review-132/summary.json)。

这些测试执行了原版事件构造器及最终 DLL，世界和部分 Win32/游戏接口由夹具提供；没有完成 Windows 实机、网络传输或两个客户端同步执行验证。入队成立不等于平台执行成功，不宣称已修好联机无效或证明不掉线。
