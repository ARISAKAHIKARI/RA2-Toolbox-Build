# 原生“追加进路径”研究记录

用户报告的顺序是：先给谭雅下达针对建筑的任务，再把普通步兵追加到该规划路径。工程师、间谍组合还可能使普通步兵走到建筑位置。这里记录实际证据，区分“复制了任务”和“最终执行成功”。

## 已确认范围

YRpp 将相关事件命名为 PlanConnect 和 PlanCommit。参考程序的 PlanConnect 接收路径寻找既有规划节点，复制节点中原执行者的任务，替换为追加单位；任务种类和目标引用保留。追加/复制阶段没有重新检查普通步兵的 C4、工程师或间谍属性。

PlanCommit 后，游戏自身把节点任务放入内部待执行事件列表，并保留规划标记。该派生步骤并非由工具再向 OutList 私自补写一条事件。由此可知，直接下达任务与“接入已有规划”不是同一条流程。

## 夹具测试

`assist/tests/planning_connect_probe.py` 在未安装工具补丁的参考 EXE 上执行原始事件构造、连接、复制、提交和下一任务分派机器码。对象登记、内存分配、坐标和移动状态使用合成世界；初始任务由测试预置，尚未捕获真实谭雅/工程师/间谍点击得到的完整载荷。

三个候选任务分别保留其原任务种类和建筑目标，并分派给普通步兵；过程中未写引擎代码或该步兵的类型能力字段。结果在 `verification/review-111/planning-connect.json`。

参考文件为用户提供的 CnCNet gamemd-spawn.exe，SHA256：
`c287d62a4d6a25b547e9339d071dd6e03adcf545699062e478aaeee38c60e89a`。
它不等于已验证所有原版 EXE 或 LBW 平台。

## 仍未确认、未交付为功能

- 实际 UI 操作生成的初始任务载荷是否与当前候选一致。
- 全部寻路、到达建筑格、动画及任务结算后，是否发生爆破、占领或潜入；这些效果不能由“任务已入队”推断。
- 最终执行链中仍存在能力检查；目前不能宣称追加路径一定绕过所有检查。
- 没有真实双机联机验证，也没有据此新增快捷键或改变运行中的 C4 Beta。

1.0.10 的 C4 Beta 使用独立的实验性判断修改，仍不能称为复现了这个原生路径行为。后续若接入已验证的原生事件，应扩展 GameRuntime 统一构造/提交接口，保持功能代码不私自 Hook 或写 OutList。
