# 原版 Scatter：方向、选格与重复调用

核对日期：2026-10-21；工具行为基线：v1.0.30-pre.8。

本次完成原版函数执行验证和实现差异分析，未替换当前工具的躲避实现，也未发布新构建。两份用户提供的游戏样本分别通过 78 个受控案例；测试不包含实机炸弹命中率、完整寻路或双机联机。游戏文件、原始反汇编和私有输入不随源码分发。

## 飞机位置的作用

原版飞机的开火路径在开火调用后，对目标所在格执行 `ScatterContent(飞机位置, true, false, false)`。格子的散开资格判断与各对象的 `Scatter` 分开进行；不能简单等同为“只检查被瞄准单位是否三星”。公开交叉参考：

- [Phobos Aircraft Hooks](https://github.com/Phobos-developers/Phobos/blob/develop/src/Ext/Aircraft/Hooks.cpp)
- [YRpp CellClass](https://github.com/Phobos-developers/YRpp/blob/phobos-dev/CellClass.h)
- [YRpp EventClass](https://github.com/Phobos-developers/YRpp/blob/phobos-dev/EventClass.h)

传入非默认坐标会进入按来源选方向的分支。核心方向使用双方的 X、Y 相对位置，先指向远离来源的一侧。它不是用飞机速度、弹体速度和预计落地时间求最佳避弹路线。Z 不参与这段方向计算，但参与“是否默认坐标”的比较；来源与单位 X/Y 完全重合等边界不应解释为有明确的“远离”方向。

普通 `EventClass::Scatter` 的有效载荷只有单位引用，不包含来源位置。其执行器向对象传入默认坐标。载具由此进入 `NearByLocation` 分支，步兵也有默认坐标的另外处理。仅仅调用同名 `Scatter` 并不意味着走了飞机开火时的同一分支。

## 已执行验证的选择过程

| 行为 | 地面载具 | 普通步兵 |
|---|---|---|
| 初始基准方向 | 远离来源的八方向近似 | 相同 |
| 初始随机偏移 | -1、0、+1 个方向，即约 -45°、0°、+45° | -2 至 +2 个方向，即约 -90° 至 +90° |
| 首选不合适时 | 按方向索引递增，依次检查邻接格，最多八个 | 相同 |
| 目的地范围 | 由当前格加一个八邻接格偏移 | 相同 |
| 当前正在车体转向 | 原函数直接返回 | 没有载具的这一组拒绝条件 |
| 已有目的地，且 `ignoreDestination=false` | 原函数直接返回 | 没有载具的这一组拒绝条件 |

候选格先经过地图可用性和对象 `CanEnterCell` 查询。函数保留第一个可通行格作为后备，同时执行额外的地形/坐标转换与格标志检查来选优先格；找不到优先格时可退回那个后备格。不能把它简化成“首个可通行格永远立即返回”。受阻后转一圈的结果也可能朝向来源，因此它不是全局最优逃逸方向算法。

找到了方向分支的目的地后，原函数排入 Move 任务并设置目的地。没有本工具的“已发出一轮，等待观察到移动并稳定两帧；未观察到则等待 300 帧”的状态机。

载具还有 `CanScatter`、任务的 Scatter/Paralyzed 属性、部署状态、locomotor 等检查。步兵另有自身动作序列、部署、locomotor 和任务条件；不能把整套载具前置条件直接套给步兵。表格描述的是本次指定参数下核对的差异，不表示步兵在任何状态都能散开。

## 当前工具的差异与下一步接入要求

1. **时机有差异。** 原版在开火调用链里处理；工具先观测新弹体，再把普通事件放入队列。识别、采样和同步队列都会产生额外延迟。移植方向算法本身不能消除这些延迟。
2. **方向有差异。** 当前发送的普通 Scatter 事件不携带来源，因此不是上述方向分支。不能再声称现版已完全复现三星散开。
3. **外层限制过宽。** 当前 `dodgeBusy` 将载具的车体转向、目的地和排队移动规则统一用于步兵；`active` 又把整个躲避过程作为下一次触发的禁止条件。原版没有同样的整轮锁。
4. **可按原版实现选格，但同步执行必须单独解决。** 可在工具自己的计算侧保留来源坐标，按原版的分类、方向偏移、候选顺序和可进入查询选出格子，再通过正常同步指令提交。不能只在本机直接调用会改任务、目的地和场景随机数状态的 Scatter 来冒充同步实现。
5. **普通 Move 并不自动重跑 Scatter 的前置判断。** 如果选择“本机选格、同步 Move”，排队期间状态可能已改变，重复的 Move 会覆盖目的地。所需的是明确的待执行指令去重/终结判断，加上载具与步兵各自的实时条件；不是盲目保留原有 300 帧整轮锁，也不是将所有保护一键删除。严格一致的开火时刻和执行时前置判断，需要同步参与方共同支持同一入口；不能承诺单端普通事件做到逐帧相同。

接入验收应比较首次触发帧、实际执行帧、来源坐标、候选/最终目的地和单位的转向/目的地状态。先分别用载具和步兵验证，再测连续投弹、阻塞和联机队列。测试前不将“采用同一方向规则”写成“效果与三星完全一致”。

## 可复现验证

脚本：`assist/tests/native_scatter_selection_runtime.py`。传入合法取得的游戏 EXE 和当前 GameRuntime DLL；不需要运行完整游戏。

```sh
python3 source/assist/tests/native_scatter_selection_runtime.py /path/to/game.exe source/GameRuntime.dll --output /tmp/scatter-selection.json
```

实际执行游戏中的车/步兵 Scatter、角度查表、方向换算、邻接遍历和前置分支，并执行原版八方向表的初始化函数。测试替身控制随机返回值、地图/可进入性查询、locomotor 和最终任务/目的地写入；没有用自写方向函数替代原函数后再自证。

每份样本覆盖：载具八方向 × 三种偏移、步兵八方向 × 五种偏移；两类各自的顺序绕障、全部阻塞、后备格、格标志偏好、默认坐标分支、转向和已有目的地检查，共 78 项。
