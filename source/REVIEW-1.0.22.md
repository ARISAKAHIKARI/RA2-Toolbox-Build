# 1.0.22：战网 / 兰博玩差异核对与联机路径点调整

## 已确认与尚未确认

用户提供的 `gamemd-spawn(3).exe` 属于战网，`gamemd-spawn(4).exe` 属于兰博玩。本版验证记录保存两者 SHA-256，未将游戏 EXE 放入仓库或发布附件。

此前 `reference-game/gamemd-spawn.exe` 与样本（4）逐字节相同。历史报告中对这份参考文件使用的 CnCNet 名称不足以证明覆盖战网；历史测试不能当作样本（3）的验证结果。本版分别运行两份输入文件。

两份程序的所查事件构造器、CanBuild、飞机移动、规划节点函数和点击坐标转换窗口一致。帧计数附近、部分事件执行分支和导入表存在差异；兰博玩还导入 extensions.dll。这些静态差异不能单独证明断线原因，平台启动后加载的 DLL 和动态修改仍未实测。

旧日志没有报告入口争用、补丁冲突、构造失败或 DLL 捕获异常。它也没有提供断线当时的双方同步状态；因此不能据此认定“入口错了”，也不能排除未捕获的异常或联机不同步。

## 飞机路径点

原实现使用两个补丁：`0x7E2908` 的 AircraftType 虚函数槽，及 `0x416AB6` 的到达处理。这两处在两份样本中相同。后者调用 `0x6385C0` 的 TryNextPlanningTokenNode；反汇编可见该函数先调用任务虚函数（参数 28），再建立后续规划事件。它并非纯粹的前端事件构造。旧回调又以本机当前玩家、菜单、心跳决定是否执行，存在同步状态单边改变风险。

本版在联机 Session 3 / 4 中不安装上述两处补丁；已安装的补丁按原管理器规则恢复。保留用户开关，自动采用已有的外部 Z 路径计划：读取到达位置，向统一命令队列提交普通移动事件，由 GameRuntime 验证身份、代次和时效后追加 OutList。没有新 DLL、输入 Hook、帧 Hook、独立事件队列或任务字段写入。单机 Session 0 / 5 保留原生路径。

联机兼容操作为按住 Z 设置路径、松开 Z 后逐段执行；攻击命令结束路径设置。界面状态显示“已启用（联机兼容）”。这是具体风险修正，尚不能断言已解决用户所有“刚进局就断线”的情况。

## 矿车手动暂停恢复

旧 ManualVersions 的 `expectOreMission()` 只有测试调用，运行时取消路径没有接线。结果是矿车被暂停后即使原生采矿继续，也可能一直被自动倒矿跳过。

本版普通右键释放也经过现有输入邮箱观察，Auto CS 关闭时仍然有效。矿区点击或可停靠的己方矿场点击可交还自动倒矿；Ctrl / Alt 强制命令不交还。普通移动须先观察 Move，再观察新的 Harvest；旧的 Return / Guard / Harvest 循环不能提前解除暂停。只有取消信号的路径，观察到实际非采矿任务后再等待 Harvest。对象点击不会被重新解释成高级进驻，也不额外发送命令。

采矿判定使用只读字段：CellClass OverlayTypeIndex +0x44、OverlayTypeClass Tiberium +0x2A9，以及矿车类型已有 Dock 列表。参考 [YRpp CellClass](https://github.com/Phobos-developers/YRpp/blob/master/CellClass.h) 和 [OverlayTypeClass](https://github.com/Phobos-developers/YRpp/blob/master/OverlayTypeClass.h)。

## 诊断和验证界限

每次只读连接记录 PE 时间戳、映像大小和关键入口字节；进入新对局时再记录一次，并列出已加载模块的名称和基址（最多 64 个，不记录完整路径）。版本提示只是与用户样本元数据相符的线索，不作为允许修改的依据；补丁仍需逐处原字节校验。不读取或修改平台校验机制。

新对局前 10 秒将常规健康日志间隔从 5 秒缩短至 1 秒。新增 `installedCodePatches` 表示实际安装的代码补丁数，`nativeAirMode=2` 表示联机事件路径；旧 `nativeHook` / `clickHook` 字段只表示接口可用，不能据此判断安装了输入拦截或内联补丁。日志均在宿主写入，不给游戏 DLL 增加文件写入或调度入口。

## 战术助手共同启动路径审查

用户补充“不打开战术助手就不掉线，多项功能都会掉线”，故审查范围扩大到 Runtime 启动、接口发现、类型扫描、自动任务扫描、输入邮箱及浮点状态保存。当前没有找到可证明所有断线同源的新缺陷，不能将飞机路径点认定为唯一原因。

在两份 EXE 上各执行 72 个无输入启动场景：Session 3 / 4，关闭全部标志、逐个 32 位功能标志、日志中的两组标志及全标志；观察帧 0、1、2、60 的游戏映像和预建对象写入、原生函数执行、事件队列及 x87/SSE 状态。新版两组日志配置均未写游戏对象、执行原生游戏函数或提交事件；全矩阵只出现显式任意建造开关对应的既有补丁写入，浮点状态保持。另以 1.0.21 DLL 对战网样本运行 6 个基线场景，日志配置在启动时写入两处飞机补丁。

这项测试使用健康、空闲的合成世界，直接发布 Runtime 标志，不覆盖宿主主动发起的科技解锁等命令，也不代表所有功能的自动任务、真实 DllMain/Windows 加载器、平台 DLL、动态重写或多人同步都经过执行。帧号为受控采样点，未运行完整游戏逐帧模拟。它证明的是所测启动路径的写入范围，不是战网断线已修复。

两份 EXE 分别加载实际编译的 GameRuntime.dll，执行原构造器和统一入口回归；新增测试覆盖四种 Session、联机无飞机补丁、普通移动事件及飞机对象不被本地改写、实际矿车取消/恢复链路。世界对象、Windows API、鼠标命中和部分原生查询为测试夹具。未运行平台客户端及其扩展 DLL，未完成真实双机联机、断线复现或截图验收。历史报告保留各自版本身份。
