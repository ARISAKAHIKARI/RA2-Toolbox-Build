# RA2 Hook 逐組測試版

這是獨立的 `RA2HookTest.exe`，用來定位「安裝哪一組 Hook 後開始同步錯誤」。它不載入工具箱舊設定，也不包含實景小地圖介面。基於 `3613e3336609286b7340943c68785b215ae10f78`，首次遠端幀同步門檻已依使用者要求撤回；保留精確簽名、站點所有權及還原檢查。

## 使用

1. 解壓到新的、可寫入的資料夾，保持 `RA2HookTest.exe`、`GameRuntime.dll`、`GameRuntimeHost32.exe` 在同一層。測試 DLL 與正常工具箱分開；啟動時核對配套 SHA-256。
2. 關閉舊工具箱及遊戲，由 RA2OL 啟動新對局，進入可操作狀態後啟動測試器，確認 PID。若遊戲以管理員執行，測試器使用相同權限。
3. **預設不測前兩個基線**，直接從功能組開始。下拉選單選開始組；「繼續測後面的組」預設勾選，取消則只測所選組。需重查基線時才勾選「本輪也測兩個基線」，每輪只加一次。
4. 右側點選的項目表示「略過」，可多選並保存至同目錄 `hook-test.ini`。**預設略過已出過 OOS 的幀完成通知 55DE81**。凡共用被略過位置的組，也一起略過，不會藉由依賴再裝回。要明確複測某組，可取消其略過選擇。
5. Hook 實際安裝並核對成功後開始觀察。**可隨時點「正常，下一組」提前結束，無須等滿 30 秒**；日誌記錄實際觀察毫秒數。30 秒只是提醒，不回答不會自動前進。未完整安裝不能記為正常。
6. 點「略過本組」會記為略過，先還原，再測後面的組；不記為通過。還在安裝或有未完成功能請求時，先記住排除選擇，等待完成後再略過，或停止並重開對局。右側清單在下次開始時生效；本輪改用「略過本組」。
7. **切出遊戲保留已安裝 Hook，暫停觀察計時**；切回後重新核對位置與新快照再繼續。遊戲暫停亦不計入觀察時間。點正常／略過後，如遊戲背景執行暫停了清理，切回即可繼續等待，不因切屏超時計為還原失敗。
8. 每組不累加。正常／略過後，必須核對全部 51 個位置恢復測前位元組、登記數歸零，才安裝下一組。明確停止、關閉測試器、進程結束或真正異常仍執行清理。相機組沿用原有幾何條件。
9. **同步錯誤後不能在同一個已失同步對局繼續。** 點「略過本組」可把可疑組記住並選好下一組；等待清理、重開遊戲和對局，再查找遊戲、點開始。還原程式碼不能倒轉已發生的遊戲事件。
10. 日誌保存在 `logs/hook-test-日期-時間-PID.log`；分享時提供平台版本、組名、對局模式及實際操作。日誌含模組本機路徑，可遮去使用者名稱。

使用者的 `4e2e516` 日誌在兩個基線正常後，幀通知組開始觀察約 0.84 秒出現原生 OOS；正常聯機產品已改走消息輪詢。這不證明平台偵測 Hook，見[幀通知分析](../research/2026-11-01-cursor-tooltip-frame-oos.md)。另一份 `3613e33` 日誌在 Runtime 基線停於通用「Hook 集合／回調狀態改變」，沒有原生 OOS 記錄；本版區分位置位元組、快照、登記和可執行狀態，並容許短暫快照繁忙與切回恢復，見[切屏與測試流程](../research/2026-11-01-hook-test-focus-selection.md)。

## 如何解讀結果

* 第一個基線就同步錯誤：當時尚未載入測試 Runtime，可先排查原始遊戲／平台／其他工具。
* 第二個基線同步錯誤：可疑範圍縮到 DLL 載入、Windows 訊息 Hook、Runtime 執行及平台對它們的反應；仍不能只憑時間先後宣稱平台偵測了 Hook。
* 某一組開始出錯：記錄當組及之前的觀察，完整重啟遊戲後單獨複測。平台掃描、自然事件及模擬結果可能延遲，不能保證最後安裝的位置就是唯一原因。
* 未能安裝：可能是本地遊戲尚未就緒、平台已修改同位置、簽名不符或功能條件未成立。日誌會保存測前／安裝後位元組和目標模組，**不覆蓋平台現有補丁**。
* 正常只表示實際觀察窗口未發現問題（提前確認可能不足 30 秒）；未操作相關功能時，也沒有測到其完整事件路徑。還原程式位元組不能倒轉已發生的遊戲事件。

CRC 組僅測八個適配入口的安裝，不呼叫全圖 Reveal、不刻意改 Cell／Visionary；不能據此認證完整全圖功能。直接地圖顯示安排最後。測試器不自動下單、生產、移動或發送遊戲事件。

日誌會記錄模組名稱／路徑、非系統模組檔案 SHA-256、51 個站點的測前／安裝／判定／停止位元組、跳轉目標所屬模組、Hook 數、狀態及使用者判定。這些資訊可比較 RA2OL 與其他平台；它不是掃描器偵測器，也不規避平台檢查。

## 編譯與驗證

先用 Zig 0.13.0 完整編譯**同一份 checkout** 的 x64 工具箱（`source/build-zig-x64.sh`），再執行：

```powershell
python source/tools/build_hook_diagnostics.py --zig C:/toolchain/zig.exe --base-build artifacts/build --output artifacts/hook-test
python source/tools/verify_hook_diagnostics.py --root artifacts/hook-test
```

建置器重用同份基礎建置中未變的 x86 Runtime／Entry／SEH 物件及 broker，以 `RA2_HOOK_DIAGNOSTICS` 重編 Assist bridge。此巨集只為相機入口增加獨立測試開關，正常產品編譯不帶它；原有幾何／簽名／所有權限制不變。Assist83、Runtime4、Entry3 ABI 不變，獨立相機通道為 24 bytes、版本 1、PID＋owner＋兩秒心跳驗證。

Windows 下建置器會實際執行隱藏 UI 的略過清單、基線預設關閉、停止後選下一組與無效 PID 拒絕測試，及 x64 → x86 broker → DLL 載入／協議握手測試，均不連接遊戲。`tests/sequence.cpp` 測試提前正常、手動略過、可選基線、共用站點排除、切屏暫停／快照重試、OOS／還原失敗不前進與清單覆蓋；`tests/camera_gate.cpp` 測試相機開關身分／時效。PE 檢查分別驗證架構、匯入、匯出、manifest 及協議。

**目前完成本機 Windows 編譯及上述檢查，沒有完成 RA2OL 雙機或實際遊戲 Hook 測試，正式工具箱已加入不完整陰影批次拒絕發布的修正；仍未做現場視覺驗證。**

本輪另在獨立 Win32 fixture 驗證高刷光標與原生提示相容修正、幀 adapter ABI 和聯機輪詢政策；這不是新版 RA2OL 雙機驗證。測試器沒有高刷光標介面，高刷懸停名稱／價格須用配套正常工具箱複測。
