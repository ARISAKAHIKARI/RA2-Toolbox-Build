# RA2 Hook 逐組測試版

這是獨立的 `RA2HookTest.exe`，用來定位「安裝哪一組 Hook 後開始同步錯誤」。它不載入工具箱舊設定，也不包含實景小地圖介面。基於 `2214328080900dd2c177c3082b7538b4035fe1da`，首次遠端幀同步門檻已依使用者要求撤回；保留精確簽名、站點所有權及還原檢查。

## 使用

1. 解壓到新的、可寫入的資料夾；保留 `RA2HookTest.exe`、`GameRuntime.dll`、`GameRuntimeHost32.exe` 在同一層。不要覆蓋正式工具箱；這個 DLL 專供測試器使用，測試器會核對兩個配套檔案的 SHA-256。
2. 關閉原工具箱，**完全退出遊戲，再由 RA2OL 正常啟動新對局**。只重啟工具箱不能移除遊戲進程中已載入的舊 DLL。
3. 進入可以操作的對局後啟動 `RA2HookTest.exe`，核對遊戲 PID，選「全部：按順序逐組測試」，點「開始」。若無法開啟遊戲進程且遊戲以管理員執行，請以相同權限執行測試器。
4. 每組實際安裝並核對成功後觀察 **30 秒**。遊戲暫停／幀停止時倒計時也暫停。到時會提示音、工作列閃爍及顯示詢問；返回測試器選「正常，下一組」或「同步錯誤，停止」。**沒有回答不會安裝下一組**；中途已出錯也可立即回報。
5. 選正常後先撤回該組，核對全部 51 個位置與測前位元組一致、登記數歸零，再進下一組。看到「未能完整安裝」只能選略過或停止，不能算通過。相機組只有符合原有小地圖幾何條件時才會安裝。
6. 同步錯誤、對局身分改變、進程退出、讀取失敗或 Hook 集合異常會停止新增 Hook。停止／關閉時等待 Runtime 確認清理；若提示還原未完成，退出遊戲後再關閉測試器。
7. 保留同目錄 `logs/hook-test-日期-時間-PID.log`。請一併記錄 RA2OL 版本、當時這一組的名字、對局模式，以及是否操作了相關功能。日誌包含模組本機路徑，可在分享前遮去使用者名稱。

若找到可疑組，完整重啟遊戲後，可在下拉選單只選該組複測；仍會先測兩個基線。

2026-11-01 收到的 `4e2e516` 日誌在兩個基線正常後，第三組 `55DE81` 幀完成通知安裝約一秒出現 OOS。正常產品已讓聯機改走消息輪詢；本測試器保留**明確診斷用**幀 Hook，選「全部」仍會測它。要繼續排查後續位置，可重啟遊戲後直接選「建造時間提示」或其他單組。這份日誌不能證明平台偵測 Hook，詳見[分析及限制](../research/2026-11-01-cursor-tooltip-frame-oos.md)。

## 如何解讀結果

* 第一個基線就同步錯誤：當時尚未載入測試 Runtime，可先排查原始遊戲／平台／其他工具。
* 第二個基線同步錯誤：可疑範圍縮到 DLL 載入、Windows 訊息 Hook、Runtime 執行及平台對它們的反應；仍不能只憑時間先後宣稱平台偵測了 Hook。
* 某一組開始出錯：記錄當組及之前的觀察，完整重啟遊戲後單獨複測。平台掃描、自然事件及模擬結果可能延遲，不能保證最後安裝的位置就是唯一原因。
* 未能安裝：可能是本地遊戲尚未就緒、平台已修改同位置、簽名不符或功能條件未成立。日誌會保存測前／安裝後位元組和目標模組，**不覆蓋平台現有補丁**。
* 30 秒正常只表示該觀察窗口未發現問題；未操作相關功能時，也沒有測到其完整事件路徑。還原程式位元組不能倒轉已發生的遊戲事件。

CRC 組僅測八個適配入口的安裝，不呼叫全圖 Reveal、不刻意改 Cell／Visionary；不能據此認證完整全圖功能。直接地圖顯示安排最後。測試器不自動下單、生產、移動或發送遊戲事件。

日誌會記錄模組名稱／路徑、非系統模組檔案 SHA-256、51 個站點的測前／安裝／判定／停止位元組、跳轉目標所屬模組、Hook 數、狀態及使用者判定。這些資訊可比較 RA2OL 與其他平台；它不是掃描器偵測器，也不規避平台檢查。

## 編譯與驗證

先用 Zig 0.13.0 完整編譯**同一份 checkout** 的 x64 工具箱（`source/build-zig-x64.sh`），再執行：

```powershell
python source/tools/build_hook_diagnostics.py --zig C:/toolchain/zig.exe --base-build artifacts/build --output artifacts/hook-test
python source/tools/verify_hook_diagnostics.py --root artifacts/hook-test
```

建置器重用同份基礎建置中未變的 x86 Runtime／Entry／SEH 物件及 broker，以 `RA2_HOOK_DIAGNOSTICS` 重編 Assist bridge。此巨集只為相機入口增加獨立測試開關，正常產品編譯不帶它；原有幾何／簽名／所有權限制不變。Assist83、Runtime4、Entry3 ABI 不變，獨立相機通道為 24 bytes、版本 1、PID＋owner＋兩秒心跳驗證。

Windows 下建置器會實際執行隱藏 UI 的無效 PID 拒絕測試，及 x64 → x86 broker → DLL 載入／協議握手測試，均不連接遊戲。`tests/sequence.cpp` 測試倒計時、必須回答、OOS／還原失敗不前進與清單覆蓋；`tests/camera_gate.cpp` 測試相機開關身分／時效。PE 檢查分別驗證架構、匯入、匯出、manifest 及協議。

**目前完成本機 Windows 編譯及上述檢查，沒有完成 RA2OL 雙機或實際遊戲 Hook 測試，正式工具箱已加入不完整陰影批次拒絕發布的修正；仍未做現場視覺驗證。**

本輪另在獨立 Win32 fixture 驗證高刷光標與原生提示相容修正、幀 adapter ABI 和聯機輪詢政策；這不是新版 RA2OL 雙機驗證。測試器沒有高刷光標介面，高刷懸停名稱／價格須用配套正常工具箱複測。
