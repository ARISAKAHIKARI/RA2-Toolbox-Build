RA2 Toolbox 0.7.20 Full — 架构与全部功能

本版遵循：不拦截或改写原版任务。原版任务照常执行，工具仅经唯一 GameRuntime 管理器读取状态、提交额外原版事件。停止使用所有功能级游戏代码 Hook。

地图全开标为实验性，新增“启用地图全开（实验性）”复选框，默认未勾选，设置即时生效并自动保存。勾选是许可，本身不发送揭图命令；按钮、快捷键、旧 AutoRevealNewMatch 自动请求和游戏侧最终执行均检查许可。取消勾选清除宿主待处理请求，游戏侧拒绝未获许可的请求；已揭示的地图不会回退。保存位置为 Assist.ini 的 [Experimental] RevealMap。

单位统计并不依赖 Tab 拦截；原有实现轮询 Tab，原版菜单可能同时响应。本版修复 Ctrl+Alt+H 在按住/短按长按模式下不能独立显示的问题，并增加“显示 / 隐藏覆盖层”按钮。“常驻显示（不依赖 Tab）”勾选后正常战场中直接显示，不必按 Tab，保留原 settings.ini tabEnabled 的兼容。菜单、失焦、无有效数据时继续隐藏，不用可读单位数据代替菜单验证。面板及 UnitMonitor.log 记录隐藏原因和菜单状态字段。未加入平台专用 Hook 或绕过保护；尚无 LBW 实机验证。

继承 0.7.18：独立鼠标绑定与即时逃生部署

高级移动、磁电轮换、按键 CS、高级进驻、飞机模式 1/2、飞碟主武器、直接攻击移动、变卖吸取目标、变卖战车共十项，各自选择停用/中键/侧键 1/侧键 2/右键，即时生效并自动保存。鼠标配置集中列在战术面板中；修改一项不互换或覆盖其他项。缺少新配置时继承旧 EnhancedButton/AttackMoveButton/SellButton；显式停用值 0 保留。未提供自定义优先级。

原有匹配规则保留：只考虑本鼠标键上已开启、组合键满足的增强项，再考虑直接攻击移动，最后变卖。地面功能非空且按住的键优先于空键；多个候选按原有磁电→高级移动→CS规则，每对象最多一个初始指令。对象目标沿用原有进驻、飞碟、飞机处理顺序。这里没有按目标失败后跨操作类别重新仲裁；如将不同类别绑定到同一组合，前一类可能遮住后一类，可设置不同按钮或组合键。飞机同按钮双空时用模式 1，不同按钮分别触发对应模式。

每个增强请求只携带本次按钮匹配的功能授权；进驻或飞碟按钮点地面不会顺带发移动或自动 CS，变卖战车与变卖吸取建筑分别校验授权。全局自动 CS 仍跟随普通右键并检查白名单。配置为右键的增强功能保留原版点击，至少下一帧追加；地面接续仍等待观察对应原版 Move。不新增 Hook，不增加私有入口，Assist 协议为 40，必须整包更新。

逃生仍只登记选中的己方载具。可部署幸存乘员独立查询原版 CanDeploy，允许就立即提交，不等待同格其他人的在途 Deploy，也不统一等待停稳两帧。当前不允许部署就保留原版散开，不发 Sleep；每个乘员独立保留在途状态，避免重复部署。散开观察窗口仍为 180 帧，取消、手动停止、正常下车及归属变化仍停止跟踪。成功入队不等于游戏中已完成部署。

继承 0.7.15 入局修复

加载/菜单/对话框、负帧号、观战及未验证会话不消费游戏命令。有效首帧 0 立即可用，无固定延时或必须先走帧的要求。输入按捕获时的对局绑定，不能在出队时改贴当前对局编号。统一事件入口在构造前和普通入队前复核现场上下文；SP 保持当前帧+1，MP 保持原版构造器帧号，发送计时仍取原版时钟。

与自动装车的启动差异

装车在明确请求时才分配乘员并构造 Enter；CS/磁电/飞机/飞碟/卖车仅开启开关时，不应自动发令，需有效输入或已登记任务。倒矿与维修是条件自动任务，可能在入局时发现实际工作。全开开关且无工作/输入的模型场景应为零事件；有受损建筑则允许维修事件，随后装车载荷与单独装车一致。原版代码、单位任务、类型和 House 数据在这些发送端用例中未发生写入。不是所有功能开关都需要安装 Hook。

执行与读取

三大宿主模块使用统一 ReadSession，连接登记有短锁，独立任务采样不持整批串行锁。宿主规划与输入邮箱交给唯一 GameRuntime.dll；管理器在游戏 GUI 线程发放执行租约，忙碌保持未确认请求。修复后的接口禁止 Patch 操作。游戏内只保留管理器的 Windows 消息入口，不创建功能自己的输入或帧入口。

事件由统一适配器调用原版 EventClass 构造器，再提交单机 DoList 或多人 OutList。可选原版高层发令后端仍经同一入口且检查真实入队结果，不在失败后盲目补发。接收端函数与游戏对象 mission/target/locomotor 不被工具写入。选兵、光标、侧栏闪烁等本地 UI 不冒充网络事件。

实际仍留在 Runtime 内的业务：自动装车候选分配、维修发现/节拍、卸载/逃生的部分选择。它们已使用同一事件入口且无私有 Hook；本版不宣称所有规划计算都已迁出 DLL。统一读取接口也不意味着跨功能共享一个完全原子的世界快照。

时效、取消与冲突

增强输入首次接收上限 150 ms / 8 帧；明确目标后，等待原版任务或处理剩余批次最多 1500 ms / 90 帧。原始输入时间不会续期。新的输入代次使旧的未提交部分失效。绑定选区对象指针+ID，核对对局、所属玩家、菜单/聊天、视口与相机，目标 ID 改变即拒绝。右键 Shift 规划保留原版，不接续。

每帧事件总预算仍为 24，增强输入在有其它规划/自动化任务时最多先使用 12。最多 512 源对象，接受前缀不会重放；过期或未接受的部分需要重新操作。外部协同计划继续使用原有来源时效与合法性检查。输入轮询和系统调度不是实时保证，极短按键可能漏采。没有新的引擎 Hook 来补救漏采。

停用与限制

科技全开的补图实验因原版自动取消生产而未发布，本版沿用停用状态，生产连续性尚未解决；随处建造保持停用；变卖敌方建筑不再提供。地图揭示恢复单机及多人；外部直接生产只限单机；直接生产检查正常 CanBuild。生产观测、类型目录、读数显示继续保留。Tab 显示不再吞游戏 Tab。没有 Windows 桌面与平台双人游戏实测，不能承诺已经消除全部断线。

67 项功能审查

F01 · 公共游戏发现与窗口定位

枚举兼容进程，先确定 PID，再读 YRpp 的 Game::hWnd 并核对窗口所属 PID 和线程。指定进程暂时没有窗口时保留只读连接，不能改绑另一场游戏。采用显式 read 字节读取，避免把 get 返回值误当输出参数。 光标模块也复用公共游戏名、窗口发现和 YRpp Game::hWnd 校验；保留同 PID 启动器子窗口路径。

路径：读取/外部展示/配置资源；无游戏函数拦截

源码：external_reader/source/process_discovery.h；message_query.h 位于 shared/source

F02 · 统一外部读取器

战术、单位统计和光标统一使用 ReadSession。同一 PID 和访问能力共享受引用计数保护的只读连接，缓存、失败诊断和批次计数归各任务独立所有；仅连接登记加短锁，读取和整批采样不持全局锁。统计/战术使用批次页面缓存，光标使用 readFresh 即时读取。只查询连接与可读连接隔离，关闭一个模块不关闭其它模块的连接。进程退出后重新连接生成新代次并清空该会话缓存。

路径：读取/外部展示/配置资源；无游戏函数拦截

源码：external_reader/source/process_connection.h; process_reader.h; shared_reader.h

F03 · 布局检查与分层就绪

布局探针检查关键对象与数组；readStatus、bridgeStatus、commandStatus、renderStatus 分别表示读取、桥接、命令和显示。能显示不代表能下单，命令桥异常也不应直接抹掉有效的只读显示。

路径：读取/外部展示/配置资源；无游戏函数拦截

源码：external_reader/source/layout_probe.h；assist/source/main.cpp 的 mergeExternal

F04 · 单一 GameRuntime 与游戏线程管理

EXE 通过统一 host_game_input 订阅消息入口；只有 GameRuntime.dll 进入游戏。游戏线程租约与忙碌拒绝保留，忙碌不伪造回执。

路径：统一管理器原版调用或事件入口；无功能级 Hook

源码：shared/source/host_game_input.h; shared/source/game_entry_manager.cpp

F05 · 禁止游戏代码补丁

管理器的 Patch 操作直接返回 PatchDenied；没有 VirtualProtect、跳板分配、原版函数入口或调用点改写。旧补丁登记地址仅作为历史资料。

路径：统一管理器原版调用或事件入口；无功能级 Hook

源码：shared/source/game_entry_manager.cpp; assist/source/input_patch.h

F06 · 统一消息与外部输入调度

每个游戏仅有管理器 WH_GETMESSAGE / WH_CALLWNDPROCRET 两个 Windows 消息订阅。宿主按 4 ms 目标轮询增强鼠标输入并保存捕获时对局、边沿、按下时修饰键与取消代次；上下文超过 150 ms 未续期则停采并清除，切局/菜单/失焦重新播种按键状态；战术控制目标间隔 16 ms。实际延迟取决于系统调度和游戏消息泵。

路径：统一管理器原版调用或事件入口；无功能级 Hook

源码：shared/source/host_game_input.h; assist/source/pointer_host.h

F07 · 统一请求、接续和事件提交

命令、选兵、外部规划、协同与增强输入使用同一 Shared 协议和同一游戏线程调度。观察到与点击目标格相符的原版 Move 状态后才追加 CS；不修改原版任务、事件字节或接收函数。请求没有独立 Hook。队列满保留未提交部分，已接收前缀不重发。

路径：统一管理器原版调用或事件入口；无功能级 Hook

源码：assist/source/pointer_intent.h; assist/source/pointer_bridge.h; assist/source/bridge.cpp

F08 · 对局身份与延迟恢复

请求携带对局代次、时间和对象版本；真正换局会取消旧请求。短暂窗口丢失、暂停或回调延迟不直接等同退出。主程序不伪造 ACK；线程迁移必须确认旧线程对象已结束。

路径：统一管理器原版调用或事件入口；无功能级 Hook

源码：assist/source/session_epoch.h；control_link.h；command_delivery.h；main.cpp

F09 · 回执与手动优先

计划、入队、观察、完成、取消和过期分别记录。每帧与跨帧仲裁避免多个自动任务争用同一单位；人工操作递增对象版本并接管任务。已入队只表示提交成功，不能冒充动作已完成。

路径：统一管理器原版调用或事件入口；无功能级 Hook

源码：assist/source/command_gateway.h；unit_task_arbiter.h；business_effects.h

F10 · 一键维修和自动维修

仅维修己方受损且未处于维修/待确认状态的建筑。默认检查 YRpp ClickRepairable (+0x157A)；勾选“允许维修不可维修的建筑”后可放宽此类型限制。收集与提交前均检查，关掉许可会跳过未提交的非标准建筑请求；已入原版队列的事件不撤回。不改原版类型数据或归属，仍通过统一 Repair 事件入口。

路径：统一管理器原版调用或事件入口；无功能级 Hook

源码：assist/source/bridge.cpp; assist/source/auto_settings_ui.h

F11 · 战斗单位筛选

从当前选区筛选符合战斗条件的己方单位，排除采矿或工程用途等不符合项。执行受管理器保护的本地选择 API，不向仿真队列发送攻击命令。

路径：统一管理器原版调用或事件入口；无功能级 Hook

源码：assist/source/bridge.cpp 的 selectFilter

F12 · 空载运输选择

查找己方有运输容量且当前空载的载具，进行本地选择。它与自动装车分开：选择空车不意味着乘员已经得到进车任务。

路径：统一管理器原版调用或事件入口；无功能级 Hook

源码：assist/source/bridge.cpp 的 selectFilter

F13 · 受损单位选择

从当前选区筛选生命值未满的己方单位，重新组成选区。它不自动修理单位，建筑维修仍走 Repair 指令。

路径：统一管理器原版调用或事件入口；无功能级 Hook

源码：assist/source/bridge.cpp 的 selectFilter

F14 · 空闲单位定位

矿车、工程师、运输载具分别按类别检查任务和目标状态，循环定位符合条件的己方对象并移动视野。没有合法对象时返回零，不用旧指针凑结果。

路径：统一管理器原版调用或事件入口；无功能级 Hook

源码：assist/source/bridge.cpp 的 findIdle；protocol.h 的 idleMission

F15 · 组合选兵与双按范围

多个兵种可配置同一个快捷键，注册时去重。单按合并选中屏幕内这些类型的己方单位，双按选全图；本局缺失类型跳过。宿主生成绑定本局的类型掩码，唯一 GameRuntime 在同一选兵请求里筛选全部对象，只清空一次再合并选区；无网络事件或新增 Hook。解绑某个兵种保留组内其他兵种。原有按普通武器选变体功能及其独立快捷键保留。普通功能快捷键仍拒绝冲突。

路径：统一管理器原版调用或事件入口；无功能级 Hook
