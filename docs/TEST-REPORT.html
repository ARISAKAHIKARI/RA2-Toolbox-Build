1.0.2 连点与全执行证据

80 项新增实际 x86 DLL 用例：两份 EXE 各40项，在四种会话验证首项原始捕获、超过首项接收窗口后续项仍共用原有总期限、目标不被指针下新对象替换、同帧额度保留并在后续帧只提交一次、后项普通CS成功后撤销前项持续规划、缺少锚点/身份变化/取消/过期/镜头变化/对象复用/非法标志拒绝，以及右键原始 Move 观察在组合中复用。未发布候选的负面对照在真实 NativeOrders 功能标志开启时复现前项持续规划残留，修复后同场景归零。旧版全部800项模型回归继续使用本次 DLL 重跑。

生产键盘分发函数在模型中逐项等待命令和选兵回执，组合选兵与变体双按互不清空，旧绑定消息、跨局和过期请求拒绝。生产鼠标宿主服务等待协同消费、回执与重试，保存原始时间和选区，配置/新输入/失焦取消剩余项。全执行关闭时保留原有规则。实际设置处理器验证开关即时生效、保存/加载、重复绑定和飞机同键两模式。

1.0.1 设置处理器负面对照复现已删除鼠标 Hook 句柄为空时把已勾选连点关闭并保存；当前处理器保持启用并可重新开启旧配置。真实 Burst 状态机验证四次补点、释放/拖动/取消、间隔及计时回绕；低显示帧率下的4ms输入截止时间使用计算模型验证，没有实测点击接受率。敌方标记绘制测试更新为纯名称，玩家颜色符号保留。

继承 1.0.1 的敌方位置标记证据

生产 TacticalSampler 与 Motion 在便携内存模型中验证：敌方四种对象、盟友/中立排除、未揭示区域不依赖揭图读取、同帧坐标更新、类型名称缓存、菜单/暂停后恢复、最新帧/玩家/镜头/显示状态复核、读取失败及重连、结盟/中立/归属变化、对象 ID 复用、死亡/离图/运输状态、视口与侧栏裁剪、2048 上限及损坏数组边界。内存哈希不变，没有读取迷雾格子。

1000 次、目标间隔 2 ms 的调度模型中，敌方标记与载员标签使用相同输入时插值坐标一致；每逻辑帧一次世界遍历，持续平移镜头未退化为每次显示采样都遍历世界。该用例验证时钟/缓存规则，不是实测 500 FPS。生产绘制函数在 GDI 记录模型中验证位置符号、玩家颜色/名称、文字裁剪和位图复用；UI 处理器验证开关即时生效和保存/重载。没有真实 Windows 像素、游戏联机或帧率证据。

继承 0.7.18 的证据

原 0.7.17 DLL 在五名同格、全部允许部署的第一帧没有提交任何 Deploy，新测试负面对照失败。当前 DLL 在首个可执行调度提交五条，各乘员独立去重；同格乘员分批允许部署时，当帧提交已允许者，不被其他在途请求阻塞；仍在 Move 但 CanDeploy 已允许时也立即提交。原版 CanDeploy、散开、部署结果由模型控制，不是实际寻路模拟。保留未选中、正常下车、取消、持续不可部署及超时边界；没有 Sleep 阻止散开。

十项独立鼠标按钮通过实际生产解析函数测试，逐项遍历停用/中键/两侧键/右键及各物理输入，检查授权隔离、功能关闭、组合键、右键延后标记和原有同类匹配规则。实际 UI 处理器验证每项即时生效、不改其他项、无效值拒绝；没有新增可配置优先级。每份 EXE 增加 24 项功能隔离场景：进驻/飞碟按钮点地面不误发移动或全局自动 CS，建筑和载具变卖只接受对应按钮授权。当前 Assist 协议为 42，EXE/DLL 必须配套。

逻辑、入口与 UI

60 项可移植本机逻辑测试、26 项源码/UI 检查、2 项模拟 Win32 读取测试全部通过。135 个生产源码文件审查：功能没有独立注入/输入 Hook、游戏代码补丁、私有事件入口；唯一管理器保留两项 Windows 消息订阅。Patch API 即使持有租约也拒绝补丁请求。四种会话中全开标志运行，游戏 .text 未发生写入。

实际 UI 创建代码在 Win32 模型中生成 199 个控件，单页战术布局覆盖 12 种视口、2292 次可达检查，无检测到的布局重叠。该结果不验证 Windows 实际绘制、文字残影或截图。两个 PE32 输出的版本、导出/协议、系统依赖和 EXE Common Controls v6 manifest 均通过静态验证。

继承 0.7.15 的入局证据

两份游戏 EXE 各 90 项：四种支持会话中按功能单开和全开，零输入/无自动工作时零发单、零原版代码与受保护对象/类型/House 写入；菜单、对话框、战术视图未激活、负帧、极值帧、观战、运行标志撤销及不支持模式会阻止装车发令。回到合法同局恢复一次，观战退出/换局使旧请求失效。有效帧 0 可以立即装车，SP 帧为 1、MP 保留 0，原版发送计时和同帧去重不变。真实受损建筑允许一次自动维修；全开时装车载荷与单独装车逐字节一致。

原版计时回调边界中模拟改变帧、玩家、会话或菜单，普通事件不会提交到变化后的上下文。宿主实际头文件的模拟 Win32 测试覆盖加载点击、捕获时对局、跨局清队列、按住右键跨菜单释放及上下文过期。正式 0.7.14 DLL 负面对照复现菜单中已发出 1 条装车事件，新版相同场景阻止。

这套证据未复现真实平台同步错误或网络掉线，不能将上述边界漏洞直接断言为所有断线根因。自动日志增加入局前三秒与就绪/功能切换的状态，供下一轮实机定位。

保留的边界修复

  • 切回窗口或重新连接时，不把此前已按住的右键释放当作新点击；只接续本次前台观察到的按下/释放。
  • 断开、换局清空增强批次状态；重新使用相同请求序号不会继承上一连接的目标或进度。
  • 批量接受前缀不重发，队列满只重试剩余项；原始截止时间不续期。
  • 有其它任务时增强批次保留当帧提交额度；同帧登记的高级任务及时反映到状态。
  • 原版 Sell 接收分支验证归属与格子建筑条件；未绕过原版限制。

退役检查与剩余限制

旧的帧 Hook、光标跳板、科技解锁等测试要求已经删除的实现。本版将其列入 RETIRED_TEST_CONTRACTS.json，使用无补丁边界和增强输入回归替代，未把旧结果冒充新版通过。参考库的资料保留为实现依据，不能当作当前版本测试证据。

右键接续依据是读取到与目标格相符的 Move 状态，未监听原版事件构造。反复点击相同目的地时，单凭状态无法区分旧移动与本次点击；平台输入延迟下，后到的原版命令仍可能覆盖追加命令。中键/侧键显式增强请求不依赖这项推断。此处的“已接收/已入队”始终不等于动作完成。

短于轮询间隔的点击可能漏采；目标查询的 thiscall ABI 已验证，但原版屏幕坐标查询在 DLL 模型中使用桩，需实际分辨率/DPI/全屏验证。模型未验证各 MOD 的完整原版接收行为。未发布的科技补图实验已撤出：原版移除图标前会发 Abandon/AbandonAll，生产连续性未解决。科技全开、随处建造、敌方变卖保持停用；地图揭示恢复多人，直接生产仍限单机。没有增加替代 Hook。

可复现

源码目录使用 Zig 0.13.0 构建 Windows x86 程序；本机逻辑测试需要 Python 3 与 g++，DLL 回归需要 Python 的 unicorn、pefile。游戏 EXE 由使用者提供，本包不附带。

python validate-logic.py
python tools/verify_windows_outputs.py
python tools/audit_architecture.py
python tools/run_current_regressions.py <用户游戏EXE> <参考游戏EXE>

实际截图工具为包根目录 Test-Screen-Capture.cmd，只观测和截图，ACK 解析与当前 Assist 协议 41 对齐；在本环境未运行成功的 Windows 实测不计入通过项。当前详细日志位于 verification。
