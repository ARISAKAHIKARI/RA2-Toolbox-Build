# Shift 五连点与热键冲突 · 1.0.2

## Shift 五连点

光标设置中勾选“Shift 五连点”，运行光标模块后，按住 Shift 点击生产侧栏。原版处理第一次点击，工具在释放后通过统一宿主输入接口补四次点击。

旧设置处理器仍要求已经删除的 `clickHook` 非空，修改任何相关设置都会把连点关闭并写入 INI。1.0.2 去掉了这个条件，开关直接控制连点，不恢复低级鼠标 Hook。回归负面对照确认 1.0.1 处理器在该句柄不存在时会关闭已勾选的功能；修复后保持勾选、立即生效并保存。

如果旧配置已经被误写为关闭，需要重新勾选一次。旧 INI 的明确关闭值继续保留，因为无法区分主动关闭与故障写入。

低绘制帧率下，物理按键观察仍按最多 4 ms 的目标间隔运行，复用原有等待计时器；500 Hz 显示仍按 2 ms 目标间隔绘制。该数值是调度目标，不是 Windows 实测延迟，短于实际轮询间隔的点击仍可能漏采。

| 模式 | 行为 |
|---|---|
| 自动补点 | 未检测到 Ares 时补四次；检测到 Ares 时使用其原生功能；检测失败时跳过额外点击 |
| 强制补点 | 通过前台、侧栏、Shift 和释放条件后补四次 |
| 关闭补点 | 不补点 |

鼠标必须位于推定生产侧栏，保持 Shift，不同时按 Ctrl/Alt。拖动超过 4 像素、失去前台、新按其他鼠标键或发送失败会取消剩余点击。补点间隔仍可配置；发送不等于游戏一定接受。日志继续记录跳过原因及发送结果。

## 热键冲突时全部执行

战术面板的增强鼠标设置下方新增同名开关，默认关闭，即时生效并自动保存到 `Assist.ini`：

```ini
[Hotkeys]
ExecuteAllMatches=1
```

| 输入 | 开启后的行为 |
|---|---|
| 战术功能键盘快捷键 | 同一组合只注册一次 Windows 热键，将全部匹配功能放入宿主队列；依次等待现有命令或选兵回执，再执行后项 |
| 同一快捷键的多个单位类型 | 继续合并成一次组合选兵；可同时与其他功能共用该组合 |
| 按武器选变体与组合选兵 | 两种双按状态分别维护，各请求等待自己的选兵回执 |
| 增强鼠标组合 | 按各功能的按钮、按住键和启用状态收集全部匹配项，包括高级移动、磁电、CS、进驻、飞机两模式、飞碟、直接攻击移动和两类合法变卖 |

增强鼠标的十项请求绑定同一次捕获的选区、目标、时间、对局和取消代次。首项在原有 150 ms 接收窗口内提交；后项沿用该组合的原始时间，共用原有 1500 ms / 90 帧处理期限，不续期。前一协同请求必须先被外部规划器消费，并完成回执和剩余重试，下一项才复用邮箱。

后项复用已经验证的原始目标，避免单位移动到指针下方后被重新选为目标；仍检查视口、对象身份、归属和存活。原版右键移动只需在该组合内观察一次；后项不会因前项已改变任务而错误等待同一条原始 Move。新的物理输入、菜单、失焦、跨局、配置变化或超时取消未提交的鼠标项。

键盘队列最多 128 项，待发项 2500 ms 后失效；配置修改会重新注册并清除旧队列。其他程序占用的系统热键仍可能注册失败，面板会报告。光标及统计模块的固定窗口控制快捷键不属于这组可配置战术热键。

所有请求仍通过现有命令、选兵、协同或指针接口进入唯一 GameRuntime。没有新增游戏 Hook、代码补丁或私有注入通道，原有每帧事件额度与同单位同帧限制继续生效。续项只释放同一组合自己持有的回执租约，不夺取其他任务的租约。

同一单位的后续命令可能覆盖前面的任务；持续规划每单位保留最后一项。这个开关允许全部匹配项依次尝试提交，不能让互斥任务同时持续，也不放宽目标合法性或过期条件。关闭后恢复原有单项匹配规则，已保存的重复绑定不会被改写。

Assist 协议升级为 **42**，必须配套更新 EXE 和 GameRuntime.dll。

## 验证边界

生产设置处理器、键盘分发器、增强鼠标宿主服务、路由器、连点状态机和轮询截止时间使用便携 Win32/读取模型验证。实际 x86 DLL 用例覆盖四种支持会话中的续项身份、原始目标、同帧等待、旧 Move 观察复用、手动取消、过期、镜头变化、对象复用和非法标志；检查原版事件入队及游戏代码未被写入。

这些模型没有运行真实 Windows 游戏、平台联机或屏幕捕获；不代表实际点击接受率、帧率、延迟或平台稳定性已经验收。
